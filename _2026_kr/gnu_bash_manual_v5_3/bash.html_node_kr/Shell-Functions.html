3.3 쉘 함수 ¶

쉘 함수는 나중에 실행하기 위해 명령어들을 하나의 이름으로 그룹화하는 방법입니다. 이들은 "일반적인" 단순 명령어와 똑같이 실행됩니다. 쉘 함수의 이름이 단순 명령어 이름으로 사용되면, 쉘은 해당 함수 이름과 연관된 명령어 목록을 실행합니다. 쉘 함수는 현재 쉘 컨텍스트에서 실행됩니다. 이를 해석하기 위해 새로운 프로세스가 생성되지 않습니다.

함수는 다음 문법을 사용하여 선언됩니다: 

fname () compound-command [ redirections ]

또는 

function fname [()] compound-command [ redirections ]

이는 fname이라는 이름의 쉘 함수를 정의합니다. 예약어 function은 선택 사항입니다. 만약 function 예약어가 제공되면 소괄호는 생략할 수 있습니다. 함수의 본체(body)는 복합 명령어 compound-command(복합 명령어 참조)입니다. 해당 명령어는 보통 {와 } 사이의 list(목록)이지만, 위에 나열된 그 어떤 복합 명령어도 될 수 있습니다. 만약 function 예약어를 사용했지만 소괄호를 제공하지 않는 경우에는 중괄호 사용을 권장합니다. 쉘이 POSIX 모드(Bash와 POSIX 참조)일 때, fname은 유효한 쉘 이름이어야 하며 특수 빌트인 명령어(특수 빌트인 참조) 중 하나와 이름이 같아서는 안 됩니다. POSIX 모드가 아닐 때 함수 이름은 ‘$’를 포함하지 않는 인용되지 않은 그 어떤 쉘 단어도 가능합니다.

쉘 함수와 연관된 리다이렉션(리다이렉션 참조)은 함수가 실행될 때 수행됩니다. 함수 정의는 unset 빌트인 명령어의 -f 옵션을 사용하여 삭제합니다(Bourne 쉘 빌트인 참조).

함수 정의의 종료 상태는 문법 오류가 발생하거나 같은 이름의 읽기 전용 함수가 이미 존재하지 않는 한 0입니다. 실행 시 함수의 종료 상태는 본체에서 마지막으로 실행된 명령어의 종료 상태입니다.

역사적인 이유로 인해, 가장 일반적인 사용법에서 함수의 본체를 감싸는 중괄호는 본체와 blank(공백) 또는 줄바꿈으로 구분되어야 합니다. 이는 중괄호가 예약어이며, 명령어 목록과 공백이나 다른 쉘 메타 문자로 구분될 때만 예약어로 인식되기 때문입니다. 중괄호를 사용할 때 list는 세미콜론, ‘&’, 또는 줄바꿈으로 종료되어야 합니다.

fname이 단순 명령어의 이름으로 지정될 때마다 compound-command가 실행됩니다. 함수는 호출한 쉘의 컨텍스트에서 실행됩니다. 이를 해석하기 위해 새로운 프로세스가 생성되지 않습니다 (이는 쉘 스크립트의 실행과 대조되는 부분입니다).

함수가 실행될 때, 함수에 전달된 인자들은 실행되는 동안 위치 파라미터(positional parameters)가 됩니다(위치 파라미터 참조). 위치 파라미터의 개수로 확장되는 특수 파라미터 ‘#’은 새로운 위치 파라미터 세트를 반영하여 업데이트됩니다. 특수 파라미터 0은 변경되지 않습니다. 함수가 실행되는 동안 FUNCNAME 변수의 첫 번째 요소는 함수의 이름으로 설정됩니다.

다음 예외 사항들을 제외하고, 쉘 실행 환경의 모든 다른 측면은 함수와 그 호출자 사이에서 동일합니다: declare 빌트인을 사용하여 함수에 trace 속성을 부여하거나 set 빌트인으로 -o functrace 옵션을 활성화하지 않는 한(이 경우 모든 함수가 DEBUG 및 RETURN 트랩을 상속함) DEBUG 및 RETURN 트랩은 상속되지 않습니다. 또한 -o errtrace 쉘 옵션이 활성화되지 않는 한 ERR 트랩은 상속되지 않습니다. trap 빌트인 명령어에 대한 설명은 Bourne 쉘 빌트인을 참조하십시오.

FUNCNEST 변수가 0보다 큰 숫자로 설정되면 함수의 최대 중첩 레벨을 정의합니다. 이 제한을 초과하는 함수 호출은 전체 명령어의 중단을 초래합니다.

함수 내에서 return 빌트인 명령어가 실행되면 함수가 완료되고 함수 호출 뒤의 다음 명령어부터 실행이 재개됩니다. RETURN 트랩과 연관된 모든 명령어가 실행 재개 전에 실행됩니다. 함수가 완료되면 위치 파라미터들과 특수 파라미터 ‘#’의 값은 함수 실행 전의 값으로 복구됩니다. 만약 return에 숫자 인자가 제공되면 그것이 함수의 반환 상태가 되며, 그렇지 않으면 함수의 반환 상태는 return 전 마지막으로 실행된 명령어의 종료 상태가 됩니다.

함수 내부의 지역 변수는 local 빌트인을 사용하여 선언합니다(지역 변수). 일반적으로 변수와 그 값은 함수와 그 호출자 사이에서 공유됩니다. 지역 변수는 오직 해당 함수와 그 함수가 호출하는 명령어들에만 보입니다. 이는 특히 쉘 함수가 다른 함수를 호출할 때 중요합니다.

다음 설명에서 현재 스코프(current scope)는 현재 실행 중인 함수를 의미합니다. 이전 스코프들은 해당 함수의 호출자 등으로 구성되며, 쉘이 그 어떤 쉘 함수도 실행하고 있지 않은 "전역" 스코프까지 거슬러 올라갑니다. 현재 로컬 스코프에서의 지역 변수는 현재 실행 중인 함수 내에서 local 또는 declare 빌트인을 사용하여 선언된 변수입니다.

지역 변수는 이전 스코프에서 선언된 동일한 이름의 변수를 "가립니다(shadow)". 예를 들어, 함수 내에서 선언된 지역 변수는 전역 변수를 포함하여 이전 스코프에서 선언된 동일한 이름의 변수를 숨깁니다. 참조 및 할당은 지역 변수를 가리키며 이전 스코프의 변수는 수정되지 않은 상태로 남습니다. 함수가 반환되면 전역 변수가 다시 보이게 됩니다.

쉘은 함수 내에서 변수의 가시성을 제어하기 위해 동적 스코핑(dynamic scoping)을 사용합니다. 동적 스코핑 환경에서는 보이는 변수와 그 값은 현재 함수에 도달하기까지의 함수 호출 시퀀스의 결과입니다. 함수가 보게 되는 변수의 값은 그 호출자(그것이 전역 스코프이든 다른 쉘 함수이든) 내에서의 해당 변수 값에 달려 있습니다. 이 값은 또한 지역 변수 선언 시 가려지는 값이며, 함수가 반환될 때 복구되는 값입니다.

예를 들어, 변수 var가 func1 함수에서 지역 변수로 선언되고 func1이 다른 함수 func2를 호출하면, func2 내부에서 행해진 var에 대한 참조는 func1의 지역 변수 var로 해석되며, var라는 이름의 모든 전역 변수를 가립니다.

다음 스크립트는 이러한 동작을 보여줍니다. 실행 시 스크립트는 다음을 표시합니다: 

In func2, var = func1 local

func1()
{
    local var='func1 local'
    func2
}

func2()
{
    echo "In func2, var = $var"
}

var=global
func1

unset 빌트인 또한 동일한 동적 스코프를 사용하여 작동합니다: 변수가 현재 스코프에서 지역 변수라면 unset은 그것을 해제합니다. 그렇지 않으면 위에 설명된 대로 그 어떤 호출 스코프에서 발견된 변수를 해제하게 됩니다. 현재 로컬 스코프의 변수가 해제되면, 해당 스코프에서 다시 설정되거나 함수가 반환될 때까지 해제된 상태(unset으로 나타남)로 남습니다. 함수가 반환되면 이전 스코프의 그 어떤 변수 인스턴스가 다시 보이게 됩니다. 만약 unset이 이전 스코프의 변수에 작용한다면 가려졌던 해당 이름의 모든 변수 인스턴스가 보이게 됩니다 (아래 localvar_unset 쉘 옵션이 이 동작을 어떻게 바꾸는지 참조하십시오).

declare (typeset) 빌트인 명령어(Bash 빌트인 명령어 참조)의 -f 옵션은 함수의 이름과 정의를 나열합니다. declare 또는 typeset의 -F 옵션은 함수 이름만 나열합니다 (또한 extdebug 쉘 옵션이 활성화된 경우 소스 파일과 라인 번호를 옵션으로 포함할 수 있습니다). 함수는 export 빌트인의 -f 옵션(Bourne 쉘 빌트인 참조)을 사용하여 내보낼(export) 수 있으며, 이를 통해 자식 쉘 프로세스(별도의 쉘 호출 시 생성되는 프로세스들)가 자동으로 해당 함수를 정의된 상태로 가질 수 있게 됩니다. unset 빌트인의 -f 옵션(Bourne 쉘 빌트인 참조)은 함수 정의를 삭제합니다.

함수는 재귀적일 수 있습니다. FUNCNEST 변수는 함수 호출 스택의 깊이를 제한하고 함수 호출 횟수를 제한하는 데 사용될 수 있습니다. 기본적으로 Bash는 재귀 호출 횟수에 제한을 두지 않습니다.
