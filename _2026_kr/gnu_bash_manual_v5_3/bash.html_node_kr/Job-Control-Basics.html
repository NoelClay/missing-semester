7.1 작업 제어 기초 ¶

작업 제어(Job control)는 프로세스의 실행을 선택적으로 중단(suspend)하고 나중에 다시 재개(resume)할 수 있는 기능을 의미합니다. 사용자는 일반적으로 운영체제 커널의 터미널 드라이버와 Bash가 공동으로 제공하는 대화형 인터페이스를 통해 이 기능을 사용합니다.

쉘은 각 파이프라인에 작업(job)을 할당합니다. 쉘은 현재 실행 중인 작업들의 테이블을 유지하며, jobs 명령어로 이를 확인할 수 있습니다. 각 작업은 대괄호 사이에 표시되는 작업 번호(job number)를 가집니다. 작업 번호는 1부터 시작합니다. Bash가 작업을 비동기적으로 시작하면 다음과 같은 한 줄을 출력합니다: 

[1] 25647

이는 이 작업의 작업 번호가 1번이며, 이 작업과 연관된 파이프라인의 마지막 프로세스의 프로세스 ID가 25647임을 나타냅니다. 단일 파이프라인 내의 모든 프로세스는 동일한 작업의 멤버입니다. Bash는 작업 제어의 기초로 작업 추상화(abstraction)를 사용합니다.

작업 제어 사용자 인터페이스의 구현을 용이하게 하기 위해, 각 프로세스는 프로세스 그룹 ID를 가지며, 운영체제는 현재 터미널의 프로세스 그룹 ID 개념을 유지합니다. 이 터미널 프로세스 그룹 ID는 제어 터미널(controlling terminal)과 연관됩니다.

동일한 프로세스 그룹 ID를 가진 프로세스들은 동일한 프로세스 그룹의 일부라고 합니다. 포그라운드(foreground) 프로세스 그룹의 멤버들(프로세스 그룹 ID가 현재 터미널 프로세스 그룹 ID와 동일한 프로세스들)은 SIGINT와 같이 키보드에서 생성된 시그널을 수신합니다. 포그라운드 프로세스 그룹에 속한 프로세스들을 포그라운드 프로세스라고 부릅니다. 백그라운드(background) 프로세스는 프로세스 그룹 ID가 제어 터미널의 ID와 다른 프로세스들을 말하며, 이러한 프로세스들은 키보드 생성 시그널의 영향을 받지 않습니다. 오직 포그라운드 프로세스만이 제어 터미널로부터 데이터를 읽거나, 사용자가 stty tostop 명령으로 지정한 경우 제어 터미널에 데이터를 쓸 수 있습니다. 시스템은 터미널로부터 데이터를 읽으려 하거나(tostop이 활성화된 상태에서 쓰려 하는) 백그라운드 프로세스에 SIGTTIN (SIGTTOU) 시그널을 보내며, 이 시그널을 포착하여 처리하지 않으면 프로세스가 중단됩니다.

Bash가 실행 중인 운영체제가 작업 제어를 지원한다면, Bash는 이를 사용하기 위한 기능들을 포함합니다. 프로세스가 실행 중일 때 중단(suspend) 문자(보통 ‘^Z’, Control-Z)를 입력하면 해당 프로세스가 중단되고 제어권이 Bash로 돌아옵니다. 지연된 중단(delayed suspend) 문자(보통 ‘^Y’, Control-Y)를 입력하면 프로세스가 터미널로부터 입력을 읽으려고 시도할 때 중단되고 제어권이 Bash로 돌아옵니다. 사용자는 이후 bg 명령어로 백그라운드에서 실행을 재개하거나, fg 명령어로 포그라운드에서 실행을 재개하거나, kill 명령어로 작업을 종료하는 등 해당 작업의 상태를 조작할 수 있습니다. 중단 문자는 즉시 효력을 발휘하며, 대기 중인 모든 출력과 미리 입력된 내용(typeahead)을 버리는 부작용이 있습니다. 백그라운드 프로세스를 강제로 중단시키거나 터미널 세션과 연관되지 않은 프로세스를 중단시키고 싶다면 kill 명령어를 사용하여 SIGSTOP 시그널을 보내십시오.

쉘에서 작업을 참조하는 데는 여러 가지 방법이 있습니다. ‘%’ 문자는 작업 사양(job specification, jobspec)을 시작합니다.

작업 번호 n은 ‘%n’으로 참조할 수 있습니다. 작업은 또한 작업을 시작하는 데 사용된 이름의 접두사나 명령줄에 나타나는 부분 문자열을 사용하여 참조할 수도 있습니다. 예를 들어, ‘%ce’는 명령어 이름이 ‘ce’로 시작하는 작업을 참조합니다. 반면 ‘%?ce’는 명령줄 어디에든 ‘ce’ 문자열이 포함된 모든 작업을 참조합니다. 접두사나 부분 문자열이 둘 이상의 작업과 일치하면 Bash는 에러를 보고합니다.

‘%%’와 ‘%+’ 기호는 쉘의 현재 작업(current job) 개념을 참조합니다. 단독으로 쓰인 ‘%’(뒤에 작업 사양이 없는 경우) 또한 현재 작업을 참조합니다. ‘%-’는 이전 작업(previous job)을 참조합니다. 작업이 백그라운드에서 시작되거나, 포그라운드에서 중단되거나, 백그라운드에서 재개될 때 해당 작업은 현재 작업이 됩니다. 원래 현재 작업이었던 작업은 이전 작업이 됩니다. 현재 작업이 종료되면 이전 작업이 현재 작업이 됩니다. 오직 하나의 작업만 있는 경우 ‘%+’와 ‘%-’ 모두 그 작업을 가리키는 데 사용될 수 있습니다. 작업과 관련된 출력(예: jobs 명령어의 출력)에서 현재 작업은 항상 ‘+’로 표시되고, 이전 작업은 ‘-’로 표시됩니다.

작업의 이름을 단순히 입력하는 것만으로도 포그라운드로 가져올 수 있습니다: ‘%1’은 ‘fg %1’의 동의어이며, 1번 작업을 백그라운드에서 포그라운드로 가져옵니다. 유사하게 ‘%1 &’은 1번 작업을 백그라운드에서 재개하며, 이는 ‘bg %1’과 동일합니다.

쉘은 작업의 상태가 변경될 때마다 즉시 알게 됩니다. 보통 Bash는 다른 출력을 방해하지 않기 위해 프롬프트를 출력하기 직전까지 기다렸다가 작업 상태 변경 사항을 사용자에게 알립니다. 하지만 목록 내의 포그라운드 명령어가 완료된 후 다음 명령어를 실행하기 전에는 작업 상태 변경 알림을 수행합니다. set 빌트인의 -b 옵션이 활성화되어 있다면, Bash는 상태 변경을 즉시 보고합니다(Set 빌트인 참조). Bash는 종료되는 각 자식 프로세스에 대해 SIGCHLD 트랩을 실행합니다.

작업이 종료되고 Bash가 이에 대해 사용자에게 알리면, Bash는 작업 테이블에서 해당 작업을 제거합니다. 해당 작업은 더 이상 jobs 출력에 나타나지 않지만, wait 명령어에 해당 작업의 프로세스 ID를 인자로 주면 종료 상태를 보고합니다. 테이블이 비어 있게 되면 작업 번호는 다시 1부터 시작합니다.

사용자가 작업이 중단된 상태(또는 checkjobs 옵션이 활성화된 경우 실행 중인 상태 - Shopt 빌트인 참조)에서 Bash를 종료하려고 시도하면, 쉘은 경고 메시지를 출력하고 checkjobs 옵션이 켜져 있다면 작업 목록과 그 상태를 나열합니다. 사용자는 jobs 명령어를 사용하여 상태를 더 자세히 확인할 수 있습니다. 사용자가 중간에 다른 명령어 없이 즉시 다시 종료를 시도하면, Bash는 다시 경고하지 않고 중단된 모든 작업들을 종료시킵니다.

wait 빌트인을 사용하여 작업이나 프로세스를 기다리고 있고 작업 제어가 활성화되어 있다면, wait은 작업의 상태가 변경될 때 반환됩니다. -f 옵션을 사용하면 wait이 작업이나 프로세스가 완전히 종료될 때까지 기다린 후 반환하도록 합니다.
