8.3.2 조건부 초기화 구문 ¶

Readline은 C 전처리기(preprocessor)의 조건부 컴파일 기능과 유사한 기능을 구현하여, 테스트 결과에 따라 키 바인딩 및 변수 설정을 수행할 수 있게 해줍니다. 네 가지 파서 지시어(parser directives)를 사용할 수 있습니다.

$if

$if 구조는 편집 모드, 사용 중인 터미널, 또는 Readline을 사용하는 애플리케이션에 따라 바인딩을 수행할 수 있게 해줍니다. 비교 연산자 뒤의 테스트 텍스트는 줄의 끝까지 이어집니다; 별도로 언급하지 않는 한 이를 분리하기 위한 특별한 문자는 필요하지 않습니다.

mode

$if 지시어의 mode= 형식은 Readline이 emacs 모드인지 vi 모드인지 테스트하는 데 사용됩니다. 이는 예를 들어 ‘set keymap’ 명령어와 함께 사용되어, Readline이 emacs 모드로 시작될 때만 emacs-standard 및 emacs-ctlx 키맵에 바인딩을 설정하도록 할 수 있습니다.

term

term= 형식은 터미널 전용 키 바인딩을 포함시키는 데 사용될 수 있습니다. 예를 들어 터미널의 기능 키(function keys)가 출력하는 키 시퀀스를 바인딩할 때 유용합니다. ‘=’ 오른쪽에 오는 단어는 터미널의 전체 이름뿐만 아니라 첫 번째 ‘-’ 이전의 터미널 이름 부분과도 대조됩니다. 이를 통해 예를 들어 xterm은 xterm과 xterm-256color 모두에 매치될 수 있습니다.

version

version 테스트는 특정 Readline 버전에 대해 비교를 수행하는 데 사용될 수 있습니다. version은 현재 Readline 버전으로 확장됩니다. 비교 연산자 세트에는 ‘=’ (및 ‘==’), ‘!=’, ‘<=’, ‘>=’, ‘<’, 그리고 ‘>’가 포함됩니다. 연산자 오른쪽에 제공되는 버전 번호는 메이저 버전 번호, 선택적인 소수점, 그리고 선택적인 마이너 버전으로 구성됩니다(예: ‘7.1’). 마이너 버전이 생략되면 ‘0’으로 간주됩니다. 연산자는 version 문자열 및 버전 번호 인자와 공백으로 구분될 수 있습니다. 다음 예시는 사용 중인 Readline 버전이 7.0 이상인 경우 변수를 설정합니다: 

$if version >= 7.0
set show-mode-in-prompt on
$endif
application

application 구조는 애플리케이션 전용 설정을 포함하는 데 사용됩니다. Readline 라이브러리를 사용하는 각 프로그램은 애플리케이션 이름(application name)을 설정하며, 특정 값을 테스트할 수 있습니다. 이는 특정 프로그램에 유용한 함수들에 키 시퀀스를 바인딩하는 데 사용될 수 있습니다. 예를 들어, 다음 명령어는 Bash에서 현재 또는 이전 단어를 따옴표로 감싸는 키 시퀀스를 추가합니다: 

$if Bash
# 현재 또는 이전 단어를 따옴표로 감쌈
"\C-xq": "\eb\"\ef\""
$endif
variable

variable 구조는 Readline 변수와 값에 대한 간단한 동등성 테스트를 제공합니다. 허용되는 비교 연산자는 ‘=’, ‘==’, 그리고 ‘!=’입니다. 변수 이름은 비교 연산자와 공백으로 구분되어야 하며, 연산자 또한 오른쪽의 값과 공백으로 구분될 수 있습니다. 문자열 및 불리언 변수를 테스트할 수 있습니다. 불리언 변수는 on 및 off 값과 대조하여 테스트해야 합니다. 다음 예시는 위에서 설명한 mode=emacs 테스트와 동일합니다: 

$if editing-mode == emacs
set show-mode-in-prompt on
$endif
$else

$if 지시어의 이 분기에 있는 명령어들은 테스트가 실패했을 때 실행됩니다.

$endif

이 명령어는 이전 예시들에서 보았듯이 $if 명령어를 종료합니다.

$include

이 지시어는 단일 파일 이름을 인자로 받아 해당 파일로부터 명령어와 키 바인딩을 읽어들입니다. 예를 들어, 다음 지시어는 /etc/inputrc로부터 설정을 읽어옵니다: 

$include /etc/inputrc
