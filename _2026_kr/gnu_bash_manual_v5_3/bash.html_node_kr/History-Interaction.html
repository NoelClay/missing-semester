9.3 히스토리 확장 ¶

쉘은 csh에서 제공하는 것과 유사한 히스토리 확장(history expansion) 기능을 제공합니다(상황에 따라 히스토리 치환(history substitution)이라고도 부릅니다). 이 섹션에서는 히스토리 정보를 조작하는 데 사용되는 문법을 설명합니다.

히스토리 확장은 대화형 쉘에서 기본적으로 활성화되어 있으며, set 빌트인 명령어의 +H 옵션을 사용하여 비활성화할 수 있습니다(Set 빌트인 참조). 비대화형 쉘은 기본적으로 히스토리 확장을 수행하지 않지만, set -H로 활성화할 수 있습니다.

히스토리 확장은 히스토리 목록의 단어들을 입력 스트림으로 가져와서, 명령어를 반복하거나 이전 명령어의 인자를 현재 입력 줄에 삽입하거나 이전 명령어의 에러를 빠르게 수정하는 것을 쉽게 만들어줍니다.

히스토리 확장은 전체 줄이 읽혀진 직후, 쉘이 이를 단어들로 분리하기 전에 수행되며, 각 줄에 대해 개별적으로 이루어집니다. Bash는 이전 줄로부터 유효한 인용(quoting) 상태를 히스토리 확장 함수에 알리려고 시도합니다.

히스토리 확장은 두 부분으로 나뉘어 일어납니다. 첫 번째는 치환 중에 히스토리 목록의 어떤 항목을 사용할지 결정하는 것입니다. 두 번째는 해당 항목의 일부를 선택하여 현재 줄에 포함시키는 것입니다.

히스토리에서 선택된 항목을 이벤트(event)라고 부르고, 해당 항목에서 조작 대상이 되는 부분들을 단어(words)라고 부릅니다. 선택된 단어들을 조작하기 위해 다양한 수정자(modifiers)를 사용할 수 있습니다. 항목은 Bash가 입력을 읽을 때와 동일한 방식으로 단어들로 분리되므로, 따옴표로 감싸진 여러 단어는 하나의 단어로 간주됩니다. 이벤트 지시자(event designator)는 이벤트를 선택하고, 선택적인 단어 지시자(word designator)는 이벤트에서 단어들을 선택하며, 다양한 선택적인 수정자들을 사용하여 선택된 단어들을 조작할 수 있습니다.

히스토리 확장은 히스토리 확장 문자(기본값은 ‘!’)가 나타날 때 시작됩니다. 히스토리 확장은 입력의 어느 곳에나 나타날 수 있지만, 중첩(nest)되지는 않습니다.

히스토리 확장은 쉘과 유사한 인용 규칙을 구현합니다: 백슬래시(‘\’)는 다음 문자의 특수한 처리를 제거하는 데 사용될 수 있고, 작은따옴표는 문자 시퀀스를 문자 그대로 감싸 히스토리 확장을 억제하는 데 사용될 수 있습니다. 큰따옴표로 감싸진 문자들은 히스토리 확장의 대상이 될 수 있는데, 백슬래시가 히스토리 확장 문자를 이스케이프할 수 있기 때문입니다. 반면 작은따옴표는 큰따옴표 내에서 특별하게 취급되지 않으므로 확장을 막지 못합니다.

쉘을 사용할 때 오직 ‘\’와 ‘'’만이 히스토리 확장 문자를 이스케이프하는 데 사용될 수 있습니다. 하지만 히스토리 확장 문자가 큰따옴표로 감싸진 문자열 내에서 닫는 큰따옴표 바로 앞에 오는 경우에도 인용된 것으로 취급됩니다.

히스토리 확장 문자 바로 뒤에 공백, 탭, 줄바꿈, 캐리지 리턴, ‘=’, 그리고 다른 쉘 메타 문자들이 오는 경우, 인용 처리되지 않았더라도 히스토리 확장이 일어나지 않습니다.

줄의 첫 번째 문자가 빠른 치환(quick substitution) 문자(histchars에서 설명됨)인 경우에 활성화되는 특별한 치환 약어 형식이 있습니다. 이는 !!와 동일한 이벤트 지시자를 사용하여 이전 히스토리 항목을 선택하고, 해당 항목에서 특정 문자열을 다른 것으로 치환합니다. 이는 아래에서 설명됩니다(이벤트 지시자 참조). 이것이 히스토리 확장 문자로 시작하지 않는 유일한 히스토리 확장입니다.

shopt 빌트인으로 설정 가능한 여러 쉘 옵션들이 히스토리 확장 동작을 수정합니다(Shopt 빌트인 참조). histverify 쉘 옵션이 활성화되어 있고 Readline이 사용 중인 경우, 히스토리 치환 결과가 즉시 쉘 파서로 전달되지 않습니다. 대신 확장된 줄이 추가적인 수정을 위해 Readline 편집 버퍼로 다시 로드됩니다. Readline이 사용 중이고 histreedit 쉘 옵션이 활성화되어 있는 경우, 실패한 히스토리 확장이 수정을 위해 Readline 편집 버퍼로 다시 로드됩니다.

history 빌트인 명령어의 -p 옵션은 히스토리 확장을 실제로 사용하기 전에 그 결과를 미리 보여줍니다. history 빌트인의 -s 옵션은 명령어를 실제로 실행하지 않고 히스토리 목록 끝에 추가하여, 나중에 다시 불러올 수 있게 하는 데 사용될 수 있습니다. 이는 Readline과 함께 사용할 때 특히 유용합니다.

쉘은 위에서 설명한 대로 histchars 변수를 통해 히스토리 확장 메커니즘에서 사용되는 다양한 문자들을 제어할 수 있게 해줍니다(Bash 변수 참조). 쉘은 히스토리 파일을 기록할 때 히스토리 타임스탬프를 표시하기 위해 히스토리 주석 문자를 사용합니다.
