10.1 기본 설치 ¶

다음은 Bash를 설치하기 위한 지침입니다.

Bash를 컴파일하는 가장 간단한 방법은 다음과 같습니다:

  1. 소스 코드가 포함된 디렉토리로 cd 명령어를 사용하여 이동한 뒤, ‘./configure’를 입력하여 시스템에 맞게 Bash를 구성(configure)합니다. 오래된 버전의 System V에서 csh를 사용 중이라면, csh가 configure를 직접 실행하려 시도하는 것을 방지하기 위해 대신 ‘sh ./configure’라고 입력해야 할 수도 있습니다.

    configure를 실행하는 데는 시간이 어느 정도 걸립니다. 실행되는 동안 어떤 기능들을 확인하고 있는지 알려주는 메시지들을 출력합니다.

  2. ‘make’를 입력하여 Bash를 컴파일하고 bashbug 버그 보고 스크립트를 빌드합니다.
  3. 선택 사항으로, ‘make tests’를 입력하여 Bash 테스트 스위트를 실행할 수 있습니다.
  4. ‘make install’을 입력하여 bash와 bashbug를 설치합니다. 이 명령어는 매뉴얼 페이지(manual pages)와 Info 파일, 메시지 번역 파일들, 일부 보충 문서들, 여러 예시 로드 가능한(loadable) 빌트인 명령어들, 그리고 로드 가능한 빌트인 개발을 위한 헤더 파일 세트 또한 설치합니다. 원하는 위치에 bash를 설치하기 위해 추가적인 권한이 필요할 수 있으며, 이 경우 ‘sudo make install’이 필요할 수 있습니다. bash 및 다른 파일들이 설치되는 위치를 제어하는 방법에 대한 더 자세한 정보는 아래에 있습니다(설치 이름 참조).

configure 쉘 스크립트는 컴파일 중에 사용되는 다양한 시스템 의존적 변수들에 대한 올바른 값들을 추측하려고 시도합니다. 스크립트는 이 값들을 사용하여 패키지의 각 디렉토리(최상위 디렉토리, builtins, doc, po, support 디렉토리, lib 아래의 각 디렉토리 및 여러 기타 디렉토리)에 Makefile을 생성합니다. 또한 시스템 의존적인 정의들을 포함하는 config.h 파일을 생성합니다. 마지막으로 나중에 현재 구성을 재현하기 위해 실행할 수 있는 config.status라는 이름의 쉘 스크립트와, 재구성을 빠르게 하기 위해 테스트 결과들을 저장하는 config.cache 파일, 그리고 컴파일러 출력을 포함하는 config.log 파일(configure 디버깅에 주로 유용함)을 생성합니다. 어느 시점에 config.cache에 유지하고 싶지 않은 결과가 포함되어 있다면, 해당 파일을 삭제하거나 수정할 수 있습니다.

configure 스크립트가 이해하는 옵션과 인자들에 대해 더 자세히 알아보려면, Bash 소스 디렉토리의 Bash 프롬프트에서 다음과 같이 입력하십시오: 

bash-4.2$ ./configure --help

소스 디렉토리와 별개의 디렉토리에서 Bash를 빌드하고 싶다면 – 예를 들어 다중 아키텍처를 위해 빌드하는 경우 – configure 스크립트의 전체 경로를 사용하기만 하면 됩니다. 다음 명령어들은 /usr/local/src/bash-4.4에 있는 소스 코드를 사용하여 /usr/local/build/bash-4.4 아래의 디렉토리에서 Bash를 빌드할 것입니다: 

mkdir /usr/local/build/bash-4.4
cd /usr/local/build/bash-4.4
bash /usr/local/src/bash-4.4/configure
make

소스와 별개의 디렉토리에서 빌드하는 것에 대한 더 자세한 정보는 다중 아키텍처를 위한 컴파일을 참조하십시오.

Bash를 컴파일하기 위해 이례적인 작업이 필요하다면, configure가 그 작업의 필요 여부를 어떻게 확인할 수 있을지 고민해 보시고, 차이점(diffs)이나 지침을 bash-maintainers@gnu.org로 보내주시면 다음 릴리스에서 고려될 수 있습니다.

configure.ac 파일은 Autoconf라는 프로그램에 의해 configure를 생성하는 데 사용됩니다. configure.ac를 변경하거나 최신 버전의 Autoconf를 사용하여 configure를 다시 생성하고 싶은 경우에만 이 파일이 필요합니다. 이 작업을 수행하는 경우, Autoconf 버전 2.69 이상을 사용하고 있는지 확인하십시오.

‘make clean’을 입력하여 소스 코드 디렉토리에서 프로그램 바이너리와 오브젝트 파일들을 제거할 수 있습니다. 다른 종류의 컴퓨터를 위해 Bash를 컴파일할 수 있도록 configure가 생성한 파일들까지 제거하려면 ‘make distclean’을 입력하십시오.
