부록 B Bourne 쉘과의 주요 차이점 ¶

Bash는 기본적으로 Bourne 쉘과 거의 동일한 문법, 파라미터 및 변수 확장, 리다이렉션, 그리고 인용(quoting) 규칙을 구현합니다. Bash는 이러한 기능들이 어떻게 구현되고 어떻게 동작해야 하는지에 대한 명세로 POSIX 표준을 사용합니다. 전통적인 Bourne 쉘과 Bash 사이에는 몇 가지 차이점이 있으며, 이 섹션에서는 중요한 차이점들을 간략하게 설명합니다. 이러한 차이점 중 다수는 이전 섹션들에서 더 깊이 있게 설명되었습니다. 이 섹션에서는 SVR4.2에 포함된 sh 버전(역사적인 Bourne 쉘의 마지막 버전)을 기준점으로 사용합니다.

  • Bash는 POSIX 명세가 전통적인 sh의 동작과 다른 경우에도 POSIX를 준수합니다(Bash와 POSIX 참조).
  • Bash는 멀티 문자 호출 옵션을 가집니다(Bash 호출하기 참조).
  • Bash의 제한된 모드는 더 유용합니다(제한된 쉘 참조). SVR4.2 쉘의 제한된 모드는 너무 제약이 심합니다.
  • Bash는 명령줄 편집 기능(명령줄 편집 참조)과 bind 빌트인을 제공합니다.
  • Bash는 프로그래밍 가능한 단어 자동 완성 메커니즘(프로그래밍 가능한 자동 완성 참조)과 이를 조작하기 위한 complete, compgen, compopt 빌트인 명령어를 제공합니다.
  • Bash는 프롬프트 문자열 변수(PS0, PS1, PS2, PS4)에서 여러 백슬래시 이스케이프 시퀀스를 해석합니다(프롬프트 제어하기 참조).
  • Bash는 PS0 프롬프트 문자열 변수를 확장하고 표시합니다.
  • Bash는 각 기본 프롬프트를 내보내기 전에 PROMPT_COMMAND 배열 변수에 있는 명령어들을 실행합니다.
  • Bash는 명령어 히스토리(Bash 히스토리 기능 참조)와 이를 조작하기 위한 history 및 fc 빌트인을 제공합니다. Bash 히스토리 목록은 타임스탬프 정보를 유지하며 HISTTIMEFORMAT 변수 값을 사용하여 이를 표시합니다.
  • Bash는 csh와 유사한 히스토리 확장을 구현합니다(히스토리 확장 참조).
  • Bash는 $'…' 인용 문법을 지원하며, 작은따옴표 사이의 텍스트에서 ANSI-C 백슬래시 이스케이프 문자들을 확장합니다(ANSI-C 인용 참조).
  • Bash는 $"…" 인용 문법을 지원하며 큰따옴표 사이의 문자들에 대해 로케일 특정 번역을 수행합니다. -D, --dump-strings, 그리고 --dump-po-strings 호출 옵션은 스크립트에서 발견된 번역 가능한 문자열들을 나열합니다(로케일 특정 번역 참조).
  • Bash는 중괄호 확장(중괄호 확장 참조)과 물결표 확장(물결표 확장 참조)을 포함합니다.
  • Bash는 명령어 별칭(alias)과 alias 및 unalias 빌트인을 구현합니다(별칭 참조).
  • Bash는 파이프라인의 반환 값을 부정하는 ! 예약어를 구현합니다(파이프라인 참조). 이는 if 문이 테스트에 실패했을 때만 동작해야 하는 경우 매우 유용합니다. Bash set의 ‘-o pipefail’ 옵션은 파이프라인의 명령어 중 하나라도 실패하면 파이프라인이 실패 상태를 반환하도록 합니다(Set 빌트인 참조).
  • Bash는 time 예약어와 명령어 타이밍 측정 기능을 가집니다(파이프라인 참조). 타이밍 통계 표시는 TIMEFORMAT 변수로 제어할 수 있습니다.
  • Bash는 코프로세스(coprocesses)와 coproc 예약어를 제공합니다(코프로세스 참조).
  • Bash는 C 언어와 유사한 for (( expr1 ; expr2 ; expr3 )) 산술 for 명령어를 구현합니다(루프 구조 참조).
  • Bash는 간단한 메뉴 생성을 가능하게 하는 select 복합 명령어를 포함합니다(조건부 구조 참조).
  • Bash는 조건부 테스트를 쉘 문법의 일부로 만드는 [[ 복합 명령어를 포함하며(조건부 구조 참조), 여기에는 선택적인 정규 표현식 매칭이 포함됩니다.
  • Bash는 case 및 [[ 구조에 대해 선택적인 대소문자 구분 없는 매칭을 제공합니다(조건부 구조 참조).
  • Bash는 추가적인 case 문 액션 목록 종료 문자인 ‘;&’와 ‘;;&’를 제공합니다(조건부 구조 참조).
  • Bash는 쉘 산술 연산, (( 복합 명령어(조건부 구조 참조), let 빌트인, 그리고 산술 확장(쉘 산술 참조)을 제공합니다.
  • Bash는 1차원 배열 변수(배열 참조)와 이를 사용하기 위한 적절한 변수 확장 및 할당 문법을 가집니다. 여러 Bash 빌트인들이 배열에 작용하는 옵션들을 받습니다. Bash는 여러 내장 배열 변수들을 제공합니다.
  • 쉘의 초기 환경에 존재하는 변수들은 자동으로 자식 프로세스로 내보내기(export) 됩니다(명령어 실행 환경 참조). Bourne 쉘은 export 명령어를 사용하여 명시적으로 표시하지 않는 한 보통 이렇게 하지 않습니다.
  • Bash는 ${num}을 사용하여 $9를 넘어서는 위치 파라미터를 확장할 수 있습니다(쉘 파라미터 확장 참조).
  • Bash는 왼쪽 변수의 값에 덧붙이는 ‘+=’ 할당 연산자를 지원합니다(쉘 파라미터 참조).
  • Bash는 변수 값에서 앞부분 또는 뒷부분의 부분 문자열을 제거하는 POSIX 패턴 제거 확장인 ‘%’, ‘#’, ‘%%’, ‘##’을 포함합니다(쉘 파라미터 확장 참조).
  • ${xx}의 길이를 반환하는 ${#xx} 확장이 지원됩니다(쉘 파라미터 확장 참조).
  • var 값의 offset부터 시작하는 length 길이의 부분 문자열로 확장되는 ${var:offset[:length]} 확장이 존재합니다(쉘 파라미터 확장 참조).
  • var 값에서 pattern과 일치하는 부분을 찾아 replacement로 교체하는 ${var/[/]pattern[/replacement]} 확장이 가능하며(쉘 파라미터 확장 참조), 일치된 텍스트를 replacement에서 사용할 수 있는 메커니즘도 제공합니다.
  • 이름이 prefix로 시작하는 모든 쉘 변수의 이름들로 확장되는 ${!prefix*} 확장이 가능합니다(쉘 파라미터 확장 참조).
  • Bash는 ${!word}를 사용한 간접 변수 확장을 지원하며(쉘 파라미터 확장 참조), 자동 간접 변수 확장을 위한 nameref 변수 속성을 구현합니다.
  • Bash는 ‘X’가 변환 방식을 지정하는 ${var@X} 형식의 일련의 파라미터 변환 단어 확장을 포함합니다(쉘 파라미터 확장 참조).
  • 명령어 치환의 POSIX $() 형식이 구현되어 있으며(명령어 치환 참조), Bourne 쉘의 ``(하위 호환성을 위해 역시 구현됨)보다 선호됩니다.
  • Bash는 감싸진 명령어를 현재 쉘 실행 환경에서 실행하는 명령어 치환의 변형인 ${ command;} 또는 ${|command;}를 구현합니다(명령어 치환 참조).
  • Bash는 프로세스 치환(process substitution) 기능을 가집니다(프로세스 치환 참조).
  • Bash는 현재 사용자 정보(UID, EUID, GROUPS), 현재 호스트 정보(HOSTTYPE, OSTYPE, MACHTYPE, HOSTNAME), 그리고 실행 중인 Bash 인스턴스 정보(BASH, BASH_VERSION, BASH_VERSINFO)를 제공하는 변수들을 자동으로 할당합니다. 자세한 내용은 Bash 변수를 참조하십시오.
  • Bash는 Bourne 쉘에는 없는, 기능을 제공하고 쉘 동작을 커스터마이징하기 위한 많은 변수들을 사용합니다. 예로는 RANDOM, SRANDOM, EPOCHSECONDS, EPOCHREALTIME, TIMEFORMAT, BASHPID, BASH_XTRACEFD, GLOBIGNORE, HISTIGNORE, 그리고 BASH_VERSION 등이 있습니다. 전체 목록은 Bash 변수를 참조하십시오.
  • Bash는 파일 이름 확장 결과의 정렬 방식을 제어하기 위해 GLOBSORT 쉘 변수를 사용합니다(파일 이름 확장 참조).
  • Bash는 모든 단어가 아닌 오직 확장 결과만 분할하기 위해 IFS 변수를 사용합니다(단어 분할 참조). 이는 오랫동안 존재해 온 쉘 보안 허점을 해결합니다.
  • 파일 이름 확장 브래킷 표현식 코드에서 브래킷 사이의 문자 세트를 부정하기 위해 ‘!’와 ‘^’를 모두 사용합니다(파일 이름 확장 참조). Bourne 쉘은 오직 ‘!’만 사용합니다.
  • Bash는 문자 클래스, 동등 클래스, 그리고 정렬 기호를 포함한 POSIX 파일 이름 확장 연산자 전체 세트를 구현합니다(파일 이름 확장 참조).
  • Bash는 extglob 쉘 옵션이 활성화되었을 때 확장된 패턴 매칭 기능들을 구현합니다(패턴 매칭 참조).
  • globstar 쉘 옵션은 파일 이름 확장을 확장하여 일치하는 파일 이름을 찾기 위해 디렉토리와 하위 디렉토리를 재귀적으로 스캔합니다(패턴 매칭 참조).
  • 동일한 이름의 변수와 함수를 가질 수 있습니다; sh는 두 네임스페이스를 분리하지 않습니다.
  • Bash 함수는 local 빌트인을 사용하여 지역 변수를 가질 수 있으며, 따라서 사용자는 유용한 재귀 함수를 작성할 수 있습니다(Bash 빌트인 명령어 참조).
  • Bash는 입력 및 출력 리다이렉션 연산자의 피연산자로 지정된 파일 이름에 대해 파일 이름 확장을 수행합니다(리다이렉션 참조).
  • Bash는 파일을 읽기 및 쓰기용으로 모두 열 수 있게 해주는 ‘<>’ 리다이렉션 연산자와, 표준 출력과 표준 에러를 동일한 파일로 보내는 ‘&>’ 리다이렉션 연산자를 포함합니다(리다이렉션 참조).
  • Bash는 문자열을 명령어의 표준 입력으로 사용할 수 있게 해주는 ‘<<<’ 리다이렉션 연산자를 포함합니다(리다이렉션 참조).
  • Bash는 하나의 파일 디스크립터를 다른 곳으로 옮기는 ‘[n]<&word’ 및 ‘[n]>&word’ 리다이렉션 연산자를 구현합니다.
  • Bash는 리다이렉션 연산자에서 사용될 때 여러 파일 이름들을 특별하게 취급합니다(리다이렉션 참조).
  • Bash는 쉘이 리다이렉션을 위해 파일 디스크립터를 할당하고 이를 var에 할당하도록 하는 {var}<word 기능을 제공합니다(리다이렉션 참조). 이는 여러 리다이렉션 연산자와 함께 작동합니다.
  • Bash는 리다이렉션 연산자를 사용하여 임의의 머신 및 서비스에 네트워크 연결을 열 수 있습니다(리다이렉션 참조).
  • 출력 리다이렉션 시 기존 파일을 덮어쓰는 것을 방지하기 위해 noclobber 옵션을 사용할 수 있습니다(Set 빌트인 참조). ‘>|’ 리다이렉션 연산자를 사용하여 noclobber 설정을 무시할 수 있습니다.
  • 명령어 앞에 오는 변수 할당은 빌트인 및 함수를 포함하여 오직 해당 명령어에만 영향을 미칩니다(환경 참조). sh에서 명령어 앞에 오는 모든 변수 할당은 파일 시스템에서 실행되는 명령어가 아닌 한 전역적입니다.
  • Bash는 쉘 스크립트를 위한 별도의 디버거를 지원하기 위해 여러 기능들을 포함합니다: 변수(BASH_ARGC, BASH_ARGV, BASH_LINENO, BASH_SOURCE), DEBUG, RETURN, 및 ERR 트랩, ‘declare -F’, 그리고 caller 빌트인.
  • Bash는 csh와 유사한 디렉토리 스택을 구현하며, 이를 조작하기 위한 pushd, popd, 및 dirs 빌트인을 제공합니다(디렉토리 스택 참조). Bash는 또한 디렉토리 스택을 DIRSTACK 쉘 변수의 값으로 시각화합니다.
  • Bash는 함수가 동일한 이름의 빌트인을 오버라이드할 수 있게 허용하며, builtin 및 command 빌트인을 통해 함수 내에서 해당 빌트인의 기능에 접근할 수 있게 해줍니다(Bash 빌트인 명령어 참조).
  • Bash는 활성 상태인 서브루틴 호출(쉘 함수 또는 . 이나 source 빌트인으로 실행된 스크립트)의 컨텍스트를 표시하는 caller 빌트인(Bash 빌트인 명령어 참조)을 포함합니다. 이는 Bash 디버거를 지원합니다.
  • Bash cd 및 pwd 빌트인(Bourne 쉘 빌트인 참조)은 각각 논리(logical) 및 물리(physical) 모드 사이를 전환하기 위한 -L 및 -P 옵션을 받습니다.
  • command 빌트인은 명령어 검색 시 선택적으로 쉘 함수를 건너뛸 수 있게 해줍니다(Bash 빌트인 명령어 참조).
  • Bash는 변수 및 함수 속성의 전체 세트를 수정하고 변수에 값을 할당하기 위해 declare 빌트인을 사용합니다.
  • disown 빌트인은 내부 쉘 작업 테이블에서 작업을 제거하거나(작업 제어 빌트인 참조), 쉘이 SIGHUP의 결과로 종료될 때 해당 작업에 SIGHUP을 보내는 것을 억제할 수 있습니다.
  • enable 빌트인(Bash 빌트인 명령어 참조)은 개별 빌트인을 활성화하거나 비활성화할 수 있으며, 공유 오브젝트(shared objects)로부터 빌트인 명령어를 동적으로 로드하는 기능을 구현합니다.
  • Bash exec 빌트인은 실행되는 명령어에 전달되는 환경의 내용과 명령어의 0번째 인자가 무엇이 될지를 사용자가 제어할 수 있게 해주는 추가 옵션들을 받습니다(Bourne 쉘 빌트인 참조).
  • 쉘 함수는 export -f를 사용하여 환경을 통해 자식 프로세스로 내보내기(export) 될 수 있습니다(쉘 함수 참조).
  • Bash export 및 readonly 빌트인(Bourne 쉘 빌트인 참조)은 쉘 함수에 작용하기 위한 -f 옵션, 다양한 속성이 설정된 변수들을 쉘 입력으로 사용 가능한 형식으로 표시하기 위한 -p 옵션, 다양한 변수 속성들을 제거하기 위한 -n 옵션, 그리고 변수 속성과 값을 동시에 설정하기 위한 ‘name=value’ 인자들을 받을 수 있습니다.
  • Bash hash 빌트인은 ‘hash -p’를 사용하여 해당 파일 이름을 $PATH 검색을 통해 찾을 수 없는 경우에도 임의의 파일 이름과 이름을 연관시킬 수 있게 해줍니다(Bourne 쉘 빌트인 참조).
  • Bash는 쉘 기능들에 대한 빠른 참조를 위해 help 빌트인을 포함합니다(Bash 빌트인 명령어 참조).
  • Bash는 파일의 내용을 인덱스 배열 변수로 빠르게 읽어 들이기 위한 mapfile 빌트인을 포함합니다(Bash 빌트인 명령어 참조).
  • 형식화된 출력을 표시하기 위해 printf 빌트인을 사용할 수 있으며(Bash 빌트인 명령어 참조), 추가적인 커스텀 형식 지정자(format specifiers)와 형식화된 출력을 쉘 변수에 직접 할당하는 옵션을 가집니다.
  • Bash read 빌트인(Bash 빌트인 명령어 참조)은 -r 옵션을 사용하여 ‘\’로 끝나는 줄을 읽을 수 있으며, 옵션이 아닌 인자가 제공되지 않은 경우 REPLY 변수를 기본값으로 사용합니다.
  • Bash read 빌트인(Bash 빌트인 명령어 참조)은 -p 옵션으로 프롬프트 문자열을 받을 수 있고, -e 또는 -E 옵션이 주어지면 줄을 얻기 위해 Readline을 사용하며, -i 옵션을 사용하여 줄에 텍스트를 삽입하는 기능을 가집니다. read 빌트인은 또한 입력을 제어하기 위한 추가 옵션들을 가집니다: -s 옵션은 입력 문자가 읽힐 때 에코(echo)되는 것을 끄고, -t 옵션은 지정된 초 내에 입력이 도착하지 않으면 read가 타임아웃되도록 하며, -n 옵션은 전체 줄이 아닌 지정된 개수의 문자만 읽도록 하고, -d 옵션은 줄바꿈 대신 특정 문자까지 읽도록 합니다.
  • return 빌트인은 . 이나 source 빌트인으로 실행된 스크립트의 실행을 중단하는 데 사용될 수 있습니다(Bourne 쉘 빌트인 참조).
  • Bash는 set 빌트인으로 제어 가능한 훨씬 더 많은 선택적 동작들을 가집니다(Set 빌트인 참조).
  • -x (xtrace) 옵션은 실행 추적 수행 시 단순 명령어 이외의 명령어들도 표시합니다(Set 빌트인 참조).
  • Bash는 쉘의 선택적 기능들을 더 세밀하게 제어하기 위한 shopt 빌트인을 포함하며(Shopt 빌트인 참조), 쉘 호출 시 이러한 옵션들을 설정하거나 해제할 수 있게 해줍니다(Bash 호출하기 참조).
  • test 빌트인(Bourne 쉘 빌트인 참조)은 인자의 개수에 따라 동작을 명시하는 POSIX 알고리즘을 구현한다는 점에서 약간 다릅니다.
  • trap 빌트인(Bourne 쉘 빌트인 참조)은 EXIT와 유사하게 DEBUG 의사 시그널(pseudo-signal) 지정을 허용합니다. DEBUG 트랩으로 지정된 명령어들은 모든 단순 명령어, for 명령어, case 명령어, select 명령어, 모든 산술 for 명령어 이전, 그리고 쉘 함수의 첫 번째 명령어가 실행되기 전에 실행됩니다. DEBUG 트랩은 함수에 trace 속성이 부여되거나 shopt 빌트인을 사용하여 functrace 옵션이 활성화되지 않는 한 쉘 함수에 상속되지 않습니다. extdebug 쉘 옵션은 DEBUG 트랩에 추가적인 효과를 줍니다.

    trap 빌트인(Bourne 쉘 빌트인 참조)은 EXIT 및 DEBUG와 유사하게 ERR 의사 시그널 지정을 허용합니다. ERR 트랩으로 지정된 명령어들은 몇 가지 예외 상황을 제외하고 단순 명령어가 실패한 후에 실행됩니다. ERR 트랩은 set 빌트인의 -o errtrace 옵션이 활성화되어 있지 않는 한 쉘 함수에 상속되지 않습니다.

    trap 빌트인(Bourne 쉘 빌트인 참조)은 EXIT 및 DEBUG와 유사하게 RETURN 의사 시그널 지정을 허용합니다. RETURN 트랩으로 지정된 명령어들은 쉘 함수나 . 또는 source로 실행된 쉘 스크립트가 반환(return)된 후 실행이 재개되기 직전에 실행됩니다. RETURN 트랩은 함수에 trace 속성이 부여되거나 shopt 빌트인을 사용하여 functrace 옵션이 활성화되지 않는 한 쉘 함수에 상속되지 않습니다.

  • Bash type 빌트인은 더 광범위하며 발견된 이름들에 대해 더 많은 정보를 제공합니다(Bash 빌트인 명령어 참조).
  • ulimit 빌트인은 훨씬 더 많은 프로세스당 리소스에 대한 제어 기능을 제공합니다(Bash 빌트인 명령어 참조).
  • Bash umask 빌트인은 입력을 위해 재사용할 수 있는 umask 명령어 형식으로 출력을 표시하기 위해 -p 옵션을 사용합니다(Bourne 쉘 빌트인 참조).
  • Bash wait 빌트인은 다음 자식 프로세스가 종료될 때까지 기다리는 -n 옵션(제공된 작업 목록에서 선택 가능함)과, 종료된 자식 프로세스에 대한 정보를 쉘 변수에 저장하는 -p 옵션을 가집니다.
  • SVR4.2 쉘은 jsh로 호출되었을 때 다르게 동작합니다(작업 제어를 켭니다).
  • SVR4.2 쉘은 Bash에는 없는 두 가지 권한 관련 빌트인(mldmode 및 priv)을 가집니다.
  • Bash는 stop 또는 newgrp 빌트인을 가지고 있지 않습니다.
  • Bash는 SHACCT 변수를 사용하지 않으며 쉘 어카운팅(shell accounting)을 수행하지 않습니다.
  • SVR4.2 sh는 Bash가 TMOUT을 사용하는 것처럼 TIMEOUT 변수를 사용합니다.

Bash에만 있는 더 많은 기능들은 Bash 기능에서 찾을 수 있습니다.

  • SVR4.2 쉘과의 구현 차이점

B.1 SVR4.2 쉘과의 구현 차이점 ¶

Bash는 완전히 새로운 구현체이기 때문에 SVR4.2 쉘이 가진 많은 한계들로부터 자유롭습니다. 예를 들어:

  • Bash는 if 또는 while 문과 같은 쉘 제어 구조로/로부터 리다이렉션할 때 서브쉘을 포크(fork)하지 않습니다.
  • Bash는 짝이 맞지 않는 따옴표를 허용하지 않습니다. SVR4.2 쉘은 특정 상황에서 EOF를 만났을 때 필요한 닫는 따옴표를 자동으로 삽입합니다. 이는 찾기 힘든 에러의 원인이 될 수 있습니다.
  • SVR4.2 쉘은 SIGSEGV를 트랩하는 방식에 기반한 기괴한 메모리 관리 기법을 사용합니다. 만약 쉘이 SIGSEGV가 차단된 프로세스(예: system() C 라이브러리 함수 호출을 통해)로부터 시작된다면 매우 비정상적으로 동작합니다.
  • 보안을 위한 의심스러운 시도로서, SVR4.2 쉘은 -p 옵션 없이 호출되었을 때 실제 및 유효 UID와 GID가 특정 매직 임계값(보통 100)보다 작으면 이를 변경합니다. 이는 예상치 못한 결과를 초래할 수 있습니다.
  • SVR4.2 쉘은 사용자가 SIGSEGV, SIGALRM, 또는 SIGCHLD를 트랩하는 것을 허용하지 않습니다.
  • SVR4.2 쉘은 IFS, MAILCHECK, PATH, PS1, 또는 PS2 변수의 해제(unset)를 허용하지 않습니다.
  • SVR4.2 쉘은 ‘^’를 ‘|’의 문서화되지 않은 동의어로 취급합니다.
  • Bash는 호출 시 여러 옵션 인자들을 허용합니다(-x -v); SVR4.2 쉘은 오직 하나의 옵션 인자만 허용합니다(-xv). 사실 일부 버전의 쉘은 두 번째 인자가 ‘-’로 시작하면 코어 덤프(dump core)를 발생시킵니다.
  • SVR4.2 쉘은 어떤 빌트인이라도 실패하면 스크립트를 종료합니다; Bash는 POSIX 표준에 열거된 특정한 실패 사례에 대해 POSIX 특수 빌트인 중 하나가 실패했을 때만 스크립트를 종료합니다.
  • 만약 lastpipe 옵션이 활성화되어 있고 작업 제어가 활성화되어 있지 않다면, Bash는 파이프라인의 마지막 요소를 현재 쉘 실행 환경에서 실행합니다.
