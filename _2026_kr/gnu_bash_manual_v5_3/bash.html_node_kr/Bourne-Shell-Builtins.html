4.1 Bourne 쉘 빌트인 ¶

다음 쉘 빌트인 명령어들은 Bourne 쉘로부터 상속되었습니다. 이 명령어들은 POSIX 표준에 명시된 대로 구현되었습니다.

: (콜론) ¶
: [arguments]

arguments를 확장하고 리다이렉션을 수행하는 것 외에는 아무것도 하지 않습니다. 반환 상태는 0입니다.

. (마침표) ¶
. [-p path] filename [arguments]

. 명령어는 현재 쉘 컨텍스트에서 filename 인자로 지정된 파일로부터 명령어들을 읽어 실행합니다.

만약 filename에 슬래시(/)가 포함되어 있지 않다면, .은 파일을 검색합니다. -p가 제공되면, .은 path를 filename을 찾을 콜론(:)으로 구분된 디렉토리 목록으로 취급합니다. 그렇지 않으면 PATH 변수에 지정된 디렉토리들을 사용하여 filename을 찾습니다. filename은 실행 가능할 필요가 없습니다. Bash가 POSIX 모드가 아닐 때 $PATH에서 filename을 찾지 못하면 현재 디렉토리에서 검색하지만, -p가 제공된 경우에는 현재 디렉토리를 검색하지 않습니다. 만약 sourcepath 옵션(Shopt 빌트인 참조)이 꺼져 있으면, .은 PATH를 검색하지 않습니다.

인자 arguments가 제공되면, 이들은 filename이 실행될 때 위치 파라미터가 됩니다. 그렇지 않으면 위치 파라미터는 변경되지 않습니다.

만약 -T 옵션이 활성화되어 있으면, .은 DEBUG 트랩을 상속받습니다. 그렇지 않으면 DEBUG 트랩 문자열은 . 호출 전후로 저장 및 복구되며, .은 실행되는 동안 DEBUG 트랩을 해제합니다. 만약 -T가 설정되어 있지 않고 불러온 파일이 DEBUG 트랩을 변경한다면, 새로운 값은 .이 완료된 후에도 유지됩니다. 반환 상태는 filename에서 마지막으로 실행된 명령어의 종료 상태이며, 실행된 명령어가 없는 경우 0입니다. 만약 filename을 찾을 수 없거나 읽을 수 없는 경우, 반환 상태는 0이 아닙니다. 이 빌트인은 source와 동일합니다.

break ¶
break [n]

for, while, until, 또는 select 루프에서 빠져나옵니다. n이 제공되면, break는 자신을 둘러싼 루프 중 n번째 바깥쪽 루프까지 빠져나옵니다. n은 1보다 크거나 같아야 합니다. 반환 상태는 n이 1보다 크거나 같은 경우 0입니다.

cd ¶
cd [-L] [-@] [directory]
cd -P [-e] [-@] [directory]

현재 작업 디렉토리를 directory로 변경합니다. 만약 directory가 제공되지 않으면, HOME 쉘 변수의 값이 directory로 사용됩니다. 만약 CDPATH 쉘 변수가 존재하고 directory가 슬래시로 시작하지 않는다면, cd는 이를 검색 경로로 사용합니다: cd는 CDPATH 내의 각 디렉토리에서 directory를 검색하며, 각 디렉토리 이름은 콜론(:)으로 구분됩니다. CDPATH 내의 빈 디렉토리 이름은 현재 디렉토리와 같은 의미입니다.

-P 옵션은 심볼릭 링크를 따라가지 않음을 의미합니다: cd가 directory를 횡단하는 동안, 그리고 directory 내의 ..을 처리하기 전에 심볼릭 링크를 해석합니다.

기본적으로, 또는 -L 옵션이 제공된 경우, 심볼릭 링크는 cd가 directory 내의 ..을 처리한 후에 해석됩니다.

만약 ..이 directory에 나타나면, cd는 바로 앞의 경로 구성 요소를 슬래시 또는 directory 시작 부분까지 제거하여 처리하며, 경로 구성 요소를 제거한 후에도 해당 시점까지 처리된 directory 부분이 여전히 유효한 디렉토리 이름인지 확인합니다. 유효한 디렉토리 이름이 아니라면 cd는 0이 아닌 상태를 반환합니다.

만약 -e 옵션이 -P와 함께 제공되었고, 디렉토리 변경에 성공한 후에도 cd가 현재 작업 디렉토리를 성공적으로 확인할 수 없다면 0이 아닌 상태를 반환합니다.

이를 지원하는 시스템에서 -@ 옵션은 파일과 연관된 확장 속성(extended attributes)을 디렉토리처럼 보여줍니다.

만약 directory가 ‘-’라면, 디렉토리 변경을 시도하기 전에 이를 $OLDPWD로 변환합니다.

만약 cd가 CDPATH로부터 비어 있지 않은 디렉토리 이름을 사용했거나, ‘-’가 첫 번째 인자였고 디렉토리 변경에 성공했다면, cd는 새로운 작업 디렉토리의 절대 경로명을 표준 출력으로 보냅니다.

디렉토리 변경에 성공하면, cd는 PWD 환경 변수의 값을 새로운 디렉토리 이름으로 설정하고, OLDPWD 환경 변수의 값을 변경 전의 현재 작업 디렉토리 값으로 설정합니다.

반환 상태는 디렉토리 변경에 성공한 경우 0이고, 그렇지 않으면 0이 아닙니다.

continue ¶
continue [n]

continue는 자신을 둘러싼 for, while, until, 또는 select 루프의 다음 반복을 재개합니다. n이 제공되면, Bash는 자신을 둘러싼 루프 중 n번째 바깥쪽 루프의 실행을 재개합니다. n은 1보다 크거나 같아야 합니다. 반환 상태는 n이 1보다 크거나 같은 경우 0입니다.

eval ¶
eval [arguments]

인자 arguments들을 공백으로 구분하여 하나의 명령어로 결합합니다. 그런 다음 Bash는 이 명령어를 읽어 실행하고, 그 종료 상태를 eval의 종료 상태로 반환합니다. 인자가 없거나 빈 인자만 있는 경우 반환 상태는 0입니다.

exec ¶
exec [-cl] [-a name] [command [arguments]]

만약 command가 제공되면, 새로운 프로세스를 생성하지 않고 현재 쉘을 해당 명령어로 대체합니다. command는 쉘 빌트인이나 함수일 수 없습니다. 인자 arguments는 command의 인자가 됩니다. -l 옵션이 제공되면, 쉘은 command에 전달되는 0번 인자의 시작 부분에 대시(-)를 추가합니다. 이는 login 프로그램이 하는 작업과 같습니다. -c 옵션은 command가 빈 환경(environment)에서 실행되도록 합니다. -a가 제공되면, 쉘은 name을 command의 0번 인자로 전달합니다.

어떤 이유로든 command를 실행할 수 없는 경우, execfail 쉘 옵션이 활성화되어 있지 않다면 비대화형 쉘은 종료됩니다. execfail이 설정된 경우 0이 아닌 상태를 반환합니다. 대화형 쉘은 파일을 실행할 수 없는 경우 0이 아닌 상태를 반환합니다. 서브쉘은 exec가 실패할 경우 무조건 종료됩니다.

만약 command가 지정되지 않았다면, 리다이렉션을 사용하여 현재 쉘 환경에 영향을 줄 수 있습니다. 리다이렉션 에러가 없다면 반환 상태는 0이고, 그렇지 않으면 0이 아닙니다.

exit ¶
exit [n]

쉘을 종료하며 부모 프로세스에게 상태 n을 반환합니다. n이 생략되면 종료 상태는 마지막으로 실행된 명령어의 종료 상태가 됩니다. EXIT에 설정된 모든 트랩은 쉘이 종료되기 전에 실행됩니다.

export ¶
export [-fn] [-p] [name[=value]]

이후에 실행되는 명령어들의 환경(environment)으로 전달되도록 각 name을 표시합니다. -f 옵션이 제공되면 name은 쉘 함수를 참조하고, 그렇지 않으면 쉘 변수를 참조합니다.

-n 옵션은 각 이름의 내보내기 표시를 제거함을 의미합니다. name이 제공되지 않거나 -p 옵션만 주어진 경우, export는 모든 내보내기된 변수들의 이름 목록을 표준 출력으로 표시합니다. -p와 -f를 함께 사용하면 내보내기된 함수들을 표시합니다. -p 옵션은 출력물을 입력으로 재사용할 수 있는 형식으로 표시합니다.

export는 변수 이름 뒤에 =value를 붙여 변수를 내보냄과 동시에 값을 설정할 수 있게 해줍니다. 이는 내보내기 속성을 수정하면서 변수의 값을 value로 설정합니다.

반환 상태는 잘못된 옵션이 제공되거나, 이름 중 하나가 유효한 쉘 변수 이름이 아니거나, 쉘 함수가 아닌 이름에 -f가 사용된 경우를 제외하고 0입니다.

false ¶
false

아무것도 하지 않으며, 0이 아닌 상태를 반환합니다.

getopts ¶
getopts optstring name [arg ...]

getopts는 쉘 스크립트나 함수에서 위치 파라미터를 파싱하고 옵션과 그 인자들을 얻기 위해 사용됩니다. optstring은 인식할 옵션 문자들을 포함합니다. 문자가 콜론(:) 뒤에 오면 해당 옵션은 인자를 가질 것으로 예상되며, 인자는 공백으로 구분되어야 합니다. 콜론(‘:’)과 물음표(‘?’)는 옵션 문자로 사용할 수 없습니다.

호출될 때마다 getopts는 다음 옵션을 쉘 변수 name에 넣고(존재하지 않으면 name을 초기화함), 다음에 처리할 인자의 인덱스를 OPTIND 변수에 넣습니다. OPTIND는 쉘이나 쉘 스크립트가 호출될 때마다 1로 초기화됩니다. 옵션이 인자를 요구하는 경우, getopts는 해당 인자를 OPTARG 변수에 넣습니다.

쉘은 OPTIND를 자동으로 리셋하지 않습니다. 동일한 쉘 호출 내에서 새로운 파라미터 세트를 사용하기 위해 getopts를 여러 번 호출할 때는 수동으로 리셋해야 합니다.

옵션의 끝에 도달하면 getopts는 0보다 큰 반환 값으로 종료됩니다. OPTIND는 첫 번째 비-옵션 인자의 인덱스로 설정되며, name은 ‘?’로 설정됩니다.

getopts는 보통 위치 파라미터를 파싱하지만, arg 값으로 더 많은 인자들이 제공되면 대신 그것들을 파싱합니다.

getopts는 두 가지 방식으로 에러를 보고할 수 있습니다. 만약 optstring의 첫 번째 문자가 콜론이라면, getopts는 저소음(silent) 에러 보고 방식을 사용합니다. 일반적인 동작에서는 잘못된 옵션을 만나거나 옵션 인자가 누락된 경우 진단 메시지를 출력합니다. 만약 OPTERR 변수가 0으로 설정되어 있다면, optstring의 첫 번째 문자가 콜론이 아니더라도 에러 메시지를 표시하지 않습니다.

만약 getopts가 잘못된 옵션을 감지하면, ‘?’를 name에 넣고, 저소음 모드가 아니라면 에러 메시지를 출력한 뒤 OPTARG를 해제합니다. 만약 저소음 모드라면 발견된 옵션 문자를 OPTARG에 할당하고 진단 메시지를 출력하지 않습니다.

필요한 인자를 찾지 못했고 저소음 모드가 아니라면, name의 값을 물음표(‘?’)로 설정하고 OPTARG를 해제한 뒤 진단 메시지를 출력합니다. 만약 저소음 모드라면 name의 값을 콜론(‘:’)으로 설정하고, 발견된 옵션 문자를 OPTARG에 설정합니다.

getopts는 명시된 옵션이든 명시되지 않은 옵션이든 발견되면 참(true)을 반환합니다. 옵션의 끝을 만나거나 에러가 발생하면 거짓(false)을 반환합니다.

hash ¶
hash [-r] [-p filename] [-dt] [name]

hash가 호출될 때마다 name 인자로 지정된 명령어들의 전체 경로명을 기억해 두어, 이후 호출 시 다시 검색할 필요가 없도록 합니다. 명령어들은 $PATH에 나열된 디렉토리들을 검색하여 찾습니다. name과 연관되어 이전에 기억된 모든 경로는 버려집니다. -p 옵션은 경로 검색을 억제하며, hash는 filename을 name의 위치로 사용합니다.

-r 옵션은 쉘이 기억하고 있는 모든 위치를 잊게 합니다. PATH 변수에 값을 할당하는 것 또한 모든 해시된 파일 이름들을 지웁니다. -d 옵션은 쉘이 각 name에 대해 기억하고 있는 위치를 잊게 합니다.

만약 -t 옵션이 제공되면, hash는 각 name에 대응하는 전체 경로명을 출력합니다. -t와 함께 여러 name 인자가 제공되면, 해시된 전체 경로 앞에 각 name을 출력합니다. -l 옵션은 출력물을 입력으로 재사용할 수 있는 형식으로 표시합니다.

인자가 주어지지 않거나 -l만 제공된 경우, hash는 기억된 명령어들에 대한 정보를 출력합니다. -t, -d, 그리고 -p 옵션(name 인자들에 작용하는 옵션들)은 서로 배타적입니다. 오직 하나만 활성화될 수 있습니다. 둘 이상이 제공되면 -t가 -p보다 우선순위가 높고, 두 옵션 모두 -d보다 우선순위가 높습니다.

반환 상태는 name을 찾지 못하거나 잘못된 옵션이 제공된 경우를 제외하고 0입니다.

pwd ¶
pwd [-LP]

현재 작업 디렉토리의 절대 경로명을 출력합니다. 만약 -P 옵션이 제공되거나, set 빌트인의 -o physical 옵션(Set 빌트인 참조)이 활성화되어 있다면, 출력되는 경로명에 심볼릭 링크가 포함되지 않습니다. 만약 -L 옵션이 제공되면, 출력되는 경로명에 심볼릭 링크가 포함될 수 있습니다. 반환 상태는 현재 디렉토리 이름을 결정하는 동안 에러가 발생하거나 잘못된 옵션이 제공된 경우를 제외하고 0입니다.

readonly ¶
readonly [-aAf] [-p] [name[=value]] ...

각 name을 읽기 전용(readonly)으로 표시합니다. 이 이름들의 값은 이후의 할당이나 해제(unset)에 의해 변경될 수 없습니다. -f 옵션이 제공되면 각 name은 쉘 함수를 참조합니다. -a 옵션은 각 name이 인덱스 배열 변수를 참조함을 의미하며, -A 옵션은 각 name이 연관 배열 변수를 참조함을 의미합니다. 두 옵션이 모두 제공되면 -A가 우선합니다. name 인자가 제공되지 않거나 -p 옵션이 제공되면, 모든 읽기 전용 이름 목록을 출력합니다. 다른 옵션들을 사용하여 출력 대상을 읽기 전용 이름들의 일부로 제한할 수 있습니다. -p 옵션은 출력물을 입력으로 재사용할 수 있는 형식으로 표시합니다.

readonly는 변수 이름 뒤에 =value를 붙여 읽기 전용 속성을 부여함과 동시에 변수의 값을 설정할 수 있게 해줍니다. 이는 읽기 전용 속성을 수정하면서 변수의 값을 value로 설정합니다.

반환 상태는 잘못된 옵션이 제공되거나, name 인자 중 하나가 유효한 쉘 변수나 함수 이름이 아니거나, 쉘 함수가 아닌 이름에 -f가 사용된 경우를 제외하고 0입니다.

return ¶
return [n]

쉘 함수의 실행이나 불러온 파일의 실행을 중단하고 값 n을 호출자에게 반환합니다. n이 제공되지 않으면 반환 값은 마지막으로 실행된 명령어의 종료 상태가 됩니다. 만약 return이 트랩 핸들러에 의해 실행되면, 상태 결정에 사용되는 마지막 명령어는 트랩 핸들러 이전에 실행된 마지막 명령어입니다. 만약 return이 DEBUG 트랩 도중에 실행되면, 상태 결정에 사용되는 마지막 명령어는 return이 호출되기 전 트랩 핸들러에 의해 실행된 마지막 명령어입니다.

return이 . (source) 빌트인으로 실행 중인 스크립트를 종료하는 데 사용되면, n이나 스크립트 내에서 마지막으로 실행된 명령어의 종료 상태를 스크립트의 종료 상태로 반환합니다. n이 제공되면 반환 값은 그 값의 하위 8비트입니다.

RETURN 트랩과 연관된 모든 명령어는 함수나 스크립트 종료 후 실행이 재개되기 전에 실행됩니다.

반환 상태는 return에 숫자가 아닌 인자가 제공되거나, 함수 외부에서 그리고 . 이나 source에 의한 스크립트 실행 도중이 아닐 때 사용된 경우 0이 아닙니다.

shift ¶
shift [n]

위치 파라미터들을 왼쪽으로 n만큼 이동시킵니다: 위치 파라미터 n+1 … $#은 $1 … $#-n으로 이름이 변경됩니다. $#부터 $#-n+1까지의 숫자로 나타내던 파라미터들은 해제(unset)됩니다. n은 0보다 크거나 같고 $#보다 작거나 같은 숫자여야 합니다. n이 제공되지 않으면 1로 간주합니다. n이 0이거나 $#보다 크면 위치 파라미터는 변경되지 않습니다. 반환 상태는 n이 $#보다 크거나 0보다 작은 경우를 제외하고 0이며, 그 외의 경우 0이 아닙니다.

test ¶
[
test expr

조건식 expr을 평가하고 0(참) 또는 1(거짓)의 상태를 반환합니다. 각 연산자와 피연산자는 별개의 인자여야 합니다. 식은 아래 Bash 조건식에 설명된 기본 요소(primaries)들로 구성됩니다. test는 어떤 옵션도 받지 않으며, 옵션의 끝을 나타내는 -- 인자도 받아들이거나 무시하지 않습니다. [ 형식을 사용할 때, 명령어의 마지막 인자는 반드시 ]여야 합니다.

식들은 우선순위가 낮아지는 순서대로 나열된 다음 연산자들을 사용하여 조합될 수 있습니다. 평가는 인자의 개수에 따라 달라집니다(아래 참조). 인자가 5개 이상일 때 test는 연산자 우선순위를 사용합니다.

! expr

expr이 거짓이면 참입니다.

( expr )

expr의 값을 반환합니다. 이는 일반적인 연산자 우선순위를 재정의하는 데 사용될 수 있습니다.

expr1 -a expr2

expr1과 expr2가 모두 참이면 참입니다.

expr1 -o expr2

expr1 또는 expr2 중 하나라도 참이면 참입니다.

test와 [ 빌트인은 인자의 개수에 따른 규칙 세트를 사용하여 조건식을 평가합니다.

인자 0개

식은 거짓입니다.

인자 1개

인자가 null이 아닌 경우에만 참입니다.

인자 2개

첫 번째 인자가 ‘!’인 경우, 두 번째 인자가 null이면 참입니다. 첫 번째 인자가 단항 조건 연산자 중 하나인 경우(Bash 조건식 참조), 단항 테스트가 참이면 식은 참입니다. 첫 번째 인자가 유효한 단항 연산자가 아니면 식은 거짓입니다.

인자 3개

다음 조건들이 나열된 순서대로 적용됩니다.

  1. 두 번째 인자가 이항 조건 연산자 중 하나인 경우(Bash 조건식 참조), 첫 번째와 세 번째 인자를 피연산자로 사용한 이항 테스트의 결과가 식의 결과가 됩니다. 인자가 3개일 때 ‘-a’와 ‘-o’ 연산자는 이항 연산자로 간주됩니다.
  2. 첫 번째 인자가 ‘!’인 경우, 값은 두 번째와 세 번째 인자를 사용한 2-인자 테스트의 부정(negation)입니다.
  3. 첫 번째 인자가 정확히 ‘(’이고 세 번째 인자가 정확히 ‘)’인 경우, 결과는 두 번째 인자에 대한 1-인자 테스트 결과입니다.
  4. 그렇지 않으면 식은 거짓입니다.
인자 4개

다음 조건들이 나열된 순서대로 적용됩니다.

  1. 첫 번째 인자가 ‘!’인 경우, 결과는 나머지 인자들로 구성된 3-인자 식의 부정입니다.
  2. 첫 번째 인자가 정확히 ‘(’이고 네 번째 인자가 정확히 ‘)’인 경우, 결과는 두 번째와 세 번째 인자를 사용한 2-인자 테스트 결과입니다.
  3. 그렇지 않으면 위에서 나열한 규칙에 따라 우선순위에 맞춰 파싱 및 평가됩니다.
인자 5개 이상

위에서 나열한 규칙에 따라 우선순위에 맞춰 파싱 및 평가됩니다.

쉘이 POSIX 모드이거나 식이 [[ 명령어의 일부인 경우, ‘<’ 및 ‘>’ 연산자는 현재 로케일을 사용하여 정렬합니다. 쉘이 POSIX 모드가 아닐 때 test와 ‘[’ 명령어는 ASCII 순서를 사용하여 사전식으로 정렬합니다.

인자가 4개 이상일 때의 역사적인 연산자 우선순위 파싱은 기본 요소(primaries)처럼 보이는 문자열을 만났을 때 모호함을 초래할 수 있습니다. POSIX 표준은 -a 및 -o 기본 요소와 식을 소괄호로 감싸는 방식을 폐지(deprecated)했습니다. 스크립트에서는 더 이상 이를 사용하지 말아야 합니다. 단일 기본 요소만 사용하도록 테스트 호출을 제한하고, -a 및 -o를 쉘의 && 및 || 목록 연산자로 교체하는 것이 훨씬 더 신뢰할 수 있습니다. 예를 들어, 

test -n string1 && test -n string2

를 사용하십시오. 다음 대신에요: 

test -n string1 -a -n string2
times ¶
times

쉘과 그 자식 프로세스들이 사용한 사용자 시간 및 시스템 시간을 출력합니다. 반환 상태는 0입니다.

trap ¶
trap [-lpP] [action] [sigspec ...]

action은 쉘이 시그널 sigspec 중 하나를 받았을 때 읽어서 실행할 명령어입니다. action이 없거나(그리고 단일 sigspec만 있는 경우) ‘-’와 같은 경우, 지정된 각 sigspec의 처리는 쉘이 시작되었을 때의 값으로 리셋됩니다. 만약 action이 빈 문자열(null string)인 경우, 각 sigspec에 의해 지정된 시그널은 쉘과 쉘이 호출하는 명령어들에 의해 무시됩니다.

인자가 제공되지 않으면, trap은 트랩이 설정된 각 시그널과 연관된 동작들을 현재의 시그널 처리를 복구하기 위해 쉘 입력으로 재사용할 수 있는 형식의 trap 명령어 세트로 출력합니다.

action이 없고 -p가 제공된 경우, trap은 각 sigspec과 연관된 트랩 명령어를 표시하거나, sigspec이 주어지지 않은 경우 모든 트랩된 시그널에 대해 현재 처리를 복구할 수 있는 형식으로 표시합니다. -P 옵션도 유사하게 동작하지만, 각 sigspec 인자와 연관된 동작들만 표시합니다. -P는 최소 하나 이상의 sigspec 인자를 요구합니다. -P 또는 -p 옵션은 서브쉘 환경(예: 명령어 치환)에서 사용될 수 있으며, 시그널 처리를 변경하기 위해 trap이 사용되기 전이라면 부모의 트랩 상태를 표시합니다.

-l 옵션은 시그널 이름과 그에 대응하는 번호 목록을 출력합니다. 각 sigspec은 시그널 이름이거나 시그널 번호입니다. 시그널 이름은 대소문자를 구분하지 않으며 SIG 접두사는 선택 사항입니다. -l이 sigspec 인자 없이 제공되면 유효한 시그널 이름 목록을 출력합니다.

만약 sigspec이 0 또는 EXIT이면, 쉘이 종료될 때 action이 실행됩니다. 만약 sigspec이 DEBUG이면, 모든 단순 명령어, for 명령어, case 명령어, select 명령어, (( 산술 명령어, [[ 조건부 명령어, 산술 for 명령어 이전에, 그리고 쉘 함수 내의 첫 번째 명령어가 실행되기 전에 action이 실행됩니다. extdebug 쉘 옵션이 DEBUG 트랩에 미치는 영향에 대한 상세 정보는 Shopt 빌트인의 설명을 참조하십시오. 만약 sigspec이 RETURN이면, 쉘 함수나 . 또는 source 빌트인으로 실행된 스크립트가 실행을 마칠 때마다 action이 실행됩니다.

만약 sigspec이 ERR이면, 파이프라인(단일 단순 명령어로 구성될 수 있음), 목록, 또는 복합 명령어가 0이 아닌 종료 상태를 반환할 때마다 action이 실행됩니다. 단, 다음 조건들을 따릅니다. ERR 트랩은 실패한 명령어가 until 또는 while 예약어 바로 뒤에 오는 명령어 목록의 일부인 경우, if 또는 elif 예약어 뒤의 테스트 부분인 경우, 마지막 명령어를 제외한 && 또는 || 목록에서 실행된 명령어의 일부인 경우, 파이프라인의 마지막 명령어가 아닌 경우(pipefail 쉘 옵션 상태에 따름), 또는 명령어의 반환 상태가 !를 통해 반전되는 경우에는 실행되지 않습니다. 이러한 조건들은 errexit (-e) 옵션이 따르는 조건들과 동일합니다.

쉘이 대화형이 아닐 때, 비대화형 쉘에 진입할 때 무시되었던 시그널들은 트랩되거나 리셋될 수 없습니다. 대화형 쉘은 진입 시 무시된 시그널에 대해서도 트랩 설정을 허용합니다. 무시되고 있지 않은 트랩된 시그널들은 서브쉘이나 서브쉘 환경이 생성될 때 원래의 값으로 리셋됩니다.

반환 상태는 sigspec이 유효한 시그널을 지정하지 않은 경우를 제외하고 0이며, 그 외의 경우 0이 아닙니다.

true ¶
true

아무것도 하지 않으며, 0 상태를 반환합니다.

umask ¶
umask [-p] [-S] [mode]

쉘 프로세스의 파일 생성 마스크를 mode로 설정합니다. 만약 mode가 숫자로 시작하면 8진수로 해석되고, 그렇지 않으면 chmod 명령어에서 허용되는 것과 유사한 기호 모드 마스크로 해석됩니다. 만약 mode가 생략되면 umask는 현재 마스크 값을 출력합니다. 만약 mode 인자 없이 -S 옵션이 제공되면, umask는 마스크를 기호 형식으로 출력합니다. 기본 출력은 8진수입니다. 만약 -p 옵션이 제공되고 mode가 생략되면, 출력은 입력으로 재사용할 수 있는 형식이 됩니다. 반환 상태는 모드가 성공적으로 변경되었거나 mode 인자가 주어지지 않은 경우 0이며, 그렇지 않으면 0이 아닙니다.

참고로 모드가 8진수로 해석될 때, umask의 각 숫자는 7에서 뺍니다. 따라서 umask 022는 권한 755를 결과로 냅니다.

unset ¶
unset [-fnv] [name]

각 변수 또는 함수 name을 제거합니다. -v 옵션이 주어지면, 각 name은 쉘 변수를 참조하며 해당 변수가 제거됩니다. -f 옵션이 주어지면, name은 쉘 함수를 참조하며 함수 정의가 제거됩니다. -n 옵션이 제공되고 name이 nameref 속성을 가진 변수라면, name이 참조하는 변수 대신 name 자체가 해제됩니다. -n은 -f 옵션이 제공된 경우에는 효과가 없습니다. 옵션이 제공되지 않으면, 각 name은 변수를 참조합니다. 해당 이름의 변수가 없으면 같은 이름의 함수가 있는 경우 이를 해제합니다. 읽기 전용 변수 및 함수는 해제할 수 없습니다. 변수나 함수가 제거되면, 이후의 명령어들에 전달되는 환경(environment)에서도 제거됩니다. 일부 쉘 변수들은 해제할 수 없습니다. 일부 쉘 변수들은 해제될 경우 특별한 동작 특성을 잃게 되며, 이러한 동작은 각 변수의 설명 부분에 언급되어 있습니다. 반환 상태는 name이 읽기 전용이거나 해제할 수 없는 경우를 제외하고 0입니다.
