9.1 Bash 히스토리 기능 ¶

set 빌트인의 -o history 옵션이 활성화되어 있으면(Set 빌트인 참조), 쉘은 이전에 입력된 명령어 목록인 명령어 히스토리(command history)에 대한 접근을 제공합니다. HISTSIZE 쉘 변수의 값은 히스토리 목록에 저장할 명령어의 개수로 사용됩니다: 쉘은 마지막 $HISTSIZE 개의 명령어 텍스트를 저장합니다 (기본값은 500). 쉘은 각 명령어를 파라미터 및 변수 확장 이전, 그러나 히스토리 확장이 수행된 이후에 HISTIGNORE 및 HISTCONTROL 쉘 변수 값에 따라 히스토리 목록에 저장합니다.

쉘이 시작될 때, Bash는 HISTFILE 변수로 지정된 파일(기본값 ~/.bash_history)로부터 히스토리 항목들을 읽어 들여 히스토리 목록을 초기화합니다. 이 파일을 히스토리 파일(history file)이라고 부릅니다. 히스토리 파일은 필요한 경우 HISTFILESIZE 변수 값으로 지정된 개수보다 많지 않도록 축소됩니다. 만약 HISTFILESIZE가 해제되어 있거나, null, 숫자가 아닌 값, 또는 0보다 작은 숫자 값으로 설정되어 있다면 히스토리 파일은 축소되지 않습니다.

히스토리 파일을 읽을 때, 히스토리 주석 문자로 시작하고 바로 뒤에 숫자가 오는 줄은 그 뒤에 오는 히스토리 항목의 타임스탬프(timestamp)로 해석됩니다. 이러한 타임스탬프들은 HISTTIMEFORMAT 변수 값에 따라 선택적으로 표시될 수 있습니다(Bash 변수 참조). 타임스탬프가 존재하면 히스토리 항목들을 구분하는 역할을 하여 여러 줄로 구성된 항목(multi-line entries)이 가능해집니다.

히스토리가 활성화된 쉘이 종료될 때, Bash는 히스토리 목록의 마지막 $HISTSIZE 개의 항목을 $HISTFILE로 명명된 파일에 복사합니다. histappend 쉘 옵션이 설정되어 있다면(Bash 빌트인 명령어 참조), Bash는 항목들을 히스토리 파일 끝에 덧붙이고, 그렇지 않으면 히스토리 파일을 덮어씁니다. HISTFILE이 해제되어 있거나 null인 경우, 또는 히스토리 파일에 쓰기 권한이 없는 경우 히스토리는 저장되지 않습니다. 히스토리를 저장한 후, Bash는 위에서 설명한 대로 히스토리 파일이 $HISTFILESIZE 줄을 넘지 않도록 축소합니다.

만약 HISTTIMEFORMAT 변수가 설정되어 있다면, 쉘은 각 히스토리 항목과 연관된 타임스탬프 정보를 히스토리 주석 문자와 함께 히스토리 파일에 기록하여, 쉘 세션 간에 타임스탬프가 보존되도록 합니다. 히스토리 파일을 읽을 때, 히스토리 주석 문자로 시작하고 바로 뒤에 숫자가 오는 줄은 그 뒤에 오는 히스토리 항목의 타임스탬프로 해석됩니다. 위에서 언급했듯이 HISTTIMEFORMAT을 사용할 때 타임스탬프는 여러 줄 히스토리 항목을 구분하는 기준이 됩니다.

fc 빌트인 명령어는 히스토리 목록의 일부를 나열하거나 편집 후 다시 실행합니다. history 빌트인은 히스토리 목록을 표시하거나 수정하고 히스토리 파일을 조작할 수 있습니다. 명령줄 편집 기능을 사용할 때, 각 편집 모드에서 히스토리 목록에 접근할 수 있는 검색 명령어들을 사용할 수 있습니다(히스토리 조작 명령어 참조).

쉘은 어떤 명령어가 히스토리 목록에 저장될지 제어할 수 있게 해줍니다. HISTCONTROL 및 HISTIGNORE 변수는 입력된 명령어 중 일부만 저장하는 데 사용됩니다. 만약 cmdhist 쉘 옵션이 활성화되어 있으면, 쉘은 여러 줄 명령어의 각 줄을 동일한 히스토리 항목에 저장하려고 시도하며, 구문적 정확성을 유지하기 위해 필요한 곳에 세미콜론을 추가합니다. lithist 쉘 옵션은 세미콜론 대신 줄바꿈을 그대로 포함하여 명령어를 저장함으로써 cmdhist의 동작을 수정합니다. 이러한 옵션들을 설정하기 위해 shopt 빌트인이 사용됩니다. shopt에 대한 설명은 Shopt 빌트인을 참조하십시오.
