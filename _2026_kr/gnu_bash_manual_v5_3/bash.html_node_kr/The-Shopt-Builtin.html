4.3.2 Shopt 빌트인 ¶

이 빌트인은 추가적인 쉘 동작 옵션들을 변경할 수 있게 해줍니다.

shopt ¶
shopt [-pqsu] [-o] [optname ...]

선택적인 쉘 동작을 제어하는 설정값들을 토글합니다. 설정할 수 있는 옵션들은 아래에 나열된 것들이거나, -o 옵션이 사용된 경우 set 빌트인 명령어의 -o 옵션으로 사용 가능한 것들입니다(Set 빌트인 참조).

옵션이 없거나 -p 옵션만 사용된 경우, 설정 가능한 모든 옵션 목록과 각 옵션의 설정 여부를 표시합니다. optname이 제공되면 해당 옵션들로 출력이 제한됩니다. -p 옵션은 출력물을 입력으로 재사용할 수 있는 형식으로 표시합니다.

다른 옵션들은 다음과 같은 의미를 갖습니다:

-s

각 optname을 활성화(set)합니다.

-u

각 optname을 비활성화(unset)합니다.

-q

일반적인 출력을 억제합니다; 반환 상태를 통해 optname의 설정 여부를 알 수 있습니다. -q와 함께 여러 optname 인자가 제공된 경우, 모든 optname이 활성화되어 있으면 반환 상태는 0이고, 그렇지 않으면 0이 아닙니다.

-o

optname의 값을 set 빌트인의 -o 옵션에 정의된 것들로 제한합니다(Set 빌트인 참조).

optname 없이 -s 또는 -u가 사용되면, shopt은 각각 활성화된 옵션들 또는 비활성화된 옵션들만 보여줍니다.

별도로 언급하지 않는 한, shopt 옵션들은 기본적으로 비활성화(off)되어 있습니다.

옵션 목록 출력 시의 반환 상태는 모든 optname이 활성화되어 있으면 0이고, 그렇지 않으면 0이 아닙니다. 옵션을 설정하거나 해제할 때의 반환 상태는 optname이 유효한 쉘 옵션이 아닌 경우를 제외하고 0입니다.

shopt 옵션 목록은 다음과 같습니다:

array_expand_once

설정된 경우, 쉘은 산술식 평가 중, 변수 할당을 수행할 수 있는 빌트인 실행 중, 그리고 배열 역참조(dereferencing)를 수행하는 빌트인 실행 중에 연관 배열 및 인덱스 배열의 서브스크립트가 여러 번 평가되는 것을 억제합니다.

assoc_expand_once

폐지됨; array_expand_once의 동의어입니다.

autocd

설정된 경우, 디렉토리 이름인 명령어 이름은 마치 cd 명령어의 인자인 것처럼 실행됩니다. 이 옵션은 대화형 쉘에서만 사용됩니다.

bash_source_fullpath

설정된 경우, BASH_SOURCE 배열 변수에 추가되는 파일 이름들이 절대 경로명으로 변환됩니다(Bash 변수 참조).

cdable_vars

설정된 경우, cd 빌트인 명령어의 인자가 디렉토리가 아니라면, 해당 인자를 이동할 디렉토리를 값으로 가진 변수의 이름으로 간주합니다.

cdspell

설정된 경우, cd 명령어는 디렉토리 경로 구성 요소의 사소한 철자 오류를 수정하려고 시도합니다. 사소한 오류에는 문자의 순서 바뀜, 문자 누락, 문자 하나 더 들어감 등이 포함됩니다. cd가 디렉토리 이름을 수정하면 수정된 파일 이름을 출력하고 명령어를 진행합니다. 이 옵션은 대화형 쉘에서만 사용됩니다.

checkhash

설정된 경우, Bash는 해시 테이블에서 발견된 명령어를 실행하기 전에 해당 명령어가 실제로 존재하는지 확인합니다. 해시된 명령어가 더 이상 존재하지 않으면 Bash는 일반적인 경로 검색을 수행합니다.

checkjobs

설정된 경우, Bash는 대화형 쉘을 종료하기 전에 중단되었거나 실행 중인 모든 작업의 상태를 나열합니다. 실행 중인 작업이 있다면, Bash는 중간에 다른 명령어 없이 두 번째 종료 시도가 있을 때까지 종료를 미룹니다(작업 제어 참조). 중단된 작업이 있다면 쉘은 항상 종료를 연기합니다.

checkwinsize

설정된 경우, Bash는 각 외부(빌트인 제외) 명령어 실행 후 윈도우 크기를 확인하고, 필요한 경우 LINES와 COLUMNS의 값을 업데이트합니다. 이때 표준 에러가 터미널인 경우 표준 에러와 연관된 파일 서술자를 사용합니다. 이 옵션은 기본적으로 활성화되어 있습니다.

cmdhist

설정된 경우, Bash는 여러 줄로 구성된 명령어의 모든 줄을 동일한 히스토리 항목에 저장하려고 시도합니다. 이를 통해 여러 줄 명령어를 쉽게 다시 편집할 수 있습니다. 이 옵션은 기본적으로 활성화되어 있지만, 명령어 히스토리가 활성화되어 있어야 효과가 있습니다(Bash 히스토리 기능 참조).

compat31
compat32
compat40
compat41
compat42
compat43
compat44

이 옵션들은 쉘의 호환성 모드의 다양한 측면을 제어합니다(쉘 호환 모드 참조).

complete_fullquote

설정된 경우, Bash는 자동 완성을 수행할 때 파일 이름과 디렉토리 이름 내의 모든 쉘 메타 문자들을 인용 처리합니다. 설정되어 있지 않으면, 자동 완성될 단어의 쉘 변수 참조 내에 달러 기호($)와 같은 메타 문자가 나타날 때 이를 인용 대상 문자 집합에서 제거합니다. 이는 디렉토리로 확장되는 변수 이름 내의 달러 기호가 인용되지 않음을 의미합니다; 하지만 파일 이름에 나타나는 달러 기호 또한 인용되지 않게 됩니다. 이 옵션은 Bash가 완료된 파일 이름을 인용하기 위해 백슬래시를 사용할 때만 작동합니다. 이 변수는 기본적으로 설정되어 있으며, 이는 4.2 버전까지의 기본 Bash 동작입니다.

direxpand

설정된 경우, Bash는 파일 이름 완성을 수행할 때 디렉토리 이름을 단어 확장의 결과로 대체합니다. 이는 Readline 편집 버퍼의 내용을 변경합니다. 설정되어 있지 않으면 Bash는 사용자가 입력한 내용을 그대로 보존하려고 시도합니다.

dirspell

설정된 경우, Bash는 단어 완성 중에 처음에 제공된 디렉토리 이름이 존재하지 않으면 디렉토리 이름에 대해 철자 수정을 시도합니다.

dotglob

설정된 경우, Bash는 파일 이름 확장 결과에 ‘.’으로 시작하는 파일 이름들을 포함시킵니다. 파일 이름 .과 ..은 dotglob이 설정되어 있더라도 항상 명시적으로 매치되어야 합니다.

execfail

설정된 경우, 비대화형 쉘은 exec 빌트인의 인자로 지정된 파일을 실행할 수 없더라도 종료되지 않습니다. 대화형 쉘은 exec가 실패하더라도 종료되지 않습니다.

expand_aliases

설정된 경우, 아래 별칭(Aliases, 별칭) 섹션에 설명된 대로 별칭이 확장됩니다. 대화형 쉘에서는 이 옵션이 기본적으로 활성화되어 있습니다.

extdebug

쉘 호출 시 또는 쉘 시작 파일에서 설정된 경우, --debugger 옵션과 동일하게 쉘이 시작되기 전에 디버거 프로파일을 실행하도록 준비합니다. 호출 후에 설정된 경우, 디버거 사용을 위한 동작들이 활성화됩니다:

  1. declare 빌트인의 -F 옵션(Bash 빌트인 명령어 참조)이 인자로 제공된 각 함수 이름에 대응하는 소스 파일명과 라인 번호를 표시합니다.
  2. DEBUG 트랩에 의해 실행된 명령어가 0이 아닌 값을 반환하면, 다음 명령어는 건너뛰고 실행되지 않습니다.
  3. DEBUG 트랩에 의해 실행된 명령어가 2를 반환하고, 쉘이 서브루틴(쉘 함수 또는 . 이나 source 빌트인으로 실행된 쉘 스크립트) 내에서 실행 중이라면, 쉘은 return 호출을 시뮬레이션합니다.
  4. BASH_ARGC와 BASH_ARGV가 해당 설명에 따라 업데이트됩니다(Bash 변수 참조).
  5. 함수 추적(tracing)이 활성화됩니다: 명령어 치환, 쉘 함수, 그리고 ( command )로 호출된 서브쉘이 DEBUG 및 RETURN 트랩을 상속받습니다.
  6. 에러 추적이 활성화됩니다: 명령어 치환, 쉘 함수, 그리고 ( command )로 호출된 서브쉘이 ERR 트랩을 상속받습니다.
extglob

설정된 경우, 위에서 설명한 확장 패턴 매칭 기능들이 활성화됩니다(패턴 매칭 참조).

extquote

설정된 경우, 큰따옴표로 감싸진 ${parameter} 확장 내에서 $'string' 및 $"string" 인용이 수행됩니다. 이 옵션은 기본적으로 활성화되어 있습니다.

failglob

설정된 경우, 파일 이름 확장 중에 파일 이름과 매치되지 않는 패턴은 확장 에러를 발생시킵니다.

force_fignore

설정된 경우, FIGNORE 쉘 변수로 지정된 접미사들은 단어 완성을 수행할 때 해당 단어들이 유일하게 가능한 완성 후보이더라도 무시되도록 합니다. FIGNORE에 대한 설명은 Bash 변수를 참조하십시오. 이 옵션은 기본적으로 활성화되어 있습니다.

globasciiranges

설정된 경우, 패턴 매칭 대괄호 표현식(패턴 매칭 참조)에서 사용되는 범위 표현식은 비교 시 전통적인 C 로케일에 있는 것처럼 동작합니다. 즉, 패턴 매칭이 현재 로케일의 정렬 순서를 고려하지 않으므로, ‘b’가 ‘A’와 ‘B’ 사이에 정렬되지 않으며, 대문자와 소문자 ASCII 문자들이 함께 정렬됩니다.

globskipdots

설정된 경우, 패턴이 ‘.’으로 시작하더라도 파일 이름 확장이 파일 이름 . 및 ..과 절대 매치되지 않습니다. 이 옵션은 기본적으로 활성화되어 있습니다.

globstar

설정된 경우, 파일 이름 확장 컨텍스트에서 사용된 ‘**’ 패턴은 모든 파일과 0개 이상의 디렉토리 및 하위 디렉토리에 매치됩니다. 패턴 뒤에 ‘/’가 붙으면 오직 디렉토리와 하위 디렉토리에만 매치됩니다.

gnu_errfmt

설정된 경우, 쉘 에러 메시지가 표준 GNU 에러 메시지 형식으로 작성됩니다.

histappend

설정된 경우, 쉘이 종료될 때 히스토리 목록이 HISTFILE 변수 값으로 지정된 파일에 덮어쓰지 않고 덧붙여집니다.

histreedit

설정되어 있고 Readline이 사용 중인 경우, 사용자가 실패한 히스토리 치환을 다시 편집할 기회를 줍니다.

histverify

설정되어 있고 Readline이 사용 중인 경우, 히스토리 치환 결과가 즉시 쉘 파서로 전달되지 않습니다. 대신 결과 줄이 Readline 편집 버퍼에 로드되어 추가적인 수정을 할 수 있게 합니다.

hostcomplete

설정되어 있고 Readline이 사용 중인 경우, Bash는 ‘@’를 포함하는 단어가 완성될 때 호스트 이름 완성을 시도합니다(Readline 자동 완성 기능 참조). 이 옵션은 기본적으로 활성화되어 있습니다.

huponexit

설정된 경우, 대화형 로그인 쉘이 종료될 때 Bash는 모든 작업(jobs)에게 SIGHUP을 보냅니다(시그널 참조).

inherit_errexit

설정된 경우, 명령어 치환은 서브쉘 환경에서 errexit 옵션을 해제하는 대신 그 값을 상속받습니다. 이 옵션은 POSIX 모드가 활성화될 때 함께 활성화됩니다.

interactive_comments

대화형 쉘에서, ‘#’으로 시작하는 단어는 비대화형 쉘에서와 마찬가지로 해당 단어와 그 줄의 나머지 모든 문자들을 무시하게 만듭니다. 이 옵션은 기본적으로 활성화되어 있습니다.

lastpipe

설정되어 있고 작업 제어가 활성 상태가 아닐 때, 쉘은 백그라운드에서 실행되지 않는 파이프라인의 마지막 명령어를 현재 쉘 환경에서 실행합니다.

lithist

활성화되어 있고 cmdhist 옵션도 활성화된 경우, 가능한 경우 세미콜론 구분자 대신 임베디드 줄바꿈을 사용하여 여러 줄 명령어를 히스토리에 저장합니다.

localvar_inherit

설정된 경우, 지역 변수는 새로운 값이 할당되기 전에 이전 범위(scope)에 이미 존재하는 동일한 이름의 변수로부터 값과 속성을 상속받습니다. nameref 속성은 상속되지 않습니다.

localvar_unset

설정된 경우, 이전 함수 범위의 지역 변수에 대해 unset을 호출하면 해당 함수가 반환될 때까지 이후의 조회에서 해당 변수들이 해제된(unset) 상태로 보이도록 표시합니다. 이는 현재 함수 범위에서 지역 변수를 해제하는 동작과 동일합니다.

login_shell

쉘이 로그인 쉘로 시작된 경우 이 옵션을 설정합니다(Bash 호출하기 참조). 이 값은 변경할 수 없습니다.

mailwarn

설정되어 있고 Bash가 메일을 확인하는 파일이 마지막 확인 이후 액세스된 경우, Bash는 "The mail in mailfile has been read"라는 메시지를 표시합니다.

no_empty_cmd_completion

설정되어 있고 Readline이 사용 중인 경우, 빈 줄에서 완성을 시도할 때 Bash는 가능한 완성 후보를 찾기 위해 PATH를 검색하지 않습니다.

nocaseglob

설정된 경우, Bash는 파일 이름 확장을 수행할 때 대소문자를 구분하지 않고 파일 이름을 매치합니다.

nocasematch

설정된 경우, Bash는 case 또는 [[ 조건부 명령어를 실행할 때(조건부 구문 참조), 패턴 치환 단어 확장을 수행할 때, 또는 프로그래밍 가능한 자동 완성의 일부로 가능한 완성 후보들을 필터링할 때 대소문자를 구분하지 않고 패턴을 매치합니다.

noexpand_translation

설정된 경우, Bash는 $"…" 인용의 번역 결과를 큰따옴표 대신 작은따옴표로 감쌉니다. 문자열이 번역되지 않은 경우 효과가 없습니다.

nullglob

설정된 경우, 그 어떤 파일과도 매치되지 않는 파일 이름 확장 패턴은(파일 이름 확장 참조) 자기 자신으로 확장되는 대신 아무것도 없는 상태로 확장되어 제거됩니다.

patsub_replacement

설정된 경우, Bash는 위에서 설명한 대로 패턴 치환의 치환 문자열 내에 나타나는 ‘&’를 패턴에 의해 매치된 텍스트로 확장합니다(쉘 파라미터 확장 참조). 이 옵션은 기본적으로 활성화되어 있습니다.

progcomp

설정된 경우, 프로그래밍 가능한 자동 완성 기능들을 활성화합니다(프로그래밍 가능한 자동 완성 참조). 이 옵션은 기본적으로 활성화되어 있습니다.

progcomp_alias

설정되어 있고 프로그래밍 가능한 자동 완성이 활성화된 경우, Bash는 정의된 완성이 없는 명령어 이름을 가능한 별칭으로 취급하고 별칭 확장을 시도합니다. 별칭이 있다면, Bash는 확장된 별칭으로부터 나온 명령어 단어를 사용하여 프로그래밍 가능한 자동 완성을 시도합니다.

promptvars

설정된 경우, 프롬프트 문자열은 아래 설명된 대로 확장된 후에 파라미터 확장, 명령어 치환, 산술 확장 및 따옴표 제거 과정을 거칩니다(프롬프트 제어하기 참조). 이 옵션은 기본적으로 활성화되어 있습니다.

restricted_shell

쉘이 제한된 모드(restricted mode)로 시작된 경우 이 옵션을 설정합니다(제한된 쉘 참조). 이 값은 변경할 수 없습니다. 이 값은 시작 파일이 실행될 때 리셋되지 않으므로, 시작 파일이 쉘의 제한 여부를 확인할 수 있게 해줍니다.

shift_verbose

설정된 경우, shift 빌트인은 시프트 횟수가 위치 파라미터의 개수를 초과할 때 에러 메시지를 출력합니다.

sourcepath

설정된 경우, . (source) 빌트인은 -p 옵션이 제공되지 않았을 때 인자로 제공된 파일을 포함하는 디렉토리를 찾기 위해 PATH 값을 사용합니다. 이 옵션은 기본적으로 활성화되어 있습니다.

varredir_close

설정된 경우, 쉘은 {varname} 리다이렉션 문법(리다이렉션 참조)을 사용하여 할당된 파일 서술자들을 명령어가 완료될 때 열어두지 않고 자동으로 닫습니다.

xpg_echo

설정된 경우, echo 빌트인은 기본적으로 백슬래시 이스케이프 시퀀스를 확장합니다. 만약 posix 쉘 옵션(Set 빌트인 참조)도 함께 활성화되어 있다면, echo는 그 어떤 옵션도 해석하지 않습니다.
