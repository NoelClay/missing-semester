6.7 배열 ¶

Bash는 1차원 인덱스(indexed) 배열과 연관(associative) 배열 변수를 제공합니다. 모든 변수는 인덱스 배열로 사용될 수 있으며, declare 빌트인을 통해 배열임을 명시적으로 선언할 수 있습니다. 배열의 크기에는 최대 제한이 없으며, 멤버들이 연속적으로 인덱싱되거나 할당되어야 할 필요도 없습니다. 인덱스 배열은 정수로 확장되어야 하는 산술식(쉘 산술 연산 참조)을 사용하여 참조하며 0부터 시작합니다. 연관 배열은 임의의 문자열을 사용합니다. 별도로 언급하지 않는 한, 인덱스 배열의 인덱스는 음수가 아닌 정수여야 합니다.

쉘은 인덱스 배열의 서브스크립트(subscript)에 대해 파라미터 및 변수 확장, 산술 확장, 명령어 치환, 그리고 따옴표 제거를 수행합니다. 이 과정에서 잠재적으로 빈 문자열이 결과로 나올 수 있는데, 서브스크립트 인덱싱은 이를 0으로 평가되는 식으로 취급합니다.

쉘은 연관 배열의 서브스크립트에 대해 물결표 확장, 파라미터 및 변수 확장, 산술 확장, 명령어 치환, 그리고 따옴표 제거를 수행합니다. 빈 문자열은 연관 배열의 키로 사용할 수 없습니다.

Bash는 다음 문법을 사용하여 변수에 값을 할당할 때 자동으로 인덱스 배열을 생성합니다: 

name[subscript]=value

subscript는 0보다 크거나 같은 숫자로 평가되어야 하는 산술식으로 취급됩니다. 인덱스 배열을 명시적으로 선언하려면 다음을 사용하십시오: 

declare -a name

(Bash 빌트인 명령어 참조). 

declare -a name[subscript]

문법도 허용되지만, subscript는 무시됩니다.

연관 배열은 다음을 사용하여 생성합니다: 

declare -A name

declare 및 readonly 빌트인을 사용하여 배열 변수에 속성을 지정할 수 있습니다. 각 속성은 배열의 모든 멤버에 적용됩니다.

배열은 다음과 같은 형식의 복합 할당(compound assignments)을 사용하여 할당됩니다: 

name=(value1 value2 ... )

여기서 각 value는 [subscript]=string 형식을 취할 수 있습니다. 인덱스 배열 할당에서는 string만 있어도 충분합니다.

목록의 각 value는 위에서 설명한 쉘 확장(쉘 확장 참조)을 거칩니다. 하지만 대괄호와 서브스크립트를 포함하여 유효한 변수 할당문 형태인 value들은 개별 변수 할당 시와 마찬가지로 중괄호 확장과 단어 분할을 거치지 않습니다.

인덱스 배열에 할당할 때 선택적인 서브스크립트가 제공되면 해당 인덱스에 할당됩니다. 그렇지 않으면 할당되는 요소의 인덱스는 해당 할당문에서 마지막으로 할당된 인덱스에 1을 더한 값이 됩니다. 인덱싱은 0부터 시작합니다.

연관 배열에 할당할 때, 복합 할당 내의 단어들은 서브스크립트가 필수인 할당문 형식이거나, 키와 값이 번갈아 나타나는 시퀀스로 해석되는 단어 목록일 수 있습니다: name=(key1 value1 key2 value2 … ). 이들은 다음과 동일하게 처리됩니다: name=( [key1]=value1 [key2]=value2 … ). 목록의 첫 번째 단어가 나머지 단어들이 어떻게 해석될지를 결정합니다; 한 목록 내의 모든 할당은 동일한 유형이어야 합니다. 키/값 쌍을 사용할 때 키는 누락되거나 비어 있을 수 없습니다; 마지막 값이 누락된 경우 빈 문자열로 처리됩니다.

이 문법은 declare 빌트인에서도 허용됩니다. 개별 배열 요소는 위에서 소개한 name[subscript]=value 문법을 사용하여 할당될 수 있습니다.

인덱스 배열에 할당할 때 name의 서브스크립트로 음수가 사용되면, 그 숫자는 배열의 최대 인덱스보다 1 큰 값을 기준으로 해석됩니다. 따라서 음수 인덱스는 배열의 끝에서부터 역산하며, 인덱스 -1은 마지막 요소를 참조합니다.

‘+=’ 연산자는 복합 할당 문법을 사용하여 할당할 때 배열 변수 뒤에 덧붙입니다; 위 쉘 파라미터 섹션을 참조하십시오.

배열 요소는 ${name[subscript]} 형식을 사용하여 참조합니다. 쉘의 파일 이름 확장 연산자와의 충돌을 피하기 위해 중괄호가 반드시 필요합니다. 만약 subscript가 ‘@’ 또는 ‘*’이면, 빌트인이나 단어 확장의 설명에서 별도로 언급하지 않는 한 해당 단어는 배열 name의 모든 멤버로 확장됩니다. 이 두 서브스크립트의 차이는 단어가 큰따옴표 내에 있을 때만 나타납니다. 큰따옴표 내에서 ${name[*]}는 각 배열 멤버의 값이 IFS 변수의 첫 번째 문자로 구분된 단일 단어로 확장되는 반면, ${name[@]}는 name의 각 요소를 별개의 단어로 확장합니다. 배열 멤버가 없는 경우 ${name[@]}는 아무것도 없는 상태로 확장됩니다. 큰따옴표 확장이 어떤 단어 내부에서 일어나는 경우, 첫 번째 파라미터의 확장 결과는 원래 단어의 앞부분 확장 결과와 결합되고, 마지막 파라미터의 확장 결과는 원래 단어의 뒷부분 확장 결과와 결합됩니다. 이는 특수 파라미터 ‘@’ 및 ‘*’의 확장 방식과 유사합니다.

${#name[subscript]}는 ${name[subscript]}의 길이로 확장됩니다. 만약 subscript가 ‘@’ 또는 ‘*’이면, 확장은 배열 내 요소의 개수가 됩니다.

인덱스 배열의 요소를 참조하기 위해 사용된 subscript가 0보다 작은 숫자로 평가되면, 이는 배열의 최대 인덱스보다 1 큰 값을 기준으로 해석됩니다. 따라서 음수 인덱스는 배열의 끝에서부터 역산하며, 인덱스 -1은 마지막 요소를 참조합니다.

서브스크립트 없이 배열 변수를 참조하는 것은 0번 서브스크립트로 참조하는 것과 동일합니다. 유효한 서브스크립트를 사용한 변수 참조는 모두 유효합니다; Bash는 필요한 경우 배열을 생성합니다.

서브스크립트에 값이 할당되어 있다면 해당 배열 변수는 설정된(set) 것으로 간주됩니다. 빈 문자열(null string)도 유효한 값입니다.

배열의 값뿐만 아니라 키(인덱스)들도 얻을 수 있습니다. ${!name[@]}와 ${!name[*]}는 배열 변수 name에 할당된 인덱스들로 확장됩니다. 큰따옴표 내에서의 처리는 큰따옴표 내 특수 파라미터 ‘@’ 및 ‘*’의 확장 방식과 유사합니다.

unset 빌트인은 배열을 파괴하는 데 사용됩니다. unset name[subscript]는 인덱스 subscript에 있는 배열 요소를 해제합니다. 인덱스 배열에 대한 음수 서브스크립트는 위에서 설명한 대로 해석됩니다. 배열 변수의 마지막 요소를 해제한다고 해서 변수 자체가 해제되지는 않습니다. name이 배열일 때 unset name은 배열 전체를 제거합니다. unset name[subscript]는 subscript가 ‘*’ 또는 ‘@’일 때 배열 유형에 따라 다르게 동작합니다. name이 연관 배열인 경우, 키가 ‘*’ 또는 ‘@’인 요소를 제거합니다. name이 인덱스 배열인 경우, unset은 모든 요소들을 제거하지만 배열 자체를 제거하지는 않습니다.

서브스크립트가 붙은 변수 이름을 명령어의 인자로 사용할 때(예: unset과 함께 사용), 위에서 설명한 단어 확장 문법을 사용하지 않는다면(예: unset a[4]), 해당 인자는 쉘의 파일 이름 확장(wildcard)의 대상이 됩니다. 경로명 확장을 원하지 않는다면 인자를 인용 처리하십시오(예: unset 'a[4]').

declare, local, 그리고 readonly 빌트인은 각각 인덱스 배열을 지정하기 위한 -a 옵션과 연관 배열을 지정하기 위한 -A 옵션을 허용합니다. 두 옵션이 모두 제공되면 -A가 우선합니다. read 빌트인은 표준 입력에서 읽은 단어 목록을 배열에 할당하기 위한 -a 옵션을 허용하며, 표준 입력으로부터 개별 배열 요소로 값을 읽어들일 수 있습니다. set과 declare 빌트인은 배열 값들을 입력으로 재사용할 수 있는 방식으로 표시합니다. 다른 빌트인들도 배열 이름 인자를 허용합니다(예: mapfile); 자세한 내용은 개별 빌트인 설명을 참조하십시오. 쉘은 다수의 빌트인 배열 변수들을 제공합니다.
