7.2 작업 제어 빌트인 ¶

bg ¶
bg [jobspec ...]

중단된 각 작업 jobspec을 마치 ‘&’와 함께 시작된 것처럼 백그라운드에서 재개합니다. jobspec이 제공되지 않으면 쉘의 현재 작업(current job) 개념을 사용합니다. bg는 작업 제어가 활성화되지 않은 상태에서 실행되거나, 활성화된 상태에서 실행되었더라도 jobspec을 찾을 수 없거나 작업 제어 없이 시작된 작업을 지정하는 경우를 제외하고 0을 반환합니다.

fg ¶
fg [jobspec]

작업 jobspec을 포그라운드에서 재개하고 이를 현재 작업으로 만듭니다. jobspec이 제공되지 않으면 fg는 현재 작업을 재개합니다. 반환 상태는 포그라운드로 배치된 명령어의 종료 상태이거나, 작업 제어가 비활성화된 상태에서 실행된 경우, 또는 활성화된 상태에서 실행되었더라도 jobspec이 유효한 작업을 지정하지 않거나 작업 제어 없이 시작된 작업을 지정하는 경우 0이 아닌 값이 됩니다.

jobs ¶
jobs [-lnprs] [jobspec]
jobs -x command [arguments]

첫 번째 형식은 활성 상태인 작업들을 나열합니다. 옵션들은 다음과 같은 의미를 갖습니다:

-l

일반적인 정보와 더불어 프로세스 ID들을 나열합니다.

-n

사용자가 마지막으로 상태를 통지받은 이후에 상태가 변경된 작업들에 대한 정보만 표시합니다.

-p

작업의 프로세스 그룹 리더의 프로세스 ID만 나열합니다.

-r

실행 중인(running) 작업들만 표시합니다.

-s

중단된(stopped) 작업들만 표시합니다.

jobspec이 제공되면 jobs는 해당 작업에 대한 정보로 출력을 제한합니다. jobspec이 제공되지 않으면 모든 작업의 상태를 나열합니다. 반환 상태는 잘못된 옵션을 만나거나 유효하지 않은 jobspec이 제공되지 않는 한 0입니다.

-x 옵션이 제공되면, jobs는 command나 arguments에서 발견되는 모든 jobspec을 대응하는 프로세스 그룹 ID로 교체하고, arguments를 전달하여 command를 실행한 뒤 그 종료 상태를 반환합니다.

kill ¶
kill [-s sigspec] [-n signum] [-sigspec] id [...]
kill -l|-L [exit_status]

sigspec 또는 signum에 의해 지정된 시그널을 각 id로 명명된 프로세스들에게 보냅니다. 각 id는 작업 사양 jobspec 또는 프로세스 ID pid일 수 있습니다. sigspec은 SIGINT와 같은 대소문자 구분 없는 시그널 이름(‘SIG’ 접두사는 선택 사항)이거나 시그널 번호입니다. signum은 시그널 번호입니다. 만약 sigspec과 signum이 주어지지 않으면 kill은 SIGTERM을 보냅니다.

-l 옵션은 시그널 이름들을 나열합니다. -l과 함께 인자들이 제공되면, 해당 인자들에 대응하는 시그널 이름들을 나열하며 반환 상태는 0입니다. exit_status는 시그널 번호나 시그널에 의해 종료된 프로세스의 종료 상태를 지정하는 숫자입니다; 이 인자가 주어지면 kill은 해당 프로세스를 종료시킨 시그널의 이름을 출력합니다. kill은 프로세스 종료 상태가 128보다 크다고 가정합니다; 그보다 작은 값은 시그널 번호로 간주합니다. -L 옵션은 -l과 동일합니다.

반환 상태는 최소 하나의 시그널이라도 성공적으로 전송된 경우 0이며, 에러가 발생하거나 잘못된 옵션을 만난 경우 0이 아닙니다.

wait ¶
wait [-fn] [-p varname] [id ...]

각 id로 지정된 자식 프로세스가 종료될 때까지 기다리고 마지막 id의 종료 상태를 반환합니다. 각 id는 프로세스 ID pid 또는 작업 사양 jobspec일 수 있습니다; 작업 사양이 제공되면 wait은 해당 작업 내의 모든 프로세스들이 종료될 때까지 기다립니다.

옵션이나 id가 제공되지 않으면, wait은 현재 실행 중인 모든 백그라운드 작업과 (프로세스 ID가 $!와 동일한 경우) 마지막으로 실행된 프로세스 치환이 종료될 때까지 기다리며, 반환 상태는 0입니다.

-n 옵션이 제공되면, wait은 제공된 id들 중 하나가 종료될 때까지 기다리거나, id가 제공되지 않은 경우 임의의 작업이나 프로세스 치환이 완료될 때까지 기다린 후 그 종료 상태를 반환합니다. 만약 제공된 id들 중 쉘의 자식 프로세스가 없거나, 인자가 주어지지 않았는데 쉘에 아직 기다려야 할 자식 프로세스가 없다면 종료 상태는 127이 됩니다.

-p 옵션이 제공되면, wait은 종료 상태가 반환된 작업의 프로세스 또는 작업 식별자를 옵션 인자로 지정된 변수 varname에 할당합니다. 해당 변수는 읽기 전용이 아니어야 하며, 할당 전에 먼저 해제(unset)됩니다. 이 옵션은 -n 옵션과 함께 사용할 때만 유용합니다.

작업 제어가 활성화되었을 때 -f 옵션을 제공하면, wait이 각 id의 상태가 변경될 때 반환되는 대신 완전히 종료될 때까지 기다리도록 강제합니다.

그 어떤 id도 쉘의 활성 자식 프로세스를 지정하지 않는다면 반환 상태는 127입니다. wait이 시그널에 의해 중단된 경우, varname은 해제된 상태로 남고 반환 상태는 위에서 설명한 대로 128보다 크게 됩니다(시그널 참조). 그렇지 않으면 반환 상태는 마지막 id의 종료 상태입니다.

disown ¶
disown [-ar] [-h] [id ...]

옵션 없이 사용하면, 활성 작업 테이블에서 각 id를 제거합니다. 각 id는 작업 사양 jobspec 또는 프로세스 ID pid일 수 있습니다; id가 pid인 경우, disown은 해당 pid를 포함하는 작업을 jobspec으로 사용합니다.

-h 옵션이 제공되면, disown은 작업 테이블에서 각 id에 해당하는 작업을 제거하지 않고, 대신 쉘이 SIGHUP을 받았을 때 해당 작업에게 SIGHUP을 보내지 않도록 표시만 합니다.

id가 제공되지 않은 경우, -a 옵션은 모든 작업을 제거하거나 표시함을 의미합니다; id 인자 없이 -r 옵션이 사용되면 실행 중인 작업들만 제거하거나 표시합니다. id가 제공되지 않고 -a나 -r 옵션도 제공되지 않았다면, disown은 현재 작업을 제거하거나 표시합니다.

반환 값은 id가 유효한 작업을 지정하지 않은 경우를 제외하고 0입니다.

suspend ¶
suspend [-f]

SIGCONT 시그널을 받을 때까지 이 쉘의 실행을 중단합니다. 로그인 쉘이나 작업 제어가 활성화되지 않은 쉘은 중단될 수 없습니다; -f 옵션은 이를 무시하고 중단을 강제합니다. 반환 상태는 쉘이 로그인 쉘이 아니거나, 작업 제어가 비활성화된 상태에서 -f가 제공되지 않은 경우를 제외하고 0입니다.

작업 제어가 활성화되어 있지 않을 때, kill 및 wait 빌트인은 jobspec 인자를 받지 않습니다. 반드시 프로세스 ID들을 제공해야 합니다.
