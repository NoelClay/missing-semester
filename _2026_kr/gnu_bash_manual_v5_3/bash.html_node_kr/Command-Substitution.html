3.5.4 명령어 치환 ¶

명령어 치환(Command substitution)은 명령어의 실행 결과물이 명령어 자체를 대체할 수 있게 해줍니다. 표준적인 명령어 치환 형식은 명령어를 다음과 같이 감싸는 것입니다: 

$(command)

또는 (권장되지 않는 이전 방식): 

`command`.

Bash는 서브쉘 환경에서 command를 실행하고, 명령어 치환 부분을 해당 명령어의 표준 출력 내용으로 교체하며, 이때 결과물의 마지막에 있는 줄바꿈 문자들은 삭제됩니다. 내부의 줄바꿈 문자는 삭제되지 않지만, 단어 분할 과정에서 제거될 수 있습니다. 명령어 치환 $(cat file)은 이와 동일하지만 더 빠른 $(< file)로 대체할 수 있습니다.

백틱(` `)을 사용하는 예전 방식의 치환에서는, 백슬래시 뒤에 ‘$’, ‘`’, 또는 ‘\’가 오지 않는 한 백슬래시의 리터럴 의미가 유지됩니다. 백슬래시가 앞에 붙지 않은 첫 번째 백틱이 명령어 치환을 종료합니다. $(command) 형식을 사용할 때는 소괄호 사이의 모든 문자열이 명령어를 구성하며, 특별하게 취급되는 문자는 없습니다.

또 다른 명령어 치환 형식도 존재합니다: 

${c command; }

이는 현재 실행 환경에서 command를 실행하고 그 출력을 캡처하며, 역시 마지막 줄바꿈들은 제거됩니다.

여는 중괄호 뒤의 문자 c는 반드시 공백, 탭, 줄바꿈, 또는 ‘|’여야 하며, 닫는 중괄호는 예약어가 나타날 수 있는 위치(즉, 세미콜론과 같은 명령어 종료자 뒤)에 있어야 합니다. Bash는 예약어가 보통 요구하는 쉘 메타 문자가 뒤따르지 않더라도 닫는 중괄호가 단어의 나머지 부분과 결합되는 것을 허용합니다.

command에 의한 그 어떤 부작용(side effect)도 현재 실행 환경에 즉시 적용되며 명령어가 완료된 후에도 유지됩니다 (예: exit 빌트인은 쉘을 종료시킵니다).

이러한 유형의 명령어 치환은 겉보기에는 이름 없는 쉘 함수를 실행하는 것과 비슷합니다: 쉘 함수 실행 시처럼 지역 변수가 생성되며, return 빌트인은 command의 완료를 강제합니다. 하지만 위치 파라미터를 포함한 나머지 실행 환경은 호출자와 공유됩니다.

만약 여는 중괄호 뒤의 첫 번째 문자가 ‘|’인 경우, 해당 구조는 command가 실행된 후의 REPLY 쉘 변수 값으로 확장되며, 이때 마지막 줄바꿈은 제거되지 않습니다. 또한 command의 표준 출력은 호출한 쉘에서와 동일하게 유지됩니다. Bash는 command 실행 시 REPLY를 초기값이 해제된 지역 변수로 생성하며, command가 완료된 후에는 일반적인 지역 변수와 마찬가지로 명령어 치환 전의 REPLY 값으로 복구합니다.

예를 들어, 다음 구조는 ‘12345’로 확장되며 현재 실행 환경의 쉘 변수 X는 변경되지 않은 상태로 둡니다: 


${ local X=12345 ; echo $X; }

( X를 local로 선언하지 않으면 일반적인 쉘 함수 실행 시처럼 현재 환경의 값이 수정됩니다.) 반면 다음 구조는 출력을 생성하지 않고도 ‘12345’로 확장됩니다: 

${| REPLY=12345; }

그리고 명령어 치환 전의 REPLY 값을 복구합니다.

명령어 치환은 중첩될 수 있습니다. 백틱 형식을 사용할 때 중첩하려면 내부의 백틱들을 백슬래시로 이스케이프해야 합니다.

치환이 큰따옴표 내에서 이루어지는 경우, Bash는 결과물에 대해 단어 분할과 파일 이름 확장을 수행하지 않습니다.
