5.2 Bash 변수 ¶

이 변수들은 Bash에 의해 설정되거나 사용되지만, 다른 쉘에서는 보통 특별하게 취급하지 않습니다.

Bash가 사용하는 몇몇 변수들은 다른 장에서 설명되어 있습니다: 작업 제어(job control) 기능을 제어하기 위한 변수들(작업 제어 변수 참조).

_ ¶

($_, 언더스코어) 컨텍스트에 따라 여러 가지 의미를 갖습니다. 쉘 시작 시, $_는 환경(environment)이나 인자 목록을 통해 전달된, 실행 중인 쉘 또는 쉘 스크립트를 호출하는 데 사용된 경로명으로 설정됩니다. 그 후에는 확장 과정을 거친 후 포그라운드에서 실행된 이전 단순 명령어의 마지막 인자로 확장됩니다. 또한 실행되는 각 명령어를 호출하는 데 사용된 전체 경로명으로 설정되어 해당 명령어에 내보내지는 환경에 배치됩니다. 메일을 확인할 때 $_은 메일 파일의 이름으로 확장됩니다.

BASH ¶

현재 Bash 인스턴스를 실행하는 데 사용된 전체 경로명입니다.

BASHOPTS ¶

활성화된 쉘 옵션들의 콜론 구분 목록입니다. 목록의 각 단어는 shopt 빌트인 명령어의 -s 옵션에 대한 유효한 인자입니다(Shopt 빌트인 참조). BASHOPTS에 나타나는 옵션들은 ‘shopt’ 명령이 ‘on’으로 보고하는 것들입니다. Bash 시작 시 이 변수가 환경에 존재한다면, 쉘은 시작 파일을 읽기 전에 목록의 각 옵션을 활성화합니다. 이 변수가 내보내지면(exported), 자식 쉘들도 목록의 각 옵션을 활성화합니다. 이 변수는 읽기 전용(readonly)입니다.

BASHPID ¶

현재 Bash 프로세스의 프로세스 ID로 확장됩니다. 이는 Bash를 재초기화할 필요가 없는 서브쉘과 같은 특정 상황에서 $$와 다릅니다. BASHPID에 값을 할당하는 것은 효과가 없습니다. 만약 BASHPID가 해제(unset)되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

BASH_ALIASES ¶

alias 빌트인에 의해 관리되는 내부 별칭 목록에 대응하는 연관 배열(associative array) 변수입니다(Bourne 쉘 빌트인 참조). 이 배열에 추가된 요소들은 별칭 목록에 나타납니다; 하지만 배열 요소를 해제한다고 해서 현재 별칭 목록에서 해당 별칭이 제거되지는 않습니다. 만약 BASH_ALIASES가 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

BASH_ARGC ¶

현재 Bash 실행 호출 스택(call stack)의 각 프레임에 있는 파라미터 개수를 값으로 갖는 배열 변수입니다. 현재 서브루틴(쉘 함수나 . 또는 source로 실행된 스크립트)으로 전달된 파라미터의 개수가 스택의 최상단에 위치합니다. 서브루틴이 실행될 때 전달된 파라미터 개수가 BASH_ARGC에 푸시(push)됩니다. 쉘은 확장 디버깅 모드(shopt 빌트인의 extdebug 옵션 설명은 Shopt 빌트인 참조)일 때만 BASH_ARGC를 설정합니다. 쉘이 서브루틴 실행을 시작한 후에 extdebug를 설정하거나, extdebug가 설정되지 않았을 때 이 변수를 참조하면 일관성 없는 값이 나올 수 있습니다. BASH_ARGC에 대한 할당은 효과가 없으며 해제할 수 없습니다.

BASH_ARGV ¶

현재 Bash 실행 호출 스택의 모든 파라미터들을 포함하는 배열 변수입니다. 마지막 서브루틴 호출의 마지막 파라미터가 스택의 최상단에 있고, 최초 호출의 첫 번째 파라미터가 최하단에 있습니다. 서브루틴이 실행될 때 쉘은 제공된 파라미터들을 BASH_ARGV에 푸시합니다. 쉘은 확장 디버깅 모드(shopt 빌트인의 extdebug 옵션 설명은 Shopt 빌트인 참조)일 때만 BASH_ARGV를 설정합니다. 쉘이 스크립트 실행을 시작한 후에 extdebug를 설정하거나, extdebug가 설정되지 않았을 때 이 변수를 참조하면 일관성 없는 값이 나올 수 있습니다. BASH_ARGV에 대한 할당은 효과가 없으며 해제할 수 없습니다.

BASH_ARGV0 ¶

참조될 때 이 변수는 쉘 또는 쉘 스크립트의 이름으로 확장됩니다($0과 동일; 특수 파라미터 0에 대한 설명은 특수 파라미터 참조). BASH_ARGV0에 값을 할당하면 $0도 동일한 값으로 설정됩니다. 만약 BASH_ARGV0가 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

BASH_CMDS ¶

hash 빌트인에 의해 관리되는 내부 명령어 해시 테이블에 대응하는 연관 배열 변수입니다(Bourne 쉘 빌트인 참조). 이 배열에 요소를 추가하면 해시 테이블에 나타납니다; 하지만 배열 요소를 해제한다고 해서 해시 테이블에서 해당 명령어 이름이 제거되지는 않습니다. 만약 BASH_CMDS가 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

BASH_COMMAND ¶

현재 실행 중이거나 실행되려고 하는 명령어로 확장됩니다. 단, 트랩(trap)의 결과로 명령어를 실행 중인 경우에는 트랩 발생 시점에 실행 중이던 명령어가 됩니다. 만약 BASH_COMMAND가 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

BASH_COMPAT ¶

쉘의 호환성 레벨을 설정하는 데 사용됩니다. 다양한 호환성 레벨과 그 영향에 대한 설명은 쉘 호환 모드를 참조하십시오. 값은 원하는 호환성 레벨에 대응하는 10진수(예: 4.2) 또는 정수(예: 42)일 수 있습니다. 만약 BASH_COMPAT가 해제되거나 빈 문자열로 설정되면, 호환성 레벨은 현재 버전의 기본값으로 설정됩니다. 만약 BASH_COMPAT가 유효하지 않은 호환성 레벨로 설정되면, 쉘은 에러 메시지를 출력하고 호환성 레벨을 현재 버전의 기본값으로 설정합니다. 유효한 값의 하위 집합은 아래 설명된 호환성 레벨들에 대응합니다(쉘 호환 모드 참조). 예를 들어, 4.2와 42는 compat42 shopt 옵션에 대응하며 호환성 레벨을 42로 설정하는 유효한 값입니다. 현재 버전 또한 유효한 값입니다.

BASH_ENV ¶

Bash가 쉘 스크립트 실행을 위해 호출될 때 이 변수가 설정되어 있다면, 그 값이 확장되어 스크립트 실행 전 읽어들일 시작 파일(startup file)의 이름으로 사용됩니다. Bash는 결과 파일명을 찾기 위해 PATH를 사용하지 않습니다. Bash 시작 파일을 참조하십시오.

BASH_EXECUTION_STRING ¶

-c 호출 옵션에 전달된 명령어 인자입니다.

BASH_LINENO ¶

FUNCNAME의 각 대응하는 멤버가 호출된 소스 파일 내의 라인 번호들을 멤버로 갖는 배열 변수입니다. ${BASH_LINENO[$i]}는 ${FUNCNAME[$i]}가 호출된 소스 파일(${BASH_SOURCE[$i+1]}) 내의 라인 번호입니다(다른 쉘 함수 내에서 참조된 경우 ${BASH_LINENO[$i-1]}일 수 있음). 현재 라인 번호를 얻으려면 LINENO를 사용하십시오. BASH_LINENO에 대한 할당은 효과가 없으며 해제할 수 없습니다.

BASH_LOADABLES_PATH ¶

enable 명령어가 동적으로 로드 가능한 빌트인을 찾을 디렉토리들의 콜론 구분 목록입니다.

BASH_MONOSECONDS ¶

이 변수가 참조될 때마다 시스템의 모노토닉 클럭(monotonic clock)이 반환하는 값으로 확장됩니다(사용 가능한 경우). 모노토닉 클럭이 없으면 EPOCHSECONDS와 동일합니다. 만약 BASH_MONOSECONDS가 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

BASH_REMATCH ¶

[[ 조건부 명령어 내의 ‘=~’ 이항 연산자에 의해 값이 할당되는 배열 변수입니다(조건부 구문 참조). 인덱스가 0인 요소는 전체 정규 표현식과 매치된 부분입니다. 인덱스가 n인 요소는 n번째 괄호 서브 표현식과 매치된 부분입니다.

BASH_SOURCE ¶

FUNCNAME 배열 변수에 있는 각 쉘 함수 이름이 정의된 소스 파일명들을 멤버로 갖는 배열 변수입니다. 쉘 함수 ${FUNCNAME[$i]}는 파일 ${BASH_SOURCE[$i]}에서 정의되었으며 ${BASH_SOURCE[$i+1]}에서 호출되었습니다. BASH_SOURCE에 대한 할당은 효과가 없으며 해제할 수 없습니다.

BASH_SUBSHELL ¶

쉘이 서브쉘이나 서브쉘 환경에서 실행을 시작할 때마다 1씩 증가합니다. 초기값은 0입니다. 만약 BASH_SUBSHELL가 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

BASH_TRAPSIG ¶

실행 중인 트랩 동작에 대응하는 시그널 번호로 설정됩니다. 시그널 번호와 트랩 실행에 대한 정보는 trap 설명(Bourne 쉘 빌트인 참조)을 확인하십시오.

BASH_VERSINFO ¶

이 Bash 인스턴스의 버전 정보를 담고 있는 읽기 전용 배열 변수입니다(배열 참조). 배열 멤버에 할당된 값들은 다음과 같습니다:

BASH_VERSINFO[0]

메이저 버전 번호 (릴리스).

BASH_VERSINFO[1]

마이너 버전 번호 (버전).

BASH_VERSINFO[2]

패치 레벨.

BASH_VERSINFO[3]

빌드 버전.

BASH_VERSINFO[4]

릴리스 상태 (예: beta).

BASH_VERSINFO[5]

MACHTYPE의 값.

BASH_VERSION ¶

이 Bash 인스턴스의 버전을 설명하는 문자열로 확장됩니다 (예: 5.2.37(3)-release).

BASH_XTRACEFD ¶

유효한 파일 서술자에 대응하는 정수로 설정되면, ‘set -x’가 활성화되었을 때 생성되는 추적 출력을 표준 에러 대신 해당 파일 서술자로 씁니다. 이를 통해 추적 출력을 진단 및 에러 메시지와 분리할 수 있습니다. BASH_XTRACEFD가 해제되거나 새로운 값이 할당될 때 해당 파일 서술자는 닫힙니다. BASH_XTRACEFD를 해제하거나 빈 문자열을 할당하면 추적 출력이 표준 에러로 전송됩니다. BASH_XTRACEFD를 2(표준 에러 파일 서술자)로 설정한 후 해제하면 표준 에러가 닫히게 됨에 유의하십시오.

CHILD_MAX ¶

쉘이 기억할 종료된 자식 프로세스 상태 값의 개수를 설정합니다. Bash는 이 값을 POSIX가 규정한 최소값 미만으로 줄이는 것을 허용하지 않으며, 초과할 수 없는 최대값(현재 8192)이 존재합니다. 최소값은 시스템마다 다릅니다.

COLUMNS ¶

select 명령어가 선택 목록을 출력할 때 터미널 너비를 결정하기 위해 사용합니다. checkwinsize 옵션이 활성화되어 있거나(Shopt 빌트인 참조), 대화형 쉘에서 SIGWINCH를 수신했을 때 자동으로 설정됩니다.

COMP_CWORD ¶

현재 커서 위치를 포함하고 있는 단어의 ${COMP_WORDS} 내 인덱스입니다. 이 변수는 오직 프로그래밍 가능한 자동 완성 기능에 의해 호출된 쉘 함수 내에서만 사용할 수 있습니다(프로그래밍 가능한 자동 완성 참조).

COMP_KEY ¶

현재 자동 완성 함수를 호출하는 데 사용된 키(또는 키 시퀀스의 마지막 키)입니다. 이 변수는 오직 프로그래밍 가능한 자동 완성 기능에 의해 호출된 쉘 함수 및 외부 명령어 내에서만 사용할 수 있습니다(프로그래밍 가능한 자동 완성 참조).

COMP_LINE ¶

현재의 명령줄 내용입니다. 이 변수는 오직 프로그래밍 가능한 자동 완성 기능에 의해 호출된 쉘 함수 및 외부 명령어 내에서만 사용할 수 있습니다(프로그래밍 가능한 자동 완성 참조).

COMP_POINT ¶

현재 명령어의 시작 부분을 기준으로 한 현재 커서 위치의 인덱스입니다. 현재 커서 위치가 현재 명령어의 끝에 있다면, 이 변수의 값은 ${#COMP_LINE}과 같습니다. 이 변수는 오직 프로그래밍 가능한 자동 완성 기능에 의해 호출된 쉘 함수 및 외부 명령어 내에서만 사용할 수 있습니다(프로그래밍 가능한 자동 완성 참조).

COMP_TYPE ¶

자동 완성 함수를 호출하게 만든 시도된 자동 완성 유형에 대응하는 정수 값으로 설정됩니다: 일반적인 자동 완성을 위한 TAB, 연속적인 탭 입력 후 목록 표시를 위한 ‘?’, 부분적인 단어 완성 시 대안 목록 표시를 위한 ‘!’, 단어가 수정되지 않았을 때 목록 표시를 위한 ‘@’, 또는 메뉴 완성을 위한 ‘%’. 이 변수는 오직 프로그래밍 가능한 자동 완성 기능에 의해 호출된 쉘 함수 및 외부 명령어 내에서만 사용할 수 있습니다(프로그래밍 가능한 자동 완성 참조).

COMP_WORDBREAKS ¶

Readline 라이브러리가 단어 완성을 수행할 때 단어 구분자로 취급하는 문자들의 집합입니다. 만약 COMP_WORDBREAKS가 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

COMP_WORDS ¶

현재 명령줄에 있는 개별 단어들로 구성된 배열 변수입니다. 명령줄은 위에서 설명한 COMP_WORDBREAKS를 사용하여 Readline이 분할하는 방식과 동일하게 단어들로 분리됩니다. 이 변수는 오직 프로그래밍 가능한 자동 완성 기능에 의해 호출된 쉘 함수 내에서만 사용할 수 있습니다(프로그래밍 가능한 자동 완성 참조).

COMPREPLY ¶

프로그래밍 가능한 자동 완성 시설에 의해 호출된 쉘 함수가 생성한 가능한 완성 후보들을 Bash가 읽어들이는 배열 변수입니다(프로그래밍 가능한 자동 완성 참조). 각 배열 요소는 하나의 가능한 완성 후보를 포함합니다.

COPROC ¶

이름 없는 코프로세스(coprocess)로부터의 출력 및 그에 대한 입력을 위한 파일 서술자들을 담기 위해 생성된 배열 변수입니다(코프로세스 참조).

DIRSTACK ¶

디렉토리 스택의 현재 내용을 담고 있는 배열 변수입니다. 디렉토리들은 dirs 빌트인에 의해 표시되는 순서대로 스택에 나타납니다. 이 배열 변수의 멤버들에 값을 할당하여 스택에 이미 있는 디렉토리들을 수정할 수 있지만, 디렉토리를 추가하거나 삭제하려면 pushd 및 popd 빌트인을 사용해야 합니다. 이 변수에 할당한다고 해서 현재 디렉토리가 변경되지는 않습니다. 만약 DIRSTACK이 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

EMACS ¶

쉘 시작 시 Bash가 환경에서 이 변수를 발견하고 그 값이 ‘t’라면, Bash는 쉘이 Emacs 쉘 버퍼 내에서 실행 중이라고 가정하고 라인 편집 기능을 비활성화합니다.

ENV ¶

대화형 쉘이 POSIX 모드로 호출될 때 BASH_ENV와 유사하게 확장되어 실행됩니다(Bash 시작 파일 및 Bash와 POSIX 참조).

EPOCHREALTIME ¶

이 파라미터가 참조될 때마다 유닉스 에포크(Unix Epoch) 이후의 초(seconds)를 마이크로초 단위의 정밀도를 가진 부동 소수점 값으로 확장합니다(time C 라이브러리 함수의 에포크 정의를 참조하십시오). EPOCHREALTIME에 대한 할당은 무시됩니다. 만약 EPOCHREALTIME이 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

EPOCHSECONDS ¶

이 파라미터가 참조될 때마다 유닉스 에포크 이후의 초(seconds)로 확장합니다(time C 라이브러리 함수의 에포크 정의를 참조하십시오). EPOCHSECONDS에 대한 할당은 무시됩니다. 만약 EPOCHSECONDS가 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

EUID ¶

현재 사용자의 숫자 형식 유효 사용자 ID(effective user id)입니다. 이 변수는 읽기 전용입니다.

EXECIGNORE ¶

PATH를 사용한 명령어 검색 시 무시할 파일 이름들을 정의하는 쉘 패턴들의 콜론 구분 목록입니다(패턴 매칭 참조). 전체 경로명이 이 패턴들 중 하나와 일치하는 파일들은 자동 완성 및 PATH 조회를 통한 명령어 실행 시 실행 파일로 간주되지 않습니다. 이는 [, test, 그리고 [[ 명령어의 동작에는 영향을 주지 않습니다. 명령어 해시 테이블 내의 전체 경로명들은 EXECIGNORE의 대상이 아닙니다. 실행 비트가 설정되어 있지만 실행 파일은 아닌 공유 라이브러리 파일들을 무시하려면 이 변수를 사용하십시오. 패턴 매칭은 extglob 쉘 옵션 설정을 따릅니다.

FCEDIT ¶

fc 빌트인 명령어에서 기본으로 사용하는 에디터입니다.

FIGNORE ¶

파일명 완성을 수행할 때 무시할 접미사들의 콜론 구분 목록입니다. 접미사가 FIGNORE의 항목 중 하나와 일치하는 파일 이름은 일치하는 파일 이름 목록에서 제외됩니다. 예시 값은 ‘.o:~’ 입니다.

FUNCNAME ¶

현재 실행 호출 스택에 있는 모든 쉘 함수들의 이름을 포함하는 배열 변수입니다. 인덱스가 0인 요소는 현재 실행 중인 쉘 함수의 이름입니다. 가장 아래에 있는 요소(가장 높은 인덱스)는 "main"입니다. 이 변수는 쉘 함수가 실행 중일 때만 존재합니다. FUNCNAME에 대한 할당은 효과가 없습니다. 만약 FUNCNAME이 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

이 변수는 BASH_LINENO 및 BASH_SOURCE와 함께 사용될 수 있습니다. FUNCNAME의 각 요소는 호출 스택을 설명하기 위해 BASH_LINENO 및 BASH_SOURCE에 대응하는 요소들을 갖습니다. 예를 들어, ${FUNCNAME[$i]}는 파일 ${BASH_SOURCE[$i+1]}의 라인 번호 ${BASH_LINENO[$i]}에서 호출되었습니다. caller 빌트인은 이 정보를 사용하여 현재 호출 스택을 표시합니다.

FUNCNEST ¶

0보다 큰 숫자 값은 함수의 최대 중첩 레벨을 정의합니다. 이 중첩 레벨을 초과하는 함수 호출은 현재 명령어의 중단을 초래합니다.

GLOBIGNORE ¶

파일명 확장에 의해 무시될 파일 이름 세트를 정의하는 패턴들의 콜론 구분 목록입니다. 파일명 확장 패턴에 매치된 파일 이름이 GLOBIGNORE 내의 패턴 중 하나와도 일치하면 매치 목록에서 제거됩니다. 패턴 매칭은 extglob 쉘 옵션 설정을 따릅니다.

GLOBSORT ¶

파일명 확장 결과가 정렬되는 방식을 제어합니다. 이 변수의 값은 파일명 확장 결과에 대한 정렬 기준과 정렬 순서를 지정합니다. 이 변수가 해제되거나 빈 문자열로 설정되면, 파일명 확장은 LC_COLLATE 쉘 변수에 의해 결정된 사전순 오름차순으로 이름을 정렬하는 역사적인 동작을 사용합니다.

설정된 경우, 유효한 값은 무시되는 선택적인 ‘+’ 기호 또는 정렬 순서를 오름차순에서 내림차순으로 반전시키는 ‘-’ 기호로 시작하며, 그 뒤에 정렬 지정자(sort specifier)가 옵니다. 유효한 정렬 지정자는 다음과 같습니다: 이름순 정렬인 ‘name’, 이름을 사전순이 아닌 숫자 순서로 정렬하는 ‘numeric’, 파일 크기순인 ‘size’, 수정 시간순인 ‘mtime’, 액세스 시간순인 ‘atime’, 아이노드(inode) 변경 시간순인 ‘ctime’, 그리고 블록 개수순인 ‘blocks’. 이름이 아닌 다른 기준으로 정렬할 때 값이 동일한 경우(예: 두 파일의 크기가 같은 경우)에는 이름을 보조 정렬 키로 사용합니다.

예를 들어, -mtime 값은 결과를 수정 시간의 내림차순(최신순)으로 정렬합니다.

‘numeric’ 지정자는 숫자로만 구성된 이름들을 숫자로 취급하여 그 숫자 값에 따라 정렬합니다(예: “2”가 “10”보다 먼저 옴). ‘numeric’을 사용할 때 숫자가 아닌 문자가 포함된 이름들은 모든 숫자 이름들 뒤에 오며, 기존 동작 방식에 따라 이름순으로 정렬됩니다.

‘nosort’ 정렬 지정자는 정렬을 완전히 비활성화합니다; Bash는 파일 시스템에서 읽어들인 순서대로 결과를 반환하며, 앞에 붙은 ‘-’는 무시합니다.

정렬 지정자가 누락된 경우 기본값은 name입니다. 따라서 ‘+’ 값은 빈 문자열과 동일하며, ‘-’ 값은 이름을 내림차순으로 정렬합니다.

유효하지 않은 값은 역사적인 정렬 동작을 복구합니다.

GROUPS ¶

현재 사용자가 속한 그룹들의 목록을 포함하는 배열 변수입니다. GROUPS에 대한 할당은 효과가 없습니다. 만약 GROUPS가 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

histchars ¶

히스토리 확장, 빠른 치환(quick substitution), 그리고 토큰화를 제어하는 2개 또는 3개의 문자입니다(히스토리 확장 참조). 첫 번째 문자는 히스토리 확장 문자로, 보통 ‘!’이며 히스토리 확장을 시작합니다. 두 번째 문자는 빠른 치환 문자로, 보통 ‘^’입니다. 줄의 첫 번째 문자로 나타날 때 히스토리 치환을 통해 이전 명령어를 반복하며 한 문자열을 다른 문자열로 바꿉니다. 선택 사항인 세 번째 문자는 히스토리 주석 문자로, 보통 ‘#’이며 단어의 첫 문자로 나타날 때 줄의 나머지 부분이 주석임을 나타냅니다. 히스토리 주석 문자는 줄의 나머지 단어들에 대해 히스토리 확장을 비활성화합니다. 이것이 반드시 쉘 파서가 줄의 나머지를 주석으로 취급하게 만드는 것은 아닙니다.

HISTCMD ¶

현재 명령어의 히스토리 번호 또는 히스토리 목록 내의 인덱스입니다. HISTCMD에 대한 할당은 효과가 없습니다. 만약 HISTCMD가 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

HISTCONTROL ¶

명령어들이 히스토리 목록에 저장되는 방식을 제어하는 값들의 콜론 구분 목록입니다. 목록에 ‘ignorespace’가 포함되어 있으면 공백 문자로 시작하는 줄은 히스토리 목록에 저장되지 않습니다. ‘ignoredups’ 값은 이전 히스토리 항목과 일치하는 줄이 저장되지 않도록 합니다. ‘ignoreboth’는 ‘ignorespace’와 ‘ignoredups’의 축약형입니다. ‘erasedups’ 값은 현재 줄이 저장되기 전에 히스토리 목록에서 현재 줄과 일치하는 이전의 모든 줄들을 제거하도록 합니다. 위 목록에 없는 값은 무시됩니다. 만약 HISTCONTROL이 해제되어 있거나 유효한 값을 포함하지 않는다면, 쉘 파서가 읽은 모든 줄은 HISTIGNORE 값에 따라 히스토리 목록에 저장됩니다. 여러 줄로 된 복합 명령어의 첫 번째 줄이 저장되었다면, 두 번째 줄부터는 HISTCONTROL 값과 관계없이 히스토리에 추가됩니다. 첫 번째 줄이 저장되지 않았다면 해당 명령어의 나머지 줄들도 저장되지 않습니다.

HISTFILE ¶

명령어 히스토리가 저장되는 파일의 이름입니다. Bash는 기본값으로 ~/.bash_history를 할당합니다. 만약 HISTFILE이 해제되거나 null이면, 쉘이 종료될 때 명령어 히스토리를 저장하지 않습니다.

HISTFILESIZE ¶

히스토리 파일에 포함될 수 있는 최대 줄 수입니다. 이 변수에 값이 할당될 때, 가장 오래된 항목들을 제거하여 해당 줄 수를 초과하지 않도록 히스토리 파일이 절단(truncate)됩니다. 히스토리 목록에 여러 줄로 된 항목이 포함된 경우, 부분적인 히스토리 항목이 남는 것을 방지하기 위해 파일이 이 최대값보다 더 많은 줄을 가질 수도 있습니다. 또한 쉘이 종료될 때 또는 history 빌트인에 의해 히스토리 파일을 쓴 후에도 이 크기로 절단됩니다. 값이 0이면 히스토리 파일은 크기가 0이 되도록 절단됩니다. 숫자가 아닌 값이나 0보다 작은 숫자 값은 절단을 억제합니다. 쉘은 시작 파일들을 읽은 후에 기본값을 HISTSIZE 값으로 설정합니다.

HISTIGNORE ¶

어떤 명령줄이 히스토리 목록에 저장될지 결정하는 데 사용되는 패턴들의 콜론 구분 목록입니다. 명령줄이 HISTIGNORE의 패턴 중 하나와 일치하면 히스토리 목록에 저장되지 않습니다. 각 패턴은 줄의 시작 부분에 고정(anchor)되며 전체 줄과 일치해야 합니다(Bash는 끝에 ‘*’를 암시적으로 추가하지 않습니다). 각 패턴은 HISTCONTROL로 지정된 검사들이 적용된 후에 테스트됩니다. 일반적인 쉘 패턴 매칭 문자 외에도 ‘&’은 이전 히스토리 라인과 매치됩니다. 백슬래시는 ‘&’을 이스케이프하며, 매칭을 시도하기 전에 백슬래시는 제거됩니다. 여러 줄로 된 복합 명령어의 첫 번째 줄이 저장되었다면, 나머지 줄들은 HISTIGNORE 값과 관계없이 히스토리에 추가됩니다. 첫 번째 줄이 저장되지 않았다면 나머지 줄들도 저장되지 않습니다. 패턴 매칭은 extglob 쉘 옵션 설정을 따릅니다.

HISTIGNORE는 HISTCONTROL의 일부 기능을 포함합니다. ‘&’ 패턴은 ignoredups와 동일하고, ‘[ ]*’ 패턴은 ignorespace와 동일합니다. 이 두 패턴을 콜론으로 구분하여 결합하면 ignoreboth와 동일한 기능을 제공합니다.

HISTSIZE ¶

히스토리 목록에 기억할 최대 명령어 개수입니다. 값이 0이면 명령어가 히스토리 목록에 저장되지 않습니다. 0보다 작은 숫자 값은 모든 명령어가 히스토리 목록에 저장되도록 합니다(제한 없음). 쉘은 시작 파일들을 읽은 후에 기본값을 500으로 설정합니다.

HISTTIMEFORMAT ¶

이 변수가 설정되어 있고 null이 아니라면, 그 값은 history 빌트인에 의해 표시되는 각 히스토리 항목과 연관된 타임스탬프를 출력하기 위한 strftime(3)의 형식 문자열로 사용됩니다. 이 변수가 설정되어 있다면, 쉘 세션 간에 타임스탬프를 보존할 수 있도록 쉘이 히스토리 파일에 타임스탬프를 기록합니다. 이때 타임스탬프와 다른 히스토리 라인을 구분하기 위해 히스토리 주석 문자를 사용합니다.

HOSTFILE ¶

쉘이 호스트 이름을 완성해야 할 때 읽어들일 /etc/hosts와 동일한 형식의 파일 이름을 포함합니다. 가능한 호스트 이름 완성 목록은 쉘이 실행 중인 동안에도 변경될 수 있습니다; 값이 변경된 후 다음번에 호스트 이름 완성이 시도될 때, Bash는 새로운 파일의 내용을 기존 목록에 추가합니다. 만약 HOSTFILE이 설정되어 있지만 값이 없거나 읽을 수 있는 파일이 아니라면, Bash는 호스트 이름 완성 목록을 얻기 위해 /etc/hosts를 읽으려고 시도합니다. HOSTFILE이 해제되면 Bash는 호스트 이름 목록을 비웁니다.

HOSTNAME ¶

현재 호스트의 이름입니다.

HOSTTYPE ¶

Bash가 실행 중인 머신을 설명하는 문자열입니다.

IGNOREEOF ¶

유일한 입력으로 EOF 문자를 받았을 때의 쉘 동작을 제어합니다. 설정된 경우, 그 값은 Bash가 종료되기 전에 입력 줄의 첫 번째 문자로 읽을 수 있는 연속적인 EOF 문자의 개수입니다. 변수가 설정되어 있지만 숫자 값이 아니거나 값이 null인 경우 기본값은 10입니다. 변수가 해제되어 있다면 EOF는 쉘에 대한 입력의 끝을 의미합니다. 이 설정은 오직 대화형 쉘에서만 유효합니다.

INPUTRC ¶

Readline 초기화 파일의 이름이며, 기본값인 ~/.inputrc를 무시하고 설정됩니다.

INSIDE_EMACS ¶

쉘 시작 시 Bash가 환경에서 이 변수를 발견하면, 쉘이 Emacs 쉘 버퍼 내에서 실행 중이라고 가정하며 TERM 값에 따라 라인 편집 기능을 비활성화할 수 있습니다.

LANG ¶

LC_로 시작하는 변수로 특별히 선택되지 않은 모든 카테고리에 대해 로케일 카테고리를 결정하는 데 사용됩니다.

LC_ALL ¶

이 변수는 LANG 및 로케일 카테고리를 지정하는 다른 모든 LC_ 변수들의 값을 무시하고 우선 적용됩니다.

LC_COLLATE ¶

파일명 확장 결과를 정렬할 때 사용되는 정렬 순서를 결정하며, 파일명 확장 및 패턴 매칭 내에서의 범위 표현식, 동등 클래스, 그리고 정렬 순서의 동작을 결정합니다(파일명 확장 참조).

LC_CTYPE ¶

파일명 확장 및 패턴 매칭 내에서의 문자 해석과 문자 클래스의 동작을 결정합니다(파일명 확장 참조).

LC_MESSAGES ¶

앞에 ‘$’가 붙은 큰따옴표 문자열을 번역할 때 사용되는 로케일을 결정합니다(로케일 특정 번역 참조).

LC_NUMERIC ¶

숫자 형식을 위해 사용되는 로케일 카테고리를 결정합니다.

LC_TIME ¶

날짜 및 시간 형식을 위해 사용되는 로케일 카테고리를 결정합니다.

LINENO ¶

현재 실행 중인 스크립트나 쉘 함수 내에서의 라인 번호입니다. 라인 번호는 1부터 시작합니다. 스크립트나 함수 외부에서 이 값은 의미 있는 값임을 보장하지 않습니다. 만약 LINENO가 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

LINES ¶

select 명령어가 선택 목록을 출력할 때 행의 길이를 결정하기 위해 사용합니다. checkwinsize 옵션이 활성화되어 있거나(Shopt 빌트인 참조), 대화형 쉘에서 SIGWINCH를 수신했을 때 자동으로 설정됩니다.

MACHTYPE ¶

Bash가 실행 중인 시스템 유형을 표준 GNU cpu-company-system 형식으로 완전하게 설명하는 문자열입니다.

MAILCHECK ¶

쉘이 MAILPATH 또는 MAIL 변수에 지정된 파일들에서 메일을 얼마나 자주(초 단위로) 확인해야 하는지 지정합니다. 기본값은 60초입니다. 메일을 확인할 시간이 되면 쉘은 기본 프롬프트를 표시하기 전에 확인을 수행합니다. 이 변수가 해제되어 있거나 0보다 크거나 같은 숫자가 아닌 값으로 설정되어 있다면 쉘은 메일 확인을 수행하지 않습니다.

MAPFILE ¶

변수 이름이 제공되지 않았을 때 mapfile 빌트인이 읽어들인 텍스트를 저장하기 위해 생성된 배열 변수입니다.

OLDPWD ¶

cd 빌트인에 의해 설정된 이전 작업 디렉토리입니다.

OPTERR ¶

값이 1로 설정되어 있으면, Bash는 getopts 빌트인 명령어에 의해 생성된 에러 메시지를 표시합니다. OPTERR은 쉘이 호출될 때마다 1로 초기화됩니다.

OSTYPE ¶

Bash가 실행 중인 운영체제를 설명하는 문자열입니다.

PIPESTATUS ¶

가장 최근에 실행된 포그라운드 파이프라인(단일 단순 명령어로 구성될 수 있음)에 포함된 명령어들의 종료 상태 값 목록을 담고 있는 배열 변수입니다(배열 참조). Bash는 여러 요소로 된 파이프라인, 실행 시간이 측정되거나 부정된 파이프라인, 단순 명령어, ‘(’ 연산자로 생성된 서브쉘, [[ 및 (( 복합 명령어 실행 후, 그리고 쉘이 명령어 실행을 중단하게 만드는 에러 조건 발생 후에 PIPESTATUS를 설정합니다.

POSIXLY_CORRECT ¶

Bash 시작 시 이 변수가 환경에 존재한다면, 마치 --posix 호출 옵션이 제공된 것처럼 시작 파일을 읽기 전에 쉘이 POSIX 모드로 진입합니다(Bash와 POSIX 참조). 쉘이 실행 중인 동안 이 변수가 설정되면, 마치 

set -o posix

명령어가 실행된 것처럼 Bash는 POSIX 모드를 활성화합니다. 쉘이 POSIX 모드에 진입할 때, 이 변수가 아직 설정되어 있지 않다면 쉘이 이 변수를 설정합니다.

PPID ¶

쉘의 부모 프로세스의 프로세스 ID입니다. 이 변수는 읽기 전용입니다.

PROMPT_COMMAND ¶

이 변수가 설정되어 있고 배열이라면, 각 설정된 요소의 값은 기본 프롬프트($PS1)를 출력하기 전에 실행할 명령어로 해석됩니다. 배열 변수가 아니라면 그 값 자체가 대신 실행할 명령어로 사용됩니다.

PROMPT_DIRTRIM ¶

0보다 큰 숫자로 설정되면, 그 값은 \w 및 \W 프롬프트 문자열 이스케이프를 확장할 때 유지할 마지막 디렉토리 구성 요소의 개수로 사용됩니다(프롬프트 제어하기 참조). 제거된 문자들은 생략 부호(...)로 대체됩니다.

PS0 ¶

이 파라미터의 값은 PS1과 마찬가지로 확장되어, 대화형 쉘에서 명령어를 읽은 후 명령어가 실행되기 직전에 표시됩니다.

PS3 ¶

이 변수의 값은 select 명령어를 위한 프롬프트로 사용됩니다. 이 변수가 설정되어 있지 않으면 select 명령어는 ‘#? ’을 프롬프트로 사용합니다.

PS4 ¶

이 파라미터의 값은 PS1과 마찬가지로 확장되며, 그 확장된 값은 -x 옵션이 설정되었을 때 명령줄이 에코(echo)되기 전에 출력되는 프롬프트가 됩니다(Set 빌트인 참조). 확장된 값의 첫 번째 문자는 여러 단계의 간접 참조를 나타내기 위해 필요한 만큼 반복됩니다. 기본값은 ‘+ ’입니다.

PWD ¶

cd 빌트인에 의해 설정된 현재 작업 디렉토리입니다.

RANDOM ¶

이 파라미터가 참조될 때마다 0에서 32767 사이의 무작위 정수로 확장됩니다. RANDOM에 값을 할당하면 무작위 숫자 시퀀스를 초기화(시드, seed)합니다. 무작위 숫자 생성기를 동일한 상수 값으로 시딩하면 동일한 값의 시퀀스가 생성됩니다. 만약 RANDOM이 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

READLINE_ARGUMENT ¶

‘bind -x’를 사용하여 정의된 Readline 명령어에 호출 시 전달된 숫자 인자입니다(Bash 빌트인 명령어 참조).

READLINE_LINE ¶

Readline 라인 버퍼의 내용으로, ‘bind -x’와 함께 사용하기 위한 용도입니다(Bash 빌트인 명령어 참조).

READLINE_MARK ¶

Readline 라인 버퍼 내의 마크(mark)(저장된 삽입 지점) 위치로, ‘bind -x’와 함께 사용하기 위한 용도입니다(Bash 빌트인 명령어 참조). 삽입 지점과 마크 사이의 문자들을 종종 리전(region)이라고 부릅니다.

READLINE_POINT ¶

Readline 라인 버퍼 내의 삽입 지점 위치로, ‘bind -x’와 함께 사용하기 위한 용도입니다(Bash 빌트인 명령어 참조).

REPLY ¶

read 빌트인의 기본 변수입니다. read에 변수 이름 인자가 제공되지 않았을 때 읽어들인 줄이 이 변수에 설정됩니다.

SECONDS ¶

이 변수는 쉘이 시작된 이후 경과한 초(seconds)로 확장됩니다. 이 변수에 값을 할당하면 카운트가 할당된 값으로 리셋되며, 이후 확장된 값은 할당된 값에 할당 이후 경과한 초를 더한 값이 됩니다. 쉘 호출 시점의 초와 현재 시간은 항상 시스템 클럭을 1초 해상도로 쿼리하여 결정됩니다. 만약 SECONDS가 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

SHELL ¶

이 환경 변수는 쉘의 전체 경로명으로 확장됩니다. 쉘 시작 시 설정되어 있지 않으면 Bash는 현재 사용자의 로그인 쉘의 전체 경로명을 이 변수에 할당합니다.

SHELLOPTS ¶

활성화된 쉘 옵션들의 콜론 구분 목록입니다. 목록의 각 단어는 set 빌트인 명령어의 -o 옵션에 대한 유효한 인자입니다(Set 빌트인 참조). SHELLOPTS에 나타나는 옵션들은 ‘set -o’ 명령이 ‘on’으로 보고하는 것들입니다. Bash 시작 시 이 변수가 환경에 존재한다면, 쉘은 시작 파일을 읽기 전에 목록의 각 옵션을 활성화합니다. 이 변수가 내보내지면, 자식 쉘들도 목록의 각 옵션을 활성화합니다. 이 변수는 읽기 전용입니다.

SHLVL ¶

새로운 Bash 인스턴스가 시작될 때마다 1씩 증가합니다. 이는 Bash 쉘이 얼마나 깊게 중첩되어 있는지를 나타내기 위한 용도입니다.

SRANDOM ¶

이 변수는 참조될 때마다 32비트 의사 난수(pseudo-random number)로 확장됩니다. /dev/urandom 또는 arc4random을 지원하는 시스템에서 무작위 숫자 생성기는 선형적이지 않으므로, 반환되는 각 숫자는 이전 숫자들과 아무런 관계가 없습니다. 무작위 숫자 생성기는 시딩(seeded)될 수 없으므로, 이 변수에 대한 할당은 효과가 없습니다. 만약 SRANDOM이 해제되면, 이후에 다시 설정되더라도 특별한 속성을 잃게 됩니다.

TIMEFORMAT ¶

이 파라미터의 값은 time 예약어가 붙은 파이프라인의 시간 정보가 어떻게 표시되어야 하는지를 지정하는 형식 문자열로 사용됩니다. ‘%’ 문자는 시간 값이나 다른 정보로 확장되는 이스케이프 시퀀스를 도입합니다. 이스케이프 시퀀스와 그 의미는 다음과 같습니다; 대괄호는 선택적인 부분을 나타냅니다.

%%

리터럴 ‘%’.

%[p][l]R

경과 시간 (초 단위).

%[p][l]U

사용자 모드에서 소요된 CPU 시간 (초 단위).

%[p][l]S

시스템 모드에서 소요된 CPU 시간 (초 단위).

%P

CPU 사용 백분율, (%U + %S) / %R 로 계산됩니다.

선택적인 p는 정밀도를 지정하는 숫자로, 소수점 뒤의 자릿수를 의미합니다. 값이 0이면 소수점이나 소수 부분이 출력되지 않습니다. time은 소수점 뒤에 최대 6자리까지 출력합니다; p의 값이 6보다 크면 6으로 변경됩니다. p가 지정되지 않으면 time은 소수점 뒤 3자리까지 출력합니다.

선택적인 l은 분(minutes)을 포함하는 MMmSS.FFs 형식의 긴 포맷을 지정합니다. p의 값은 소수 부분이 포함될지 여부를 결정합니다.

이 변수가 설정되어 있지 않으면 Bash는 다음과 같은 값을 가진 것처럼 동작합니다: 

$'\nreal\t%3lR\nuser\t%3lU\nsys\t%3lS'

값이 null이면 Bash는 시간 정보를 전혀 표시하지 않습니다. 형식 문자열이 표시될 때 마지막에 줄바꿈이 하나 추가됩니다.

TMOUT ¶

0보다 큰 값으로 설정되면, read 빌트인은 이 값을 기본 타임아웃으로 사용합니다(Bash 빌트인 명령어 참조). select 명령어(조건부 구문 참조)는 입력이 터미널로부터 올 때 TMOUT 초 동안 입력이 도착하지 않으면 종료됩니다.

대화형 쉘에서 이 값은 기본 프롬프트를 띄운 후 입력을 기다릴 시간(초 단위)으로 해석됩니다. 완전한 입력 줄이 지정된 초 내에 도착하지 않으면 Bash는 종료됩니다.

TMPDIR ¶

설정된 경우, Bash는 쉘이 사용할 임시 파일들을 생성할 디렉토리의 이름으로 이 값을 사용합니다.

UID ¶

현재 사용자의 숫자 형식 실제 사용자 ID(real user id)입니다. 이 변수는 읽기 전용입니다.
