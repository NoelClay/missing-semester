6.2 Bash 시작 파일 ¶

이 섹션에서는 Bash가 시작 파일(startup files)을 실행하는 방식을 설명합니다. 만약 해당 파일들이 존재하지만 읽을 수 없는 경우, Bash는 에러를 보고합니다. 파일 이름에 포함된 물결표(tilde)는 위에서 설명한 물결표 확장 규칙에 따라 확장됩니다(물결표 확장 참조).

대화형 쉘에 대한 설명은 대화형 쉘을 참조하십시오.

대화형 로그인 쉘로 호출되거나 --login 옵션을 사용한 경우 ¶

Bash가 대화형 로그인 쉘로 호출되거나, --login 옵션과 함께 비대화형 쉘로 호출되면, 먼저 /etc/profile 파일이 존재할 경우 해당 파일로부터 명령어들을 읽어 실행합니다. 그 후 ~/.bash_profile, ~/.bash_login, 그리고 ~/.profile 순서대로 파일을 찾아 가장 먼저 발견되고 읽기 가능한 파일로부터 명령어들을 읽어 실행합니다. --noprofile 옵션은 이러한 동작을 억제합니다.

대화형 로그인 쉘이 종료되거나, 비대화형 로그인 쉘이 exit 빌트인 명령어를 실행할 때, Bash는 ~/.bash_logout 파일이 존재하면 해당 파일로부터 명령어들을 읽어 실행합니다.

대화형 비로그인 쉘로 호출된 경우 ¶

Bash가 로그인 쉘이 아닌 대화형 쉘로 실행될 때, ~/.bashrc 파일이 존재하면 해당 파일로부터 명령어들을 읽어 실행합니다. --norc 옵션은 이러한 동작을 억제합니다. --rcfile file 옵션은 Bash가 ~/.bashrc 대신 file을 사용하도록 합니다.

따라서 일반적으로 사용자의 ~/.bash_profile에는 로그인 전용 초기화 작업 뒤(또는 전)에 다음과 같은 줄이 포함됩니다: 

if [ -f ~/.bashrc ]; then . ~/.bashrc; fi

비대화형으로 호출된 경우 ¶

Bash가 예를 들어 쉘 스크립트 실행을 위해 비대화형으로 시작되면, 환경에서 BASH_ENV 변수를 찾고, 해당 변수가 존재하면 그 값을 확장하여 읽고 실행할 파일의 이름으로 사용합니다. Bash는 마치 다음 명령어가 실행된 것처럼 동작합니다: 

if [ -n "$BASH_ENV" ]; then . "$BASH_ENV"; fi

하지만 파일 이름을 찾기 위해 PATH 변수 값을 사용하지는 않습니다.

위에서 언급했듯이, 비대화형 쉘이 --login 옵션과 함께 호출되면 Bash는 로그인 쉘 시작 파일들을 읽어 실행하려고 시도합니다.

sh라는 이름으로 호출된 경우 ¶

Bash가 sh라는 이름으로 호출되면, 기존 sh 버전들의 시작 동작을 최대한 가깝게 흉내 내려고 시도하면서 POSIX 표준 또한 준수합니다.

대화형 로그인 쉘로 호출되거나 --login 옵션과 함께 비대화형 쉘로 호출되면, 먼저 /etc/profile과 ~/.profile 순서대로 읽고 실행하려고 시도합니다. --noprofile 옵션은 이 동작을 억제합니다.

Bash가 sh라는 이름의 대화형 쉘로 호출되면, ENV 변수를 찾고 정의되어 있다면 그 값을 확장하여 읽고 실행할 파일 이름으로 사용합니다. sh로 호출된 쉘은 다른 시작 파일들을 읽으려 하지 않으므로, --rcfile 옵션은 아무런 효과가 없습니다.

sh라는 이름으로 호출된 비대화형 쉘은 그 어떤 시작 파일도 읽으려 하지 않습니다.

sh로 호출되었을 때, Bash는 시작 파일들을 읽은 후 POSIX 모드로 진입합니다.

POSIX 모드로 호출된 경우 ¶

--posix 명령줄 옵션을 사용하는 등 Bash가 POSIX 모드에서 시작되면, 시작 파일에 대해 POSIX 표준을 따릅니다. 이 모드에서 대화형 쉘은 ENV 변수를 확장하고 그 확장된 값인 이름의 파일로부터 명령어들을 읽어 실행합니다. 그 외의 다른 시작 파일들은 읽지 않습니다.

원격 쉘 데몬에 의해 호출된 경우 ¶

Bash는 표준 입력이 네트워크 연결에 연결되어 실행되는 시점(예: 구식의 드문 원격 쉘 데몬인 rshd나 보안 쉘 데몬인 sshd에 의해 실행될 때)을 판단하려고 시도합니다. 만약 Bash가 이런 방식으로 비대화형으로 실행되고 있다고 판단하면, ~/.bashrc 파일이 존재하고 읽기 가능한 경우 해당 파일을 읽어 실행합니다. sh로 호출된 경우에는 이 파일을 읽지 않습니다. --norc 옵션은 이 동작을 억제하며, --rcfile 옵션은 Bash가 ~/.bashrc 대신 다른 파일을 사용하게 할 수 있지만, rshd나 sshd는 보통 이러한 옵션들과 함께 쉘을 호출하거나 옵션 지정을 허용하지 않습니다.

유효 UID/GID와 실제 UID/GID가 다르게 호출된 경우 ¶

만약 Bash가 유효 사용자(그룹) ID가 실제 사용자(그룹) ID와 다른 상태로 시작되었고 -p 옵션이 제공되지 않았다면, 그 어떤 시작 파일도 읽지 않으며, 환경으로부터 쉘 함수를 상속받지 않고, SHELLOPTS, BASHOPTS, CDPATH, 그리고 GLOBIGNORE 변수가 환경에 존재하더라도 무시하며, 유효 사용자 ID를 실제 사용자 ID로 설정합니다. 만약 호출 시 -p 옵션이 제공되었다면 시작 동작은 동일하지만 유효 사용자 ID가 리셋되지 않습니다.
