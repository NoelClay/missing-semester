3.7.3 명령어 실행 환경 ¶

쉘은 다음 항목들로 구성된 실행 환경(execution environment)을 가집니다:

  • 쉘 호출 시 상속받은 열린 파일들. exec 빌트인에 제공된 리다이렉션에 의해 수정될 수 있습니다.
  • cd, pushd, popd에 의해 설정되었거나 호출 시 상속받은 현재 작업 디렉토리.
  • umask에 의해 설정되었거나 부모 프로세스로부터 상속받은 파일 생성 모드 마스크(mask).
  • trap에 의해 설정된 현재 트랩(traps).
  • 변수 할당이나 set으로 설정되었거나 부모로부터 상속받은 쉘 파라미터들.
  • 실행 중에 정의되었거나 부모로부터 상속받은 쉘 함수들.
  • 호출 시(기본값 또는 명령줄 인자) 또는 set에 의해 활성화된 옵션들.
  • shopt에 의해 활성화된 옵션들(Shopt 빌트인 참조).
  • alias로 정의된 쉘 별칭들(별칭 참조).
  • 백그라운드 작업을 포함한 다양한 프로세스 ID들(명령어 목록 참조), $$의 값, 그리고 $PPID의 값.

빌트인이나 쉘 함수가 아닌 단순 명령어가 실행될 때, 해당 명령어는 다음과 같은 항목들로 구성된 별도의 실행 환경에서 호출됩니다. 별도로 언급하지 않는 한, 값들은 쉘로부터 상속받습니다.

  • 쉘의 열린 파일들 및 해당 명령어에 지정된 리다이렉션에 의한 수정 및 추가 사항들.
  • 현재 작업 디렉토리.
  • 파일 생성 모드 마스크.
  • 내보내기(export)로 표시된 쉘 변수 및 함수들, 그리고 해당 명령어를 위해 내보내진 변수들(환경 참조).
  • 쉘에 의해 포착된 트랩들은 부모로부터 상속받은 값으로 초기화되고, 쉘이 무시한 트랩들은 그대로 무시됩니다.

이 별도의 환경에서 호출된 명령어는 쉘의 실행 환경에 영향을 미칠 수 없습니다.

서브쉘(subshell)은 쉘 프로세스의 복사본입니다.

명령어 치환, 소괄호로 그룹화된 명령어들, 그리고 비동기 명령어들은 쉘 환경의 복제본인 서브쉘 환경에서 호출됩니다. 단, 쉘에 의해 포착된 트랩들은 호출 시 부모로부터 상속받은 값으로 초기화됩니다. 파이프라인의 일부로 호출된 빌트인 명령어들 또한 lastpipe 쉘 옵션의 값에 따라 마지막 요소가 아닐 경우 서브쉘 환경에서 실행됩니다(Shopt 빌트인 참조). 서브쉘 환경에서 행해진 변경 사항은 원래 쉘의 실행 환경에 영향을 줄 수 없습니다.

쉘이 POSIX 모드일 때, 명령어 치환을 실행하기 위해 생성된 서브쉘은 부모 쉘로부터 -e 옵션의 값을 상속받습니다. POSIX 모드가 아닐 때 Bash는 그러한 서브쉘에서 -e 옵션을 해제합니다. POSIX 모드가 아닐 때 이 동작을 제어하는 방법은 inherit_errexit 쉘 옵션 설명(Bash 빌트인 명령어 참조)을 확인하십시오.

명령어 뒤에 ‘&’가 붙고 작업 제어가 활성 상태가 아니라면, 해당 명령어의 기본 표준 입력은 빈 파일인 /dev/null이 됩니다. 그렇지 않은 경우, 호출된 명령어는 호출한 쉘의 파일 서술자들을 (리다이렉션에 의해 수정된 상태로) 상속받습니다.
