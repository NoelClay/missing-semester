3.2.5.2 조건부 구문 ¶

if ¶

if 명령어의 문법은 다음과 같습니다: 

if test-commands; then
  consequent-commands;
[elif more-test-commands; then
  more-consequents;]
[else alternate-consequents;]
fi

test-commands 목록이 실행되고, 그 반환 상태가 0이면 consequent-commands 목록이 실행됩니다. 만약 test-commands가 0이 아닌 상태를 반환하면, 각 elif 목록이 차례대로 실행되며, 그 종료 상태가 0이면 해당되는 more-consequents가 실행되고 명령어가 종료됩니다. 만약 ‘else alternate-consequents’가 존재하고, 마지막 if 또는 elif 절의 마지막 명령어가 0이 아닌 종료 상태를 반환하면 alternate-consequents가 실행됩니다. 반환 상태는 마지막으로 실행된 명령어의 종료 상태이거나, 참으로 판명된 조건이 없는 경우 0입니다.

case ¶

case 명령어의 문법은 다음과 같습니다: 

case word in
    [ [(] pattern [| pattern]...) command-list ;;]...
esac

case는 word와 매치되는 첫 번째 pattern에 해당하는 command-list를 선택적으로 실행하며, 첫 번째 패턴부터 마지막 패턴까지 순차적으로 진행합니다. 매칭은 아래 패턴 매칭에 설명된 규칙에 따라 수행됩니다. 만약 nocasematch 쉘 옵션(Shopt 빌트인의 shopt 설명 참조)이 활성화되어 있으면, 알파벳 문자의 대소문자를 구분하지 않고 매칭을 수행합니다. ‘|’는 패턴 목록에서 여러 패턴을 구분하는 데 사용되며, ‘)’ 연산자는 패턴 목록을 종료합니다. 패턴 목록과 그에 연관된 command-list를 하나의 절(clause)이라고 합니다.

각 절은 ‘;;’, ‘;&’, 또는 ‘;;&’로 종료되어야 합니다. 쉘이 패턴 매칭을 시도하기 전에 word에 대해 물결표 확장, 파라미터 확장, 명령어 치환, 프로세스 치환, 산술 확장 및 따옴표 제거(쉘 파라미터 확장 참조)가 수행됩니다. 각 pattern에 대해서도 물결표 확장, 파라미터 확장, 명령어 치환, 산술 확장, 프로세스 치환 및 따옴표 제거가 수행됩니다.

case 절은 임의의 개수만큼 존재할 수 있으며, 각 절은 ‘;;’, ‘;&’, 또는 ‘;;&’로 종료됩니다. 첫 번째로 매치되는 패턴에 의해 실행될 명령어 목록이 결정됩니다. 마지막 패턴으로 ‘*’를 사용하여 기본 케이스(default case)를 정의하는 것이 일반적인 관례입니다. 이 패턴은 항상 매치되기 때문입니다.

다음은 스크립트에서 동물의 흥미로운 특징 하나를 설명하는 데 case를 사용하는 예시입니다: 

echo -n "동물 이름을 입력하세요: "
read ANIMAL
echo -n "$ANIMAL의 다리 개수는 "
case $ANIMAL in
  horse | dog | cat) echo -n "4개";;
  man | kangaroo ) echo -n "2개";;
  *) echo -n "알 수 없음";;
esac
echo " 입니다."

‘;;’ 연산자가 사용되면, 첫 번째 패턴 매칭 후에 case 명령어가 종료됩니다. ‘;;’ 대신 ‘;&’를 사용하면 다음 절에 연관된 command-list(있는 경우)가 이어서 실행됩니다. ‘;;’ 대신 ‘;;&’를 사용하면 쉘은 다음 절의 패턴들을 테스트하고, 매칭에 성공하면 연관된 command-list를 실행하며, 마치 이전 패턴 목록이 매치되지 않았던 것처럼 계속해서 case 문 실행을 이어갑니다.

매치되는 pattern이 없으면 반환 상태는 0입니다. 그렇지 않은 경우, 반환 상태는 마지막으로 실행된 command-list의 종료 상태입니다.

select ¶

select 구문을 사용하면 메뉴를 쉽게 생성할 수 있습니다. for 명령어와 거의 동일한 문법을 가집니다: 

select name [in words ...]; do commands; done

먼저 in 뒤에 오는 단어 목록을 확장하여 항목 목록을 생성하고, 확장된 단어 세트를 각 단어 앞에 숫자를 붙여 표준 에러 스트림에 출력합니다. 만약 ‘in words’가 생략되면, 마치 ‘in "$@"’가 지정된 것처럼 위치 파라미터들을 출력합니다. 그런 다음 select는 PS3 프롬프트를 표시하고 표준 입력에서 한 줄을 읽습니다. 입력된 줄이 표시된 단어 중 하나에 해당하는 숫자로 구성되어 있으면, select는 name의 값을 해당 단어로 설정합니다. 입력된 줄이 비어 있으면 select는 단어들과 프롬프트를 다시 표시합니다. EOF가 읽히면 select는 종료되고 1을 반환합니다. 그 외의 값이 읽히면 name은 null로 설정됩니다. 읽어들인 줄은 REPLY 변수에 저장됩니다.

각 선택 후에 break 명령어가 실행될 때까지 commands가 실행되며, break가 실행되면 select 명령어가 종료됩니다.

다음은 사용자가 현재 디렉토리에서 파일명을 선택하게 하고, 선택된 파일의 이름과 인덱스를 표시하는 예시입니다. 

select fname in *;
do
	echo $fname \($REPLY\) 을(를) 선택하셨습니다.
	break;
done
((…))
(( expression ))

산술식 expression은 아래에 설명된 규칙(쉘 산술 연산 참조)에 따라 평가됩니다. expression은 큰따옴표 내에 있는 것처럼 동일한 확장을 거치지만, expression 내의 이스케이프되지 않은 큰따옴표 문자는 특별하게 취급되지 않고 제거됩니다. 이로 인해 잠재적으로 빈 문자열이 결과로 나올 수 있는데, 이 명령어는 이를 0으로 평가되는 식으로 취급합니다. 식의 값이 0이 아니면 반환 상태는 0이고, 그렇지 않으면 반환 상태는 1입니다.

[[…]] ¶
[[ expression ]]

조건식 expression을 평가하고 0(참) 또는 0이 아닌 값(거짓)의 상태를 반환합니다. 식은 아래 Bash 조건식에 설명된 기본 요소(primaries)들로 구성됩니다. [[와 ]] 사이의 단어들은 단어 분할(word splitting)과 파일 이름 확장을 거치지 않습니다. 쉘은 해당 단어들에 대해 물결표 확장, 파라미터 및 변수 확장, 산술 확장, 명령어 치환, 프로세스 치환 및 따옴표 제거를 수행합니다. ‘-f’와 같은 조건부 연산자들은 기본 요소로 인식되려면 인용되지 않아야 합니다.

[[와 함께 사용될 때, ‘<’ 및 ‘>’ 연산자는 현재 로케일을 사용하여 사전순으로 정렬합니다.

‘==’ 및 ‘!=’ 연산자가 사용될 때, 연산자 오른쪽의 문자열은 패턴으로 간주되며, 마치 extglob 쉘 옵션이 활성화된 것처럼 아래 패턴 매칭에 설명된 규칙에 따라 매칭됩니다. ‘=’ 연산자는 ‘==’와 동일합니다. 만약 nocasematch 쉘 옵션(Shopt 빌트인의 shopt 설명 참조)이 활성화되어 있으면, 알파벳 문자의 대소문자를 구분하지 않고 매칭을 수행합니다. 문자열이 패턴과 매치되면(‘==’) 또는 매치되지 않으면(‘!=’) 반환 값은 0이고, 그렇지 않으면 1입니다.

패턴의 임의의 부분을 쉘의 인용 메커니즘을 사용하여 인용하면, 인용된 부분은 리터럴(literal)로 매치됩니다. 즉, 인용된 부분의 모든 문자는 특별한 패턴 매칭 의미를 갖지 않고 그 자체로 매치됩니다.

‘==’ 및 ‘!=’와 동일한 우선순위를 가진 추가적인 이항 연산자 ‘=~’를 사용할 수 있습니다. ‘=~’를 사용하면 연산자 오른쪽의 문자열은 POSIX 확장 정규 표현식 패턴으로 간주되어 그에 따라 매칭됩니다(보통 regex(3)에 설명된 POSIX regcomp 및 regexec 인터페이스 사용). 문자열이 패턴과 매치되면 반환 값은 0이고, 매치되지 않으면 1입니다. 정규 표현식의 문법이 잘못된 경우 조건식은 2를 반환합니다. 만약 nocasematch 쉘 옵션(Shopt 빌트인의 shopt 설명 참조)이 활성화되어 있으면, 대소문자를 구분하지 않고 매칭을 수행합니다.

패턴의 임의의 부분을 인용하여 해당 부분이 정규 표현식이 아닌 리터럴로 매치되도록 강제할 수 있습니다(위 내용 참조). 패턴이 쉘 변수에 저장되어 있는 경우, 변수 확장을 인용하면 전체 패턴이 리터럴로 매치되도록 강제합니다.

패턴이 문자열의 어느 부분에라도 매치되면 매칭은 성공합니다. 패턴이 전체 문자열과 매치되도록 강제하려면 정규 표현식 연산자인 ‘^’와 ‘$’를 사용하여 앵커(anchor)를 설정하십시오.

예를 들어, 다음은 쉘 변수 line에 저장된 줄에서, space 문자 클래스의 문자가 0개 이상 나타나고, 그 바로 뒤에 ‘a’가 0개 또는 1개 나타난 후 ‘b’가 이어지는 문자 시퀀스가 값의 어느 곳에든 있는 경우 매치됩니다: 

[[ $line =~ [[:space:]]*(a)?b ]]

이는 line의 값이 ‘aab’, ‘ aaaaaab’, ‘xaby’, ‘ ab’인 경우 모두 매치되며, 값의 어느 곳에든 ‘b’가 포함된 줄도 모두 매치됨을 의미합니다.

정규 표현식 문법에서 특별한 의미를 갖는 문자(‘^$|[]()\.*+?’)를 매치하고 싶다면, 특별한 의미를 제거하기 위해 반드시 인용되어야 합니다. 즉, 패턴 ‘xxx.txt’에서 ‘.’은 문자열의 모든 문자와 매치되지만(일반적인 정규 표현식 의미), 패턴 ‘"xxx.txt"’에서는 오직 리터럴 ‘.’과만 매치될 수 있습니다.

마찬가지로, 정규 표현식 문법에서 특별한 의미를 갖는 문자를 패턴에 포함시키고 싶다면 해당 문자가 인용되지 않았는지 확인해야 합니다. 예를 들어 패턴을 문자열의 시작이나 끝에 고정(anchor)하고 싶다면, 그 어떤 형태의 쉘 인용을 사용해서도 ‘^’ 또는 ‘$’ 문자를 인용해서는 안 됩니다.

줄의 시작 부분에서 ‘initial string’을 매치하고 싶다면 다음과 같이 작성하면 됩니다: 

[[ $line =~ ^"initial string" ]]

하지만 다음과 같이 작성하면 작동하지 않습니다: 

[[ $line =~ "^initial string" ]]

두 번째 예시에서는 ‘^’가 인용되어 일반적인 특별한 의미를 잃어버렸기 때문입니다.

인용을 사용하지 않고 정규 표현식을 올바르게 지정하거나, 쉘의 인용 처리와 따옴표 제거를 고려하면서 정규 표현식에서 사용되는 인용을 파악하는 것은 때때로 어렵습니다. 정규 표현식을 쉘 변수에 저장하는 것은 쉘에 특별한 의미를 갖는 문자들을 인용할 때 발생하는 문제들을 피하는 유용한 방법이 되곤 합니다. 예를 들어, 다음은 위에서 사용된 패턴과 동일합니다: 

pattern='[[:space:]]*(a)?b'
[[ $line =~ $pattern ]]

쉘 프로그래머는 백슬래시 사용에 특별히 주의해야 합니다. 백슬래시는 쉘과 정규 표현식 모두에서 다음 문자의 특별한 의미를 제거하는 데 사용되기 때문입니다. 즉, 쉘의 단어 확장이 완료된 후(쉘 확장 참조), 원래 인용되지 않았던 패턴 부분에 남아있는 모든 백슬래시는 패턴 문자의 특별한 의미를 제거할 수 있습니다. 패턴의 어떤 부분이 인용되어 있다면, 쉘은 정규 표현식 파서가 해당 인용된 부분에 나타난 나머지 백슬래시들을 리터럴로 취급하도록 최선을 다합니다.

다음 두 세트의 명령어는 서로 동일하지 않습니다: 

pattern='\.'

[[ . =~ $pattern ]]
[[ . =~ \. ]]

[[ . =~ "$pattern" ]]
[[ . =~ '\.' ]]

처음 두 매칭은 성공하지만, 뒤의 두 매칭은 실패합니다. 뒤의 두 예시에서는 백슬래시가 매치되어야 할 패턴의 일부가 되기 때문입니다. 처음 두 예시에서 정규 표현식 파서로 전달되는 패턴은 ‘\.’입니다. 백슬래시가 ‘.’의 특별한 의미를 제거하므로 리터럴 ‘.’과 매치됩니다. 뒤의 두 예시에서 정규 표현식 파서로 전달되는 패턴은 백슬래시가 인용되어 있습니다(예: ‘\.’). 문자열에는 백슬래시가 포함되어 있지 않으므로 매치되지 않습니다. 만약 첫 번째 예시들의 문자열이 ‘.’이 아닌 다른 것, 예를 들어 ‘a’였다면 패턴은 매치되지 않았을 것입니다. 패턴 내의 인용된 ‘.’은 모든 단일 문자와 매치되는 특별한 의미를 잃었기 때문입니다.

정규 표현식의 대괄호 표현식(Bracket expressions) 또한 오류의 원인이 될 수 있습니다. 정규 표현식에서 평소에는 특별한 의미를 갖는 문자들이 대괄호 사이에서는 그 의미를 잃기 때문입니다. 하지만 대괄호 표현식을 사용하면 특별한 패턴 문자들을 인용하지 않고도 매치할 수 있으므로, 때로는 이러한 용도로 유용하게 쓰입니다.

다소 이상한 방식처럼 보일 수 있지만, 다음 패턴은 문자열 내의 ‘.’과 매치됩니다: 

[[ . =~ [.] ]]

쉘은 정규 표현식 함수로 패턴을 전달하기 전에 모든 단어 확장을 수행하므로, 쉘의 인용 처리가 우선권을 갖는다고 간주할 수 있습니다. 위에서 언급했듯이, 정규 표현식 파서는 쉘 확장 후 패턴에 남아있는 인용되지 않은 백슬래시들을 자신의 규칙에 따라 해석합니다. 이는 쉘 프로그래머가 가능한 한 이중으로 인용해야 하는 번거로움을 피하게 하려는 의도이며, 따라서 필요한 경우 특수 패턴 문자를 인용하는 데 쉘 인용만으로 충분해야 합니다.

배열 변수 BASH_REMATCH는 문자열의 어떤 부분이 패턴과 매치되었는지를 기록합니다. 인덱스가 0인 BASH_REMATCH 요소는 전체 정규 표현식과 매치된 문자열 부분을 포함합니다. 정규 표현식 내의 괄호로 감싸진 서브 표현식(parenthesized subexpressions)에 의해 매치된 부분 문자열은 나머지 BASH_REMATCH 인덱스에 저장됩니다. 인덱스 n인 BASH_REMATCH 요소는 n번째 괄호 서브 표현식과 매치된 문자열 부분입니다.

Bash는 BASH_REMATCH를 전역 범위(global scope)로 설정합니다. 이를 지역 변수로 선언하면 예상치 못한 결과가 발생할 수 있습니다.

식들은 아래 나열된 연산자들을 사용하여 조합될 수 있으며, 우선순위가 높은 순서대로 나열되었습니다:

( expression )

expression의 값을 반환합니다. 연산자의 일반적인 우선순위를 재정의하는 데 사용될 수 있습니다.

! expression

expression이 거짓이면 참입니다.

expression1 && expression2

expression1과 expression2가 모두 참이면 참입니다.

expression1 || expression2

expression1 또는 expression2 중 하나라도 참이면 참입니다.

&& 및 || 연산자는 expression1의 값만으로 전체 조건식의 반환 값을 결정하기에 충분한 경우 expression2를 평가하지 않습니다.
