4.2 Bash 빌트인 명령어 ¶

이 섹션은 Bash에만 있거나 Bash에서 확장된 빌트인 명령어들에 대해 설명합니다. 이들 중 일부는 POSIX 표준에 명시되어 있습니다.

alias ¶
alias [-p] [name[=value] ...]

인자가 없거나 -p 옵션이 사용되면, alias는 모든 별칭(alias) 목록을 입력으로 재사용할 수 있는 형식으로 표준 출력에 출력합니다. 인자가 제공되면, value가 주어진 각 name에 대해 별칭을 정의합니다. 만약 value가 주어지지 않으면, 별칭 name의 이름과 값을 출력합니다. value의 마지막에 공백이 있으면, 명령어 파싱 중에 별칭이 확장될 때 다음 단어도 별칭 치환 대상인지 확인하게 됩니다. alias는 대응하는 =value 없이 제공된 name에 대해 정의된 별칭이 없는 경우를 제외하고 참(true)을 반환합니다. 별칭에 대한 설명은 별칭을 참조하십시오.

bind ¶
bind [-m keymap] [-lsvSVX]
bind [-m keymap] [-q function] [-u function] [-r keyseq]
bind [-m keymap] -f filename
bind [-m keymap] -x keyseq[: ]shell-command
bind [-m keymap] keyseq:function-name
bind [-m keymap] keyseq:readline-command
bind [-m keymap] -p|-P [readline-command]
bind readline-command-line

현재의 Readline(명령줄 편집 참조) 키 및 함수 바인딩을 표시하거나, 키 시퀀스를 Readline 함수/매크로 또는 쉘 명령어에 바인딩하거나, Readline 변수를 설정합니다. 옵션이 아닌 각 인자는 Readline 초기화 파일(Readline 초기화 파일 참조)에 나타나는 것과 동일한 형식의 키 바인딩 또는 명령어이지만, 각 바인딩이나 명령어는 별개의 인자로 전달되어야 합니다. (예: ‘"\C-x\C-r":re-read-init-file’).

이하의 설명에서, 다시 읽어들일 수 있는 형식으로 출력하는 옵션들은 Readline 초기화 파일에 나타나거나 bind 명령어의 개별 인자로 제공될 수 있는 형식으로 출력합니다.

옵션이 제공되면 다음과 같은 의미를 갖습니다:

-m keymap

이후의 바인딩에 영향을 줄 키맵(keymap)으로 keymap을 사용합니다. 사용 가능한 keymap 이름은 emacs, emacs-standard, emacs-meta, emacs-ctlx, vi, vi-move, vi-command, 그리고 vi-insert입니다. vi는 vi-command와 동일하며(vi-move 또한 동의어임), emacs는 emacs-standard와 동일합니다.

-l

모든 Readline 함수의 이름을 나열합니다.

-p

Readline 함수 이름과 바인딩을 이후의 bind 명령어 인자나 Readline 초기화 파일에서 사용할 수 있는 형식으로 표시합니다. 옵션 처리 후 인자가 남아있다면, bind는 이를 Readline 명령어 이름으로 간주하고 해당 이름들로 출력을 제한합니다.

-P

현재의 Readline 함수 이름과 바인딩을 나열합니다. 옵션 처리 후 인자가 남아있다면, bind는 이를 Readline 명령어 이름으로 간주하고 해당 이름들로 출력을 제한합니다.

-s

매크로에 바인딩된 Readline 키 시퀀스와 그 출력 문자열을 이후의 bind 명령어 인자나 Readline 초기화 파일에서 사용할 수 있는 형식으로 표시합니다.

-S

매크로에 바인딩된 Readline 키 시퀀스와 그 출력 문자열을 표시합니다.

-v

Readline 변수 이름과 값을 이후의 bind 명령어 인자나 Readline 초기화 파일에서 사용할 수 있는 형식으로 표시합니다.

-V

현재의 Readline 변수 이름과 값을 나열합니다.

-f filename

filename으로부터 키 바인딩을 읽어들입니다.

-q function

지정된 Readline function을 호출하는 키 시퀀스들을 표시합니다.

-u function

지정된 Readline function에 바인딩된 모든 키 시퀀스들의 바인딩을 해제합니다.

-r keyseq

keyseq에 대한 현재 바인딩을 제거합니다.

-x keyseq:shell-command

keyseq가 입력될 때마다 shell-command가 실행되도록 합니다. keyseq와 shell-command 사이의 구분자는 공백이거나 선택적으로 공백이 뒤따르는 콜론(:)입니다. 구분자가 공백인 경우 shell-command는 반드시 큰따옴표로 감싸져야 하며, Readline은 저장하기 전에 shell-command 내의 모든 특별한 백슬래시 이스케이프를 확장합니다. 구분자가 콜론인 경우 큰따옴표 사용은 선택 사항이며, Readline은 저장하기 전에 명령어 문자열을 확장하지 않습니다. 전체 키 바인딩 표현식은 단일 인자여야 하므로 작은따옴표로 감싸는 것이 좋습니다. shell-command가 실행될 때, 쉘은 READLINE_LINE 변수를 Readline 라인 버퍼의 내용으로 설정하고, READLINE_POINT와 READLINE_MARK 변수를 각각 현재 삽입 지점의 위치와 저장된 삽입 지점(mark)의 위치로 설정합니다. 사용자가 제공한 숫자 인자가 있다면 이를 READLINE_ARGUMENT 변수에 할당합니다. 인자가 없다면 해당 변수는 설정되지 않습니다. 실행된 명령어가 READLINE_LINE, READLINE_POINT, 또는 READLINE_MARK 중 하나의 값을 변경하면, 그 새로운 값들이 편집 상태에 반영됩니다.

-X

쉘 명령어에 바인딩된 모든 키 시퀀스와 연관된 명령어들을 이후의 bind 명령어 인자로 재사용할 수 있는 형식으로 나열합니다.

반환 상태는 잘못된 옵션이 제공되거나 에러가 발생하지 않는 한 0입니다.

builtin ¶
builtin [shell-builtin [args]]

지정된 쉘 빌트인 shell-builtin을 실행하고 args를 전달하며 그 종료 상태를 반환합니다. 이는 쉘 빌트인과 동일한 이름의 쉘 함수를 정의할 때, 함수 내부에서 빌트인의 기능을 유지하고자 할 때 유용합니다. 반환 상태는 shell-builtin이 쉘 빌트인 명령어가 아닌 경우 0이 아닙니다.

caller ¶
caller [expr]

현재 활성화된 서브루틴 호출(쉘 함수 또는 . 이나 source 빌트인으로 실행 중인 스크립트)의 컨텍스트를 반환합니다.

expr이 없으면 caller는 현재 서브루틴 호출의 라인 번호와 소스 파일명을 표시합니다. 0 이상의 정수가 expr로 제공되면, caller는 현재 실행 호출 스택(call stack)의 해당 위치에 대응하는 라인 번호, 서브루틴 이름, 그리고 소스 파일을 표시합니다. 이 추가 정보는 예를 들어 스택 트레이스(stack trace)를 출력하는 데 사용될 수 있습니다. 현재 프레임은 프레임 0입니다.

반환 값은 쉘이 서브루틴 호출을 실행 중이 아니거나 expr이 호출 스택의 유효한 위치에 대응하지 않는 경우를 제외하고 0입니다.

command ¶
command [-pVv] command [arguments ...]

command 빌트인은 command라는 이름의 쉘 함수가 있더라도 이를 무시하고 command를 arguments와 함께 실행합니다. 오직 쉘 빌트인 명령어 또는 PATH 검색을 통해 발견된 명령어만 실행됩니다. 만약 ls라는 이름의 쉘 함수가 있을 때, 함수 내부에서 ‘command ls’를 실행하면 함수를 재귀적으로 호출하는 대신 외부 명령어 ls를 실행합니다. -p 옵션은 모든 표준 유틸리티를 찾을 수 있음이 보장된 PATH 기본값을 사용함을 의미합니다. 이 경우 반환 상태는 command를 찾을 수 없거나 에러가 발생한 경우 127이고, 그렇지 않으면 command의 종료 상태가 됩니다.

만약 -V 또는 -v 옵션이 제공되면, command는 command에 대한 설명을 출력합니다. -v 옵션은 command를 호출하는 데 사용되는 명령어 또는 파일 이름을 나타내는 단어 하나를 표시합니다. -V 옵션은 더 상세한 설명을 생성합니다. 이 경우 반환 상태는 command를 찾은 경우 0이고, 그렇지 않으면 0이 아닙니다.

declare ¶
declare [-aAfFgiIlnrtux] [-p] [name[=value] ...]

변수를 선언하고 속성을 부여합니다. name이 주어지지 않으면 변수 또는 쉘 함수의 값들을 표시합니다.

-p 옵션은 각 name의 속성과 값을 표시합니다. -p가 name 인자들과 함께 사용되면 -f와 -F를 제외한 추가 옵션들은 무시됩니다.

name 인자 없이 -p만 제공되면, declare는 추가 옵션들로 지정된 속성들을 가진 모든 변수들의 속성과 값을 표시합니다. -p와 함께 다른 옵션이 제공되지 않으면, declare는 모든 쉘 변수들의 속성과 값을 표시합니다. -f 옵션은 표시 대상을 쉘 함수로 제한합니다.

-F 옵션은 함수 정의(본체) 표시를 억제하고 함수 이름과 속성만 출력합니다. shopt를 통해 extdebug 쉘 옵션이 활성화되어 있다면(Shopt 빌트인 참조), 각 name이 정의된 소스 파일명과 라인 번호도 함께 표시됩니다. -F는 -f를 내포합니다.

-g 옵션은 쉘 함수 내에서 declare가 실행되더라도 변수가 전역 범위(global scope)에서 생성되거나 수정되도록 강제합니다. 쉘 함수 밖에서 실행될 때는 무시됩니다.

-I 옵션은 지역 변수가 주변 범위(surrounding scope)에 이미 존재하는 동일한 name의 변수로부터 속성(nameref 속성 제외)과 값을 상속받도록 합니다. 기존 변수가 없으면 지역 변수는 초기에 해제된(unset) 상태가 됩니다.

다음 옵션들은 특정 속성을 가진 변수들로 출력을 제한하거나 변수에 속성을 부여하는 데 사용될 수 있습니다:

-a

각 name은 인덱스 배열 변수입니다(배열 참조).

-A

각 name은 연관 배열 변수입니다(배열 참조).

-f

각 name은 쉘 함수를 참조합니다.

-i

변수를 정수로 취급합니다. 변수에 값이 할당될 때 산술 평가(쉘 산술 연산 참조)가 수행됩니다.

-l

변수에 값이 할당될 때 모든 대문자가 소문자로 변환됩니다. 대문자 속성은 비활성화됩니다.

-n

각 name에 nameref 속성을 부여하여 다른 변수에 대한 이름 참조로 만듭니다. 그 '다른 변수'는 name의 값에 의해 정의됩니다. -n 속성 자체를 사용하거나 변경하는 경우를 제외하고, name에 대한 모든 참조, 할당 및 속성 수정은 name의 값이 가리키는 변수에 대해 수행됩니다. 네임레프 속성은 배열 변수에는 적용할 수 없습니다.

-r

name들을 읽기 전용(readonly)으로 만듭니다. 이 이름들은 이후의 할당문에 의해 값이 변경되거나 해제될 수 없습니다.

-t

각 name에 trace 속성을 부여합니다. 추적되는(traced) 함수는 호출한 쉘로부터 DEBUG 및 RETURN 트랩을 상속받습니다. 추적 속성은 변수에 대해서는 특별한 의미를 갖지 않습니다.

-u

변수에 값이 할당될 때 모든 소문자가 대문자로 변환됩니다. 소문자 속성은 비활성화됩니다.

-x

환경(environment)을 통해 이후의 명령어들로 내보내지도록(export) 각 name을 표시합니다.

‘-’ 대신 ‘+’를 사용하면 지정된 속성을 끕니다. 단, ‘+a’와 ‘+A’는 배열 변수를 파괴하는 데 사용할 수 없으며 ‘+r’은 읽기 전용 속성을 제거할 수 없습니다.

함수 내에서 사용될 때, -g 옵션이 제공되지 않는 한 declare는 각 name을 local 명령어와 마찬가지로 지역 변수로 만듭니다. 변수 이름 뒤에 =value가 오면 변수의 값은 value로 설정됩니다.

-a 또는 -A와 복합 할당(compound assignment) 문법을 사용하여 배열 변수를 생성할 때, 추가적인 속성들은 이후의 할당 전까지는 효력을 발휘하지 않습니다.

반환 상태는 잘못된 옵션을 만난 경우, ‘-f foo=bar’를 사용하여 함수를 정의하려고 시도한 경우, 읽기 전용 변수에 값을 할당하려고 시도한 경우, 복합 할당 문법을 사용하지 않고 배열 변수에 값을 할당하려고 시도한 경우(배열 참조), 이름 중 하나가 유효한 쉘 변수 이름이 아닌 경우, 읽기 전용 변수의 읽기 전용 상태를 끄려고 시도한 경우, 배열 변수의 배열 상태를 끄려고 시도한 경우, 또는 -f로 존재하지 않는 함수를 표시하려고 시도한 경우를 제외하고 0입니다.

echo ¶
echo [-neE] [arg ...]

arg들을 공백으로 구분하여 출력하고 마지막에 줄바꿈을 붙입니다. 반환 상태는 쓰기 에러가 발생하지 않는 한 0입니다. -n이 지정되면 마지막 줄바꿈을 출력하지 않습니다.

-e 옵션이 주어지면, echo는 다음의 백슬래시 이스케이프 문자들을 해석합니다. -E 옵션은 기본적으로 해석되는 시스템에서도 이러한 이스케이프 문자 해석을 비활성화합니다. xpg_echo 쉘 옵션은 echo가 기본적으로 옵션을 해석하고 이스케이프 문자를 확장할지 여부를 결정합니다. echo는 --를 옵션의 끝으로 해석하지 않습니다.

echo는 다음 이스케이프 시퀀스들을 해석합니다:

\a

경고 (벨)

\b

백스페이스

\c

이후의 출력 억제

\e
\E

이스케이프

\f

폼 피드(form feed)

\n

줄바꿈 (new line)

\r

캐리지 리턴 (carriage return)

\t

수평 탭

\v

수직 탭

\\

백슬래시

\0nnn

8진수 값 nnn(0~3자리의 8진수 숫자)을 가지는 8비트 문자.

\xHH

16진수 값 HH(1~2자리의 16진수 숫자)를 가지는 8비트 문자.

\uHHHH

16진수 값 HHHH(1~4자리의 16진수 숫자)를 가지는 유니코드(ISO/IEC 10646) 문자.

\UHHHHHHHH

16진수 값 HHHHHHHH(1~8자리의 16진수 숫자)를 가지는 유니코드(ISO/IEC 10646) 문자.

echo는 인식하지 못하는 백슬래시 이스케이프 문자들은 수정 없이 그대로 출력합니다.

enable ¶
enable [-a] [-dnps] [-f filename] [name ...]

쉘 빌트인 명령어를 활성화하거나 비활성화합니다. 빌트인을 비활성화하면, 쉘이 보통 파일보다 빌트인을 먼저 검색함에도 불구하고 전체 경로명을 지정하지 않고도 쉘 빌트인과 동일한 이름을 가진 실행 파일을 실행할 수 있게 됩니다.

-n이 제공되면 name들을 비활성화합니다. 그렇지 않으면 name들을 활성화합니다. 예를 들어, 쉘 빌트인 버전 대신 $PATH에서 찾은 test 바이너리를 사용하려면 ‘enable -n test’라고 입력하십시오.

-p 옵션이 제공되거나 name 인자가 없으면 쉘 빌트인 목록을 출력합니다. 다른 인자가 없으면 모든 활성화된 쉘 빌트인 목록이 출력됩니다. -n 옵션은 비활성화된 빌트인만 출력함을 의미합니다. -a 옵션은 각 빌트인이 활성화되었는지 여부와 함께 목록을 출력함을 의미합니다. -s 옵션은 출력을 POSIX 특수 빌트인으로 제한함을 의미합니다.

동적 로딩을 지원하는 시스템에서 -f 옵션은 공유 객체(shared object) filename으로부터 새로운 빌트인 명령어 name을 로드함을 의미합니다. 만약 filename에 슬래시가 포함되어 있지 않다면, Bash는 BASH_LOADABLES_PATH 변수 값을 filename을 찾을 콜론 구분 디렉토리 목록으로 사용합니다. BASH_LOADABLES_PATH의 기본값은 시스템에 따라 다르며, 현재 디렉토리 검색을 강제하기 위해 "."을 포함할 수 있습니다. -d 옵션은 -f로 로드된 빌트인을 삭제합니다. -s가 -f와 함께 사용되면, 새로운 빌트인은 POSIX 특수 빌트인이 됩니다(특수 빌트인 참조).

옵션이 없고 name이 쉘 빌트인이 아닌 경우, enable은 마치 ‘enable -f name name’ 명령어를 실행한 것처럼 name이라는 이름의 공유 객체로부터 name을 로드하려고 시도합니다.

반환 상태는 name이 쉘 빌트인이 아니거나 공유 객체로부터 새로운 빌트인을 로드하는 중에 에러가 발생하지 않는 한 0입니다.

help ¶
help [-dms] [pattern]

빌트인 명령어에 대한 도움말 정보를 표시합니다. 만약 pattern이 지정되면, help는 pattern과 매치되는 모든 명령어에 대해 아래 설명된 대로 상세 도움말을 제공합니다. 그렇지 않으면 모든 빌트인 및 쉘 복합 명령어 목록을 표시합니다.

옵션이 제공되면 다음과 같은 의미를 갖습니다:

-d

각 pattern에 대한 짧은 설명을 표시합니다.

-m

각 pattern에 대한 설명을 매뉴얼 페이지(manpage)와 유사한 형식으로 표시합니다.

-s

각 pattern에 대해 짧은 사용법 요약(synopsis)만 표시합니다.

만약 pattern에 패턴 매칭 문자(패턴 매칭 참조)가 포함되어 있다면, 이를 쉘 패턴으로 간주하고 help는 pattern과 매치되는 각 도움말 항목의 설명을 출력합니다.

그렇지 않고 pattern이 도움말 항목의 이름과 정확히 일치하면, help는 해당 항목과 연관된 설명을 출력합니다. 그 외의 경우, help는 접두사 매칭(prefix matching)을 수행하여 일치하는 모든 도움말 항목의 설명을 출력합니다.

반환 상태는 pattern과 매치되는 명령어가 없는 경우를 제외하고 0입니다.

let ¶
let expression [expression ...]

let 빌트인은 쉘 변수에 대해 산술 연산을 수행할 수 있게 해줍니다. 각 expression은 아래 쉘 산술 연산에 주어진 규칙에 따라 산술식으로 평가됩니다. 만약 마지막 expression이 0으로 평가되면 let은 1을 반환하고, 그렇지 않으면 0을 반환합니다.

local ¶
local [option] name[=value] ...

각 인자에 대해 name이라는 이름의 지역 변수를 생성하고 value를 할당합니다. option은 declare에서 허용되는 모든 옵션이 가능합니다. local은 오직 함수 내부에서만 사용할 수 있습니다. 이는 변수 name의 가시 범위를 해당 함수와 그 자식 함수들로 제한합니다. 함수 밖에서 local을 사용하는 것은 에러입니다.

만약 name이 ‘-’라면, local이 호출된 함수 내에서 쉘 옵션 세트들을 지역적으로 만듭니다: local 호출 후 함수 내부에서 set 빌트인을 사용하여 변경된 모든 쉘 옵션들은 함수가 반환될 때 원래의 값으로 복구됩니다. 복구 작업은 함수 호출 전에 유효했던 값들을 복구하기 위해 일련의 set 명령어들을 실행하는 것과 같이 수행됩니다.

피연산자가 없으면 local은 모든 지역 변수 목록을 표준 출력으로 씁니다.

반환 상태는 local이 함수 밖에서 사용되었거나, 잘못된 name이 제공되었거나, name이 읽기 전용 변수인 경우를 제외하고 0입니다.

logout ¶
logout [n]

로그인 쉘을 종료하며 부모 프로세스에게 상태 n을 반환합니다.

mapfile ¶
mapfile [-d delim] [-n count] [-O origin] [-s count]
    [-t] [-u fd] [-C callback] [-c quantum] [array]

표준 입력 또는 -u 옵션의 인자로 제공된 파일 서술자 fd로부터 줄들을 읽어 인덱스 배열 변수 array에 넣습니다. 변수 MAPFILE이 기본 array입니다. 옵션이 제공되면 다음과 같은 의미를 갖습니다:

-d

줄바꿈 대신 delim의 첫 번째 문자를 각 입력 줄의 종료 문자로 사용합니다. 만약 delim이 빈 문자열이면, mapfile은 NUL 문자를 읽을 때 줄을 종료합니다.

-n

최대 count개의 줄을 복사합니다. count가 0이면 모든 줄을 복사합니다.

-O

배열 array의 인덱스 origin부터 할당을 시작합니다. 기본 인덱스는 0입니다.

-s

처음 읽은 count개의 줄을 버립니다.

-t

각 줄의 끝에서 delim(기본값은 줄바꿈)을 제거합니다.

-u

표준 입력 대신 파일 서술자 fd로부터 줄들을 읽습니다.

-C

quantum개의 줄을 읽을 때마다 callback을 평가합니다. -c 옵션이 quantum을 지정합니다.

-c

callback 호출 사이에 읽을 줄의 개수를 지정합니다.

-c 없이 -C가 지정된 경우 기본 퀀텀(quantum)은 5000입니다. callback이 평가될 때, 다음에 할당될 배열 요소의 인덱스와 해당 요소에 할당될 줄이 추가 인자로 제공됩니다. callback은 줄을 읽은 후, 배열 요소가 할당되기 전에 평가됩니다.

명시적인 시작 위치(origin)가 제공되지 않으면, mapfile은 할당을 시작하기 전에 array를 비웁니다.

mapfile은 잘못된 옵션이나 옵션 인자가 제공된 경우, array가 잘못되었거나 할당할 수 없는 경우, 또는 array가 인덱스 배열이 아닌 경우를 제외하고 0을 반환합니다.

printf ¶
printf [-v var] format [arguments]

format의 제어에 따라 형식화된 arguments를 표준 출력으로 씁니다. -v 옵션은 출력물을 표준 출력으로 출력하는 대신 변수 var에 할당합니다.

format은 세 가지 유형의 객체를 포함하는 문자열입니다: 표준 출력으로 그대로 복사되는 일반 문자들, 표준 출력으로 변환되어 복사되는 문자 이스케이프 시퀀스들, 그리고 다음 argument를 출력하게 하는 형식 지정자(format specifications)들입니다. 표준 printf(3) 형식 문자들인 cCsSndiouxXeEfFgGaA 외에도 printf는 다음과 같은 추가 형식 지정자들을 해석합니다:

%b

printf가 대응하는 argument 내의 백슬래시 이스케이프 시퀀스를 echo -e와 동일한 방식으로 확장하도록 합니다(Bash 빌트인 명령어 참조).

%q

printf가 대응하는 argument를 쉘 입력으로 재사용할 수 있는 형식으로 출력하도록 합니다. 인자 문자열 내의 문자들이 요구하는 경우 %q와 %Q는 ANSI-C 인용 스타일(ANSI-C 방식 인용 참조)을 사용하며, 그렇지 않은 경우 백슬래시 인용을 사용합니다. 형식 문자열이 printf 대체 형식(alternate form)을 사용하는 경우, 이 두 형식은 인자 문자열을 작은따옴표를 사용하여 인용합니다.

%Q

%q와 유사하지만, 인용하기 전에 제공된 정밀도(precision)를 argument에 적용합니다.

%(datefmt)T

printf가 datefmt를 strftime(3)의 형식 문자열로 사용하여 생성된 날짜-시간 문자열을 출력하도록 합니다. 대응하는 argument는 에포크(epoch) 이후의 초(seconds)를 나타내는 정수입니다. 이 형식 지정자는 두 가지 특수 인자 값을 인식합니다: -1은 현재 시간을 나타내고, -2는 쉘이 호출된 시간을 나타냅니다. 인자가 지정되지 않으면 -1이 제공된 것처럼 동작합니다. 이는 일반적인 printf 동작의 예외 사항입니다.

%b, %q, 그리고 %T 형식 지정자들은 모두 형식 사양의 필드 너비와 정밀도 인자들을 사용하며, 보통 원본보다 더 많은 문자들을 포함하게 되는 확장된 인자로부터 해당 바이트만큼을 씁니다(또는 해당 너비의 필드를 사용합니다).

%n 형식 지정자는 쉘 변수 이름으로 취급되는 대응하는 인자를 받습니다.

%s 및 %c 형식 지정자는 l (long) 수정자를 받을 수 있으며, 이는 인자 문자열을 와이드 문자(wide-character) 문자열로 변환하고 제공된 필드 너비와 정밀도를 바이트가 아닌 문자 단위로 적용하도록 강제합니다. %S와 %C 형식 지정자는 각각 %ls 및 %lc와 동일합니다.

문자열이 아닌 형식 지정자에 대한 인자들은 C 언어 상수로 취급됩니다. 단, 앞에 붙는 플러스(+)나 마이너스(-) 기호는 허용되며, 시작 문자가 작은따옴표나 큰따옴표인 경우 그 값은 현재 로케일을 사용한 바로 다음 문자의 숫자 값이 됩니다.

format은 모든 arguments를 소모할 때까지 필요한 만큼 재사용됩니다. 만약 format이 제공된 것보다 더 많은 arguments를 요구하면, 추가적인 형식 지정자들은 적절히 0 값이나 빈 문자열(null string)이 제공된 것처럼 동작합니다. 반환 값은 성공 시 0이며, 잘못된 옵션이 제공되거나 쓰기 또는 할당 에러가 발생한 경우 0이 아닙니다.

read ¶
read [-Eers] [-a aname] [-d delim] [-i text] [-n nchars]
    [-N nchars] [-p prompt] [-t timeout] [-u fd] [name ...]

표준 입력 또는 -u 옵션의 인자로 제공된 파일 서술자 fd로부터 한 줄을 읽어, 위 단어 분할에 설명된 대로 단어들로 분리한 뒤, 첫 번째 단어를 첫 번째 name에, 두 번째 단어를 두 번째 name에 할당하는 식으로 진행합니다. 이름보다 단어가 더 많으면, 남은 단어들과 그 사이의 구분자들이 마지막 name에 할당됩니다. 입력 스트림에서 읽은 단어보다 이름이 더 많으면, 남은 이름들에는 빈 값이 할당됩니다. IFS 변수 값의 문자들은 쉘이 확장에 사용하는 것과 동일한 규칙(단어 분할 참조)을 사용하여 줄을 단어들로 분리하는 데 사용됩니다. 백슬래시 문자 ‘\’는 다음에 읽을 문자의 특별한 의미를 제거하며 줄 이어짐(line continuation)에 사용됩니다.

옵션이 제공되면 다음과 같은 의미를 갖습니다:

-a aname

단어들이 0부터 시작하여 배열 변수 aname의 순차적인 인덱스에 할당됩니다. 할당 전에 aname의 모든 요소가 제거됩니다. 다른 name 인자들은 무시됩니다.

-d delim

줄바꿈 대신 delim의 첫 번째 문자를 입력 줄의 종료 문자로 사용합니다. 만약 delim이 빈 문자열이면, read는 NUL 문자를 읽을 때 줄을 종료합니다.

-e

표준 입력을 터미널로부터 받는 경우, read는 Readline(명령줄 편집 참조)을 사용하여 줄을 가져옵니다. Readline은 현재의(또는 이전에 라인 편집이 활성화되지 않았다면 기본) 편집 설정을 사용하지만, Readline의 기본 파일명 자동 완성을 사용합니다.

-E

표준 입력을 터미널로부터 받는 경우, read는 Readline(명령줄 편집 참조)을 사용하여 줄을 가져옵니다. Readline은 현재의 편집 설정을 사용하지만, 프로그래밍 가능한 자동 완성을 포함한 Bash의 기본 자동 완성을 사용합니다.

-i text

줄을 읽기 위해 Readline이 사용되는 경우, 편집이 시작되기 전에 text를 편집 버퍼에 넣습니다.

-n nchars

완전한 입력 줄을 기다리는 대신 nchars개의 문자를 읽은 후에 반환합니다. 단, EOF를 만나거나 read가 타임아웃되는 경우는 예외입니다. 구분 문자를 읽은 경우에는 nchars개 미만을 읽었더라도 반환합니다.

-N nchars

완전한 입력 줄을 기다리는 대신 정확히 nchars개의 문자를 읽은 후에 반환합니다. 단, EOF를 만나거나 read가 타임아웃되는 경우는 예외입니다. 입력 중의 구분 문자는 특별하게 취급되지 않으며 nchars개를 다 읽을 때까지 read를 종료시키지 않습니다. 결과물은 IFS의 문자들로 분리되지 않습니다; 이 옵션의 의도는 변수에 읽어들인 문자들을 정확히 그대로 할당하는 것입니다(백슬래시는 예외; 아래 -r 옵션 참조).

-p prompt

입력을 시도하기 전에 마지막 줄바꿈 없이 prompt를 표시합니다. 입력을 터미널로부터 받는 경우에만 표시됩니다.

-r

이 옵션이 주어지면 백슬래시는 이스케이프 문자로 동작하지 않습니다. 백슬래시는 줄의 일부로 간주됩니다. 특히 백슬래시-줄바꿈 쌍은 줄 이어짐으로 사용할 수 없습니다.

-s

저소음 모드. 입력을 터미널로부터 받는 경우 입력 문자가 화면에 출력되지 않습니다.

-t timeout

timeout 초 이내에 완전한 입력 줄(또는 지정된 개수의 문자)을 읽지 못하면 read가 타임아웃되어 실패를 반환하도록 합니다. timeout은 소수점 뒤에 소수 부분이 있는 10진수일 수 있습니다. 이 옵션은 read가 터미널, 파이프, 또는 기타 특수 파일로부터 입력을 읽을 때만 유효하며, 일반 파일에서 읽을 때는 효과가 없습니다. read가 타임아웃되면, 읽어들인 모든 부분 입력을 지정된 변수 name에 저장하고 128보다 큰 상태를 반환합니다. 만약 timeout이 0이면, read는 데이터를 읽으려고 시도하지 않고 즉시 반환합니다. 이 경우 지정된 파일 서술자에서 입력을 사용할 수 있거나 읽기가 EOF를 반환하면 종료 상태는 0이고, 그렇지 않으면 0이 아닙니다.

-u fd

표준 입력 대신 파일 서술자 fd로부터 입력을 읽습니다.

delim이 빈 문자열인 경우를 제외하고, read는 입력 중의 모든 NUL 문자들을 무시합니다.

name이 제공되지 않으면, read는 읽어들인 줄을 마지막 구분 문자를 제외하고 다른 수정 없이 REPLY 변수에 할당합니다.

종료 상태는 EOF를 만나거나, read가 타임아웃되거나(상태 128 초과), 변수 할당 에러(예: 읽기 전용 변수에 할당)가 발생하거나, -u의 인자로 잘못된 파일 서술자가 제공된 경우를 제외하고 0입니다.

readarray ¶
readarray [-d delim] [-n count] [-O origin] [-s count]
    [-t] [-u fd] [-C callback] [-c quantum] [array]

표준 입력 또는 -u 옵션이 제공된 경우 파일 서술자 fd로부터 줄들을 읽어 인덱스 배열 변수 array에 넣습니다.

mapfile의 동의어입니다.

source ¶
source [-p path] filename [arguments]

.의 동의어입니다(Bourne 쉘 빌트인 참조).

type ¶
type [-afptP] [name ...]

각 name이 명령어 이름으로 사용될 때 어떻게 해석될지 나타냅니다.

-t 옵션이 사용되면, type은 name이 별칭, 쉘 예약어, 쉘 함수, 쉘 빌트인, 또는 실행 파일인지에 따라 각각 ‘alias’, ‘keyword’, ‘function’, ‘builtin’, 또는 ‘file’ 중 단어 하나를 출력합니다. name을 찾지 못한 경우 type은 아무것도 출력하지 않고 실패 상태를 반환합니다.

-p 옵션이 사용되면, type은 $PATH를 검색하여 name에 대해 발견될 실행 파일의 이름을 반환하거나, -t가 ‘file’을 반환하지 않을 상황이라면 아무것도 반환하지 않습니다.

-P 옵션은 -t가 ‘file’을 반환하지 않을 상황이더라도 각 name에 대해 경로 검색을 강제합니다.

만약 name이 해시된 명령어 테이블에 존재한다면, -p 및 -P 옵션은 해시된 값을 출력하며, 이는 반드시 $PATH에서 가장 먼저 나타나는 파일이 아닐 수도 있습니다.

-a 옵션이 사용되면, type은 name이라는 이름의 명령어를 포함하는 모든 장소를 반환합니다. 여기에는 별칭, 예약어, 함수, 빌트인이 포함되지만, 실행 파일로만 제한하기 위해 경로 검색 옵션(-p 및 -P)을 함께 제공할 수 있습니다. -a가 -p와 함께 사용되면, type은 해시된 명령어 테이블을 보지 않고 name에 대해 PATH 검색만 수행합니다.

-f 옵션이 사용되면, command 빌트인과 마찬가지로 쉘 함수를 찾으려고 시도하지 않습니다.

반환 상태는 모든 name들을 찾은 경우 0이고, 하나라도 찾지 못한 경우 0이 아닙니다.

typeset ¶
typeset [-afFgrxilnrtux] [-p] [name[=value] ...]

typeset 명령어는 Korn 쉘과의 호환성을 위해 제공됩니다. 이는 declare 빌트인 명령어의 동의어입니다.

ulimit ¶
ulimit [-HS] -a
ulimit [-HS] [-bcdefiklmnpqrstuvxPRT] [limit]

ulimit은 그러한 제어를 허용하는 시스템에서 쉘과 쉘이 시작하는 프로세스들이 사용할 수 있는 자원에 대한 제어를 제공합니다. 옵션이 주어지면 다음과 같이 해석됩니다:

-S

자원과 연관된 소프트 제한(soft limit)을 변경하고 보고합니다.

-H

자원과 연관된 하드 제한(hard limit)을 변경하고 보고합니다.

-a

현재의 모든 제한을 보고합니다; 어떤 제한도 설정하지 않습니다.

-b

최대 소켓 버퍼 크기.

-c

생성되는 코어 파일의 최대 크기.

-d

프로세스 데이터 세그먼트의 최대 크기.

-e

최대 스케줄링 우선순위 ("nice").

-f

쉘과 그 자식 프로세스들이 쓸 수 있는 파일의 최대 크기.

-i

대기 중인 시그널의 최대 개수.

-k

할당될 수 있는 최대 kqueue 개수.

-l

메모리에 고정(lock)될 수 있는 최대 크기.

-m

최대 상주 집합 크기 (많은 시스템들이 이 제한을 준수하지 않음).

-n

열린 파일 서술자의 최대 개수 (대부분의 시스템은 이 값의 설정을 허용하지 않음).

-p

파이프 버퍼 크기.

-q

POSIX 메시지 큐의 최대 바이트 수.

-r

최대 실시간 스케줄링 우선순위.

-s

최대 스택 크기.

-t

초 단위의 최대 CPU 시간.

-u

단일 사용자가 사용할 수 있는 최대 프로세스 개수.

-v

쉘과 그 자식 프로세스들이 사용할 수 있는 최대 가상 메모리 양.

-x

파일 잠금(file lock)의 최대 개수.

-P

의사 터미널(pseudoterminal)의 최대 개수.

-R

실시간 프로세스가 블록되기 전까지 실행될 수 있는 최대 시간 (마이크로초 단위).

-T

최대 스레드(thread) 개수.

limit가 제공되고 -a 옵션이 사용되지 않은 경우, limit는 지정된 자원의 새로운 값이 됩니다. 특수 limit 값인 hard, soft, 그리고 unlimited는 각각 현재의 하드 제한, 현재의 소프트 제한, 그리고 제한 없음을 의미합니다. 하드 제한은 루트 사용자가 아닌 경우 한번 설정되면 늘릴 수 없습니다; 소프트 제한은 하드 제한 값까지 늘릴 수 있습니다. 그렇지 않고 -H 옵션이 제공되지 않았다면, ulimit은 지정된 자원의 현재 소프트 제한 값을 출력합니다. 둘 이상의 자원이 지정되면, 값 앞에 제한 이름과 (적절한 경우) 단위가 함께 출력됩니다. 새로운 제한을 설정할 때 -H와 -S가 모두 제공되지 않으면 ulimit은 하드 제한과 소프트 제한을 모두 설정합니다. 옵션이 제공되지 않으면 -f로 간주합니다.

값은 1024바이트 단위로 증가합니다. 단, -t(초 단위), -R(마이크로초 단위), -p(512바이트 블록 단위), 그리고 -P, -T, -b, -k, -n, -u(단위 없음)는 예외입니다. 또한 POSIX 모드(Bash와 POSIX 참조)일 때 -c와 -f는 512바이트 단위로 증가합니다.

반환 상태는 잘못된 옵션이나 인자가 제공되거나, 새로운 제한을 설정하는 중에 에러가 발생하지 않는 한 0입니다.

unalias ¶
unalias [-a] [name ... ]

별칭 목록에서 각 name을 제거합니다. -a가 제공되면 모든 별칭을 제거합니다. 반환 값은 제공된 name이 정의된 별칭이 아닌 경우를 제외하고 참(true)입니다. 별칭에 대한 설명은 별칭을 참조하십시오.
