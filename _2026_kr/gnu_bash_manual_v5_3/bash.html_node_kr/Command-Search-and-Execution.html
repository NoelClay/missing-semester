3.7.2 명령어 검색 및 실행 ¶

명령어가 단어들로 분리된 후, 그 결과가 단순 명령어와 선택적인 인자 목록인 경우 쉘은 다음 작업들을 수행합니다.

  1. 명령어 이름에 슬래시(/)가 포함되어 있지 않은 경우, 쉘은 명령어의 위치를 찾으려고 시도합니다. 해당 이름을 가진 쉘 함수가 존재하면, 쉘 함수에 설명된 대로 해당 함수를 호출합니다.
  2. 이름이 함수와 일치하지 않으면, 쉘은 쉘 빌트인 명령어 목록에서 해당 이름을 검색합니다. 일치하는 빌트인이 발견되면 해당 빌트인을 호출합니다.
  3. 이름이 쉘 함수도 아니고 빌트인도 아니며 슬래시를 포함하고 있지 않다면, Bash는 $PATH의 각 요소를 검색하여 해당 이름을 가진 실행 파일이 포함된 디렉토리를 찾습니다. Bash는 실행 파일의 전체 경로명을 기억하기 위해 해시 테이블(hash table)을 사용하며, 이를 통해 반복적인 PATH 검색을 피합니다(Bourne 쉘 빌트인의 hash 설명 참조). 해시 테이블에서 명령어를 찾지 못한 경우에만 $PATH의 디렉토리들에 대한 전체 검색을 수행합니다. 검색에 실패하면, 쉘은 command_not_found_handle이라는 이름으로 정의된 쉘 함수가 있는지 찾습니다. 만약 해당 함수가 존재하면, 원래의 명령어와 그 인자들을 인자로 하여 별도의 실행 환경에서 이 함수를 호출하며, 함수의 종료 상태가 해당 서브쉘의 종료 상태가 됩니다. 해당 함수가 정의되어 있지 않으면, 쉘은 에러 메시지를 출력하고 종료 상태 127을 반환합니다.
  4. 검색에 성공하거나 명령어 이름에 하나 이상의 슬래시가 포함되어 있다면, 쉘은 별도의 실행 환경에서 해당 프로그램을 실행합니다. 0번 인자는 주어진 이름으로 설정되며, 명령어의 나머지 인자들은 제공된 인자들(있는 경우)로 설정됩니다.
  5. 파일이 실행 가능한 형식이 아니며 디렉토리도 아니어서 실행에 실패한 경우, 해당 파일은 쉘 명령어들을 포함한 쉘 스크립트로 간주됩니다. 쉘은 쉘 스크립트에 설명된 대로 이를 실행합니다.
  6. 명령어가 비동기적으로 시작되지 않았다면, 쉘은 명령어가 완료될 때까지 기다린 후 종료 상태를 수집합니다.
